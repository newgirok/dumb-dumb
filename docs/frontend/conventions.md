## 디자인 시스템

### 테마 — Animal Crossing

Tailwind CSS v4 + `@theme` 블록 기반 커스텀 디자인 시스템. 색상 토큰은 `oklch()` 색공간으로 정의한다.

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  --font-display: var(--font-display), "Nunito", ui-sans-serif, system-ui, sans-serif;
  --font-body:    var(--font-display), "Nunito", ui-sans-serif, system-ui, sans-serif;
  --font-mono:    var(--font-mono),    "JetBrains Mono", ui-monospace, monospace;
}
```

### 색상 토큰

| 토큰 | 용도 |
|---|---|
| `--color-paper` | 기본 배경 (크림 화이트) |
| `--color-grass` | 주요 액션 컬러 (초록) |
| `--color-grass-light` | 활성 상태 배경, 테두리 |
| `--color-bark` | 기본 텍스트 (짙은 갈색) |
| `--color-sky` | 보조 배경 (하늘 파랑) |
| `--color-sand` | CTA 섹션 배경 |

모든 토큰은 `app/globals.css`의 `@theme` 블록에서 정의하며, Tailwind 유틸리티(`bg-paper`, `text-bark` 등)나 `var(--color-*)` 형태로 사용한다. 보조 단계(`-2`, `-3`, `-dark`)와 `--color-accent*`, 그림자(`--shadow-card`, `--shadow-btn`), 이징(`--ease-smooth`, `--ease-bounce`) 토큰도 같은 블록에 있다.

### 폰트

- **Display / Body**: Nunito (Google Fonts, `next/font/google`)
- **Mono**: JetBrains Mono (코드, 시리얼 번호 등)
- **Luckiest Guy**(선택 페이지 제목): `app/page.tsx`가 `next/font/google`로 받아 `--font-title` 변수로 제목 "Dumb Dumb"에만 쓴다. 두툼한 만화 로고체라 장난꾸러기 같은 이름과 어울린다
- **Stylish**(버튼 이름·지도 글씨): `app/globals.css`가 `@font-face 'Stylish'`(`/ref-assets/fonts/Stylish-Regular.woff2`·`.woff`)를 전역으로 선언한다. 펼침 지도 글씨(지도 라벨의 한글·제목 태그·표지·범례·축척·쪽지 제목·도장·마커 라벨)가 쓴다. woff2 파일이 1MB 가까이 돼 선택 페이지가 `react-dom`의 `preload`로 미리 받아 두되 `fetchPriority: 'low'`로 받아 첫 화면 글자와 대역폭을 다투지 않는다(지도는 처음 쓰는 한글 글자 모양을 그려 저장해 다시 쓰므로 조각이 아닌 전체 파일이 먼저 와 있어야 한다)
- **선택 페이지 글자 전용 폰트**: 선택 페이지 버튼 이름은 `'Stylish Home'`(`public/fonts/stylish-home.woff2`, 4KB — "플레이 내 주변 에셋 미리보기"), 배지는 `'Pretendard Home'`(`public/fonts/pretendard-home.woff2`, 2KB — "베타 개발용")으로 그리고, 두 파일을 `preload`로 먼저 받는다 — 느린 휴대폰 망(1.6Mbps)에서도 0.7초 안에 제 글꼴로 뜬다(전체 폰트 936KB·748KB를 기다리면 14초 걸린다). 두 폰트의 `@font-face`는 `globals.css`에 한 번만 둔다 — 페이지 안에 두면 뒤로 가기로 선택 페이지가 다시 붙을 때마다 폰트를 다시 맞추느라(서버에 다시 확인한다) 버튼 이름·배지가 잠깐 비어 보인다. 공식 배포본(Google Fonts의 Stylish TTF, Pretendard v1.3.9 OTF)에서 fontTools `pyftsubset --text=… --flavor=woff2 --name-IDs='*'`로 만들어 OFL 라이선스 정보를 폰트 안에 남긴다(명령은 `app/page.tsx` 주석). 버튼 이름·배지 글자를 바꾸면 다시 만들고, 빠진 글자는 뒤의 전체 폰트로 그려진다
- **로더 글자 전용 폰트**: 로더 첫 줄(안내 한 줄)은 프로젝트 제목 글씨인 Stylish로 그린다(19px·`#5d5a57` — 펼침 지도 쪽지 제목과 같다). 로더 첫 줄과 GPS 상태 제목에 쓰는 글자만 담은 `'Stylish Loader'`(`public/fonts/stylish-loader.woff2`, 24KB)를 루트 레이아웃이 `preload`로 먼저 받아, 어느 페이지든 첫 화면이 로더여도 글자가 곧바로 제 글꼴로 뜬다. 만드는 법은 선택 페이지 글자 전용 폰트와 같고(명령은 `components/ui/loader.tsx` 주석), 로더 문구를 바꾸면 다시 만든다. 빠진 글자는 뒤의 전체 Stylish로 그려진다. `@font-face`는 `globals.css`에 한 번만 둔다 — 로더마다 넣으면 로더가 붙을 때마다 브라우저가 폰트를 다시 맞추느라 글자가 잠깐 숨는다
- **Pretendard**(한글 UI 글씨): `app/globals.css`가 `@font-face 'Pretendard'`(굵기 400 하나, jsDelivr의 `pretendard@v1.3.9` woff2·woff)를 선언하고, 루트 레이아웃이 woff2(약 770KB)를 `preload`로 미리 받는다. 로더 안내 줄(첫 줄 아래), 펼침 지도 쪽지의 안내 글씨·버튼이 쓴다(선택 페이지 배지는 아래 글자 전용 폰트)
- 웹 폰트는 모두 `font-display: block`이다(`next/font`도 `display: 'block'`). 기본 글꼴로 먼저 그렸다가 바꿔 끼우지 않고, 폰트가 오면 바로 그 폰트로 그린다 — 3초 안에 오지 않을 때만 기본 글꼴로 보인다

```tsx
// app/layout.tsx
import { Nunito, JetBrains_Mono } from 'next/font/google'
const nunito = Nunito({ subsets: ['latin'], variable: '--font-display', display: 'block' })
```

### 애니메이션 토큰

`@theme`의 `--animate-*` 토큰이 Tailwind `animate-*` 유틸리티가 된다.

| 유틸리티 | 효과 | 사용처 |
|---|---|---|
| `animate-float` | 4초 상하 부유(−10px) | 정의만 있음 |
| `animate-float-slow` | 6초 상하 부유 | 정의만 있음 |
| `animate-sway` | 5초 좌우 흔들림(±3°) | 정의만 있음 |

`fog-vignette` 유틸리티는 `--fog-radius` 런타임 변수를 쓰는 radial-gradient 비네트로, `lib/three/fog.ts`와 짝을 이룬다. 플레이 씬과 내 주변 모두 이 비네트를 붙이지 않는다.

## 3D 씬 — 플레이 씬과 내 주변 (ADR 001)

3D 씬은 두 곳이다. 로그인 없이 공개되는 **플레이 씬**과, 내 위치 주변 실제 길을 같은 화풍으로 까는 **내 주변(베타)**이 같은 렌더링 구조로 동작한다.

| 구분 | 플레이 씬 | 내 주변(베타) |
|---|---|---|
| 경로·진입점 | `/play` · `features/play/play-scene.tsx` | `/nearby` · `features/nearby/nearby-scene.tsx` |
| 베이스 | 베이크드 로우폴리 3D 씬 (`/ref-assets` 참조 에셋, 해변 섬) | 실제 길(OpenStreetMap 벡터 타일)을 그린 바닥 구역 |
| 좌표계 | 씬 로컬 미터 (Y-up) | GPS 위치를 0.001° 격자에 맞춘 원점 기준 로컬 미터. 다른 사람과는 위경도로 주고받는다 |
| 렌더러 | 씬 전용 `WebGLRenderer` 단일 캔버스 | 같은 구조 — 플레이 씬과 같은 공유 3D 엔진(`lib/three/`의 셰이더·3인칭 조작·그림자·후처리·원격 캐릭터)을 쓴다 |
| 네트워크 | 익명 socket.io `/room` — 같은 방 캐릭터 상태 중계 + 만남 대화(1:1 글, 저장 없음). 인증 없음, 서버가 없으면 혼자 | 익명 socket.io `/proximity` — 반경 200m 안 가까운 19명 |
| 펼침 지도 | M·HUD 지도 버튼으로 펼치는 종이 지도 — '나' = 실제 GPS 위치(캐릭터 옷 색), 북쪽 위 | 같은 종이 지도 — '나' = 캐릭터 자리 + 화면이 보는 방향 화살표, GPS가 잡은 자리는 작은 점·정확도 원으로 따로, 북쪽 위 |

내 주변(베타)의 세부 규칙은 아래 [내 주변(베타)](#내-주변베타-nearby) 절에, 펼침 지도는 [펼침 지도](#펼침-지도-paper-map--maplibre-gl-js) 절에, 위치 추적은 [GPS 상태](#gps-상태) 절에 있다.

### 렌더러 초기화 규칙

각 씬의 렌더러는 아래 지점에서만 만든다.

- **플레이 씬**: `features/play/play-scene.tsx`가 원본처럼 `new THREE.WebGLRenderer({ antialias: false, depth: false })`로 만들고 계단 현상은 SMAA로 편다. 픽셀 비율은 `min(devicePixelRatio, 1.5)`(데스크톱 사파리는 1)에 적응형 배수(0.7~1, 인트로 2초 뒤부터 4초마다 평균 FPS 30 미만이면 −0.1·60 이상이면 +0.1, 방향이 4번 뒤집히면 멈춤)를 곱한다. 그림자는 `PCFSoftShadowMap`. 후처리는 EffectComposer로 `RenderPass` → 최종 패스(`postprocess.ts` — 사면체 보간 LUT·인트로 리빌, 선형 공간) → `SMAAPass` → `OutputPass` 순서다. 카메라는 near 1m·far 175m다.
- **내 주변(베타)**: `features/nearby/nearby-scene.tsx`가 같은 설정(`antialias: false`·`depth: false`, `PCFSoftShadowMap`, `RenderPass` → 최종 패스 → `SMAAPass` → `OutputPass`, near 1m·far 175m)으로 만든다.
- 개발용 에셋 미리보기 `/asset-viewer`(`features/asset-viewer/asset-viewer.tsx`)는 자체 렌더러와 OrbitControls를 쓰고, 화면을 `fixed inset-0`으로 채워 창 크기를 따라간다. 세로로 긴 화면에서는 씬과 같은 기준(`framingFor(aspect).fov`)으로 화각을 넓힌다.
- 펼침 지도(`components/map/paper-map.tsx`)는 씬 렌더러를 쓰지 않는다 — MapLibre GL이 자기 캔버스(별도 WebGL 컨텍스트)를 만든다([펼침 지도](#펼침-지도-paper-map--maplibre-gl-js) 절).

### 렌더 루프 규칙

- **플레이 씬**: `play-scene.tsx`가 소유한 단일 `requestAnimationFrame` 루프에서 돈다. 프레임 간격(dt)은 0.1초로 클램프하고, 3인칭 컨트롤러 갱신 → 캐릭터 애니메이션 가중치(`kid-animation.ts` — idle↔run은 수평 속도, air·bored가 덮음) → 동적 그림자 중심을 카메라 시선 앞 6m로 이동 → 오디오(환경음·발소리) → 터치 원 UI → 같은 방 다른 캐릭터들(`remote-players.ts` — 위치·방향 보간, 가중치, 100m 안·화면 안일 때만 포즈) → 만남 대화 머리 위 자리(`talk.frame` — 머리 위 표시·E 키 상대 고르기, 표시·메뉴·말풍선 translate3d) → 캐릭터 믹서 → 갈매기 비행 → 하늘 돔 카메라 추종 → 인트로 리빌 uniform → 적응형 DPR → `composer.render()` 순서를 지킨다. LOD 단계는 렌더러가 `LODExtended.update`로 고르고, 생물 애니메이션은 각 오브젝트의 `onBeforeRender`(화면에 그려질 때만)에서 한다. NPC(UFO·alien·cats·sloth·gossip) 근접 상호작용은 비활성이며, 판정 로직은 `scene.tsx`에 주석으로 있다
- 플레이 씬의 거리 안개는 램프 셰이더가 카메라 거리 40~300m 구간에서 명도를 0.6으로, 채도를 0.3으로 모으는 고정값이다(원본 식). 가시거리 라이선스 등급은 어느 씬도 렌더링에 반영하지 않는다
- 플레이 씬의 그림자는 두 겹이다 — 동적 그림자맵(2048², 시선 앞 ±12m)과 로딩 때 씬 전체를 한 번 구운 정적 그림자(`shadows.ts`, 4096², LOD 단계별 3장 — 원본 데스크톱 값 8192²는 타깃을 잡는 것만으로 내장 GPU에서 화면 합성을 0.4초쯤 멈춰 로더 스피너가 끊긴다. 4096²도 한 번에 잡고 그리면 0.05~0.1초 멈춰 1024² 조각으로 나눠 굽는다). 동적 그림자 중심에서 9~12m 사이에서 정적 그림자로 넘어간다. 캐릭터가 아닌 면은 카메라 1.5~2m 안에서 가로줄 디더로 솎아낸다
- **로더 뒤 GPU 예열**(`lib/three/warm-up.ts`): 로더는 렌더링 준비가 다 끝난 뒤에 걷는다 — 로더가 걷힌 뒤에는 셰이더 컴파일·버퍼·텍스처·렌더 타깃을 새로 만드는 일이 없고(걸어 다니며 처음 보는 곳까지), 매 프레임 애니메이션 갱신만 남는다. 플레이 씬은 에셋(늦게 오는 인트로 전환 이미지·터치 원 텍스처까지)을 모두 붙일 때까지 `composer.render()`를 부르지 않는다 — 로더가 덮은 동안 그리면 물체가 붙을 때마다 첫 렌더가 셰이더 컴파일·업로드를 몰고 온다. 다 붙으면 씬 재질을 물체마다 병렬 컴파일(`compileAsync`, `KHR_parallel_shader_compile`)하며 새 프로그램이 생길 때마다 한 프레임 쉬고, 후처리 패스 재질과 동적 그림자 깊이 재질(`compileShadowDepth` — three처럼 면·맵 등을 옮긴 재질)도 같은 방식으로 컴파일한다. 이어 텍스처를 하나씩 올리고(`initTexture`) 정적 그림자를 1024² 조각마다 굽되(조각만 보는 카메라 `setViewOffset`로 조각 크기 임시 타깃에 그려 맵의 같은 자리로 복사한다 — 4096² 깊이 타깃을 한 번에 잡지 않는다), 하나 넘길 때마다 GPU가 그 일을 끝낼 때까지 WebGL2 펜스로 기다린다(`settle` — 큰 업로드·그리기는 메인 스레드에서 금방 돌아와도 GPU에서는 더 걸려, 바로 다음 일을 넘기면 GPU에 일이 밀려 화면 합성이 끼어들 틈이 없다). 그다음 씬의 모든 물체(숨긴 LOD 단계·멀리 있어 숨긴 묶음·평소 숨겨 둔 터치 원까지)를 16×16 타깃에 24개씩 한 번 그려(`drawAllGradually`, 동적 그림자 포함) 지오메트리·인스턴스 버퍼와 그리기 상태(VAO)를 미리 만든다 — 그려 보지 않은 물체는 걸어가다 처음 화면에 들 때 이 일을 몰고 온다. 인트로가 시작될 카메라 자리(`INTRO_ZOOM`만큼 물린 자리)에서도 한 번 그린 뒤, GPU가 비면 화면 크기로 한 프레임 그려 첫 렌더의 버퍼 업로드를 마치고 GPU가 다 그릴 때까지 기다린다(펼침 지도는 기다리지 않는다 — 처음 펼칠 때 만든다). 그 뒤로는 로더가 덮는 동안 씬을 그리지 않고, 로더 배경이 녹기 시작할 때(걷기 시작한 뒤 `LOADER_DISSOLVE_MS` 0.5초)부터 그린다 — 덮인 캔버스는 화면 합성이 기다리지 않아 매 프레임 그린 일이 GPU에 밀려 쌓이고(창 2048×1100·배율 125%의 내장 GPU는 한 프레임에 30~40ms), 로더가 녹아 씬이 처음 보이는 순간 그 일을 한꺼번에 기다리느라 화면이 0.4~1초 멈춘다. 그동안 GPU를 붙잡아 스피너도 끊긴다. 크롬(윈도우)은 화면 합성과 WebGL 명령을 같은 GPU 스레드에서 처리해, 이런 일이 한 프레임에 몰리면 합성 스레드의 CSS 스피너도 멈추기 때문이다
- 셰이더는 그리는 곳(화면·렌더 타깃)에 따라 출력 색 공간이 달라 다른 프로그램이 된다 — 실제로 그릴 타깃(컴포저 버퍼)을 걸고 컴파일한다. 정적 그림자를 굽는 동안에는 씬의 빛을 굽기 레이어에 넣어 빛 조건을 화면과 같게 둔다(three는 프레임마다 그림자를 빛 상태를 갱신하기 전에 그려, 첫 프레임 동적 그림자가 직전 굽기의 빛 상태를 쓴다). 미리 컴파일에 쓴 재질은 씬을 치울 때 dispose한다 — 먼저 dispose하면 프로그램도 함께 지워진다
- 내 주변도 같은 순서로 예열한다 — 씬을 다 붙일 때까지 그리지 않고, 씬·후처리·동적 그림자 깊이 재질을 나눠 컴파일하고 텍스처를 하나씩 올린 뒤 모든 물체를 한 번씩 그려 두고(`drawAllGradually`) 화면 크기로 한 프레임 그린 뒤, 로더 배경이 녹기 시작할 때부터 그린다(덮인 동안 그리지 않는 까닭은 플레이 씬과 같다). 처음 그리는 물체를 한 프레임에 몰아 그리면 드라이버의 첫 그리기 준비로 화면 표시(Present)가 0.2초 가까이 막힌다. 에셋 미리보기는 물체마다 병렬 컴파일(`compileGradually`)한 뒤에 그린다
- 스킨 메시의 뼈 번호(`skinIndex`)는 `createSkin`이 float(`Float32Array`)로 바꿔 둔다 — 정수(Uint16)를 float 속성으로 읽히면 윈도 크롬(ANGLE D3D11)이 그 셰이더를 처음 그릴 때 이 형식에 맞는 정점 셰이더를 새로 컴파일하느라 GPU가 40~50ms 멈춘다(미리 컴파일해 둬도 피하지 못한다)

### 오브젝트 생명주기

- `.bin` 에셋은 `lib/three/bin-loader.ts`의 `loadBinGeometry`로만 로드한다. 이름별 Promise 캐시와 공유 DRACOLoader 워커를 쓰며, 캐시가 소유한 지오메트리(`userData.shared = true`)는 dispose하지 않는다. 인스턴스마다 속성을 붙여야 하면 `clone()`한 뒤 쓴다
- 플레이 씬의 kid는 `play-scene.tsx`가 `createSkin`으로 직접 조립하고, 같은 방 다른 캐릭터는 `remote-players.ts`가 같은 지오메트리·클립으로 한 명마다 스킨드 메시·믹서·재질(색 시드)을 따로 만든다. 나가면 0.25초에 걸쳐 줄인 뒤 스켈레톤·재질을 dispose하고, 방에 다시 들어가거나 연결이 끊기면 곧바로 모두 지운다
- 에셋 미리보기는 `lib/three/character.ts`의 `loadCharacter`(ref-assets kid 스킨드 메시)로 캐릭터를 띄우고 `Character.dispose()`로 정리한다
- 플레이 씬은 언마운트 시 루프를 멈추고 씬 소켓을 닫은 뒤 다른 캐릭터들·오디오·머티리얼·정적 그림자맵·바다 반사·갈매기·터치 원·KTX2 로더·컴포저·렌더러를 dispose하고 캔버스를 떼어 낸다
- 만남 대화 상태(`createTalk`)는 씬 컴포넌트가 처음 렌더할 때 한 번 만들어 ref에 두고(대화 화면과 우상단 받기 버튼이 같은 것을 구독한다), 씬 소켓을 연 뒤 `bind(connection.talk)`로 잇는다. 언마운트·재접속 때는 `bind(null)`·`reset()`으로 진행 중인 요청·대화를 비운다
- 펼침 지도는 내 주변은 씬이 시작되면(`playing`), 플레이 씬은 씬을 불러오는 동안(WebGL2가 없거나 불러오지 못하면 붙이지 않는다) 마운트되고, 처음 펼칠 때 MapLibre 지도를 한 번 만들어 접혀 있어도 살려 두며, 언마운트 때 마커를 지우고 `map.remove()`한다. GPS 추적기(`createGpsTracker`)는 씬이 이펙트 안에서 만들고 언마운트 때 `dispose()`한다 — 개발 모드(StrictMode)가 이펙트를 두 번 돌려도 추적기가 하나만 남는다

## 이동·카메라

### 플레이 씬

- **PC**: WASD·방향키로 카메라 기준 전후좌우로 이동하고, 스페이스로 점프한다(누르고 있어도 한 번만 뛴다). 마우스 왼쪽 버튼을 누르고 있으면 화면 고정점(가로 중앙, 세로는 캐릭터 발끝 — 16:9 이상에서는 원본 값인 위에서 72.5%, 그보다 좁으면 반응형 구도에 맞춰 발끝을 따라간다)에서 커서까지의 방향으로 이동하며, 고정점에서 화면 짧은 변 × 0.23(90~200px, 원본 200px)만큼 떨어지면 입력이 최대 세기가 된다. 오른쪽 버튼을 짧게(0.5초 미만) 눌렀다 떼도 점프다. 게임패드 0번의 왼쪽 스틱(데드존 0.15~0.25)과 A 버튼도 받는다. 인트로 시작 1.5초 뒤부터 조작을 받고, 창이 포커스를 잃으면 입력을 끊는다. 60초 넘게 멈춰 있으면 캐릭터가 심심해하는 모션(kid-bored)으로 바뀐다.
- **이동 물리**: 원본 수식·상수를 그대로 따른다. 입력만큼 가속하고 매 프레임 감쇠해(관성) 약 0.5초에 걸쳐 최고 속도 약 3.75m/s에 이르고, 손을 떼면 약 0.7m 미끄러져 선다. 점프는 높이 약 1.1m·체공 약 0.5초다.
- **터치**: 첫 손가락은 처음 누른 자리 기준 조이스틱이다(75px 끌면 최대). 누른 자리에 이동 원이 나타나고 안쪽 손잡이가 끄는 방향으로 밀린다(`touch-circles.ts`). 짧게(15px·0.75초 미만) 탭하면 점프하고, 두 번째 손가락 탭은 점프하면서 그 자리에 점프 원을 퍼뜨린다. 휴대폰은 위아래 커서 패럴랙스가 없다.
- **GPS**: 실제 위치는 펼침 지도의 '나' 표시에만 쓰이고 씬 이동을 직접 구동하지 않는다. 사이트 권한이 이미 허용돼 있으면(Permissions API `granted`) 씬 페이지를 열 때 바로 추적하고, 아니면 지도를 처음 펼칠 때 권한을 묻는다([GPS 상태](#gps-상태) 절).
- **시작 위치**: 원본 오프닝 좌표(12.2, 2.25, −58) 주변 ±4m에서 무작위로 고른 점을 collider 표면에 세운다.
- **카메라**: 3인칭 추적 카메라로 씬 안을 이동한다(`lib/three/third-person.ts`). 화면 중심 주체는 캐릭터이며, 이동 좌표는 씬 로컬 좌표다(같은 방 사람에게 보이도록 씬 소켓으로 보낼 뿐 서버가 물리를 계산하지 않는다). 카메라는 화면 비율 16:9 이상에서 원본 구도(세로 화각 45°, 시선 목표점(발 위 1.1m·정면 0.5m) 중심 반경 5.836m·앙각 9.866°)의 고정 각도로 서고, 그보다 좁은 화면에서는 아래 반응형 구도를 따른다. 리그 세부는 [ADR 006](../adr/006-quarter-view-camera-lock.md)을 따른다.
- **반응형 구도**(`third-person.ts`의 `framingFor(aspect)`): 화면 비율(가로/세로)이 16:9에서 9:19.5로 좁아질수록(smoothstep) 세로 화각 45°→66°, 반경 ×1→×1.3, 앙각 +0°→+8°, 시선 들기 0°→5°로 옮겨 가 캐릭터가 화면 아래쪽에 선다. 가장 긴 세로 화면에서 하늘·앞길·발밑이 대략 3분의 1씩 보인다. 처음에는 곧장 맞추고, 창 크기·회전으로 비율이 달라지면 화각·극각·시선각·반경이 모두 줌 스무딩 비율(`lerpZoom`, 60fps 한 프레임당 0.05)로 부드럽게 따라간다. 컨트롤러가 `camera.aspect`를 보고 스스로 맞추므로 씬은 aspect만 갱신한다. 벽 충돌로 줄이는 반경의 상한과 인트로 줌 시작 반경은 구도 반경 기준이고, 패럴랙스·흔들림은 원본 값 그대로 얹는다. 마우스 조이스틱 고정점(`mouseCenterY`)도 구도가 정한다. 두 씬(플레이·내 주변)이 같은 컨트롤러라 둘 다 적용되고, 에셋 미리보기도 세로 화면에서 같은 기준으로 화각을 넓힌다.
- 캐릭터는 캡슐(반경 = 키 × 0.2)로 충돌 메시(`collider.bin`, `three-mesh-bvh`)와 부딪친다. 벽에서는 벽을 따라 미끄러지고, 캡슐이 타고 넘을 수 있는 낮은 턱만 오르며, 난간에서는 떨어진다.

### 내 주변(베타) (`/nearby`)

실제 지도의 길을 플레이 씬 화풍으로 깔아 펼침 지도와 맞춰 보는 1단계 베타다(`features/nearby/`). 같은 동네에 들른 사람은 실제 자리에 보인다. 땅의 쓰임(잔디·숲·광장)·건물·소품·물·고도는 2단계에서 붙인다([로드맵](../roadmap.md) P2-4).

- **데이터**: OpenStreetMap 벡터 타일(OpenFreeMap, OpenMapTiles 스키마)의 `transportation` 레이어를 z14 타일 단위로 받는다(`lib/geo/vector-tiles.ts`). 철도·지하철·뱃길·공사 중·터널·실내 길은 뺀다. 화면 좌하단에 출처(OpenStreetMap·OpenMapTiles·OpenFreeMap)를 표기한다
- **좌표**: 시작 위치를 0.001° 격자에 맞춘 점이 원점이다(`lib/geo/local-frame.ts`, 1m = 1m, 동쪽 +x·북쪽 −z). 캐릭터는 시작 위치(격자에 맞추기 전 좌표)에 서서 북쪽을 바라보며 시작한다 — 차도 위면 가장 가까운 인도로 옮겨 세운다(`nearestWalk`). 실제 위치에 세우므로 컨트롤러의 시작 흩뜨림은 끈다(`spawnRadius: 0`, 플레이 씬은 ±4m)
- **시작(대기형)**: 씬이 GPS 추적기를 만들고 곧바로 `waitForStartFix`로 위치를 요청한다(iOS에서 동작 권한을 물어야 하면 권한 단계의 '허용'을 누른 뒤). ±50m 안 위치가 오면 바로 시작하고, 그보다 흐리면 첫 위치를 받고 6초 동안 더 나아지길 기다렸다가 그 사이 가장 나은 위치로 이 근처에서 시작한다. 위치를 하나도 못 받는 동안(권한 창·찾는 중·권한 거부·https 아님·미지원)은 스스로 넘어가지 않고 대기 화면에서 계속 기다린다(시간 제한이 없고, 받은 위치 없이는 시작하지 않는다)
- **대기 화면**: 로더(`components/ui/loader.tsx`)를 띄우고, 위치를 기다리는 동안은 로딩 첫 줄 "내 위치를 찾는 중이에요"만 둔다(작은 줄 없음 — 플레이 씬과 같다). 해야 할 일이 있을 때만 상태별 제목·안내(`startWaitNote`)로 바꾸고 설정 순서는 로더의 `detail`에 번호 목록(`GpsSteps`)으로 붙인다 — 권한을 묻거나 꺼져 있을 때, 보안 연결이 아니거나 위치를 못 쓰는 브라우저일 때, 신호가 한참 늦을 때다. 찾는 중·흐린 위치에는 스피너가 돌고, 받을 수 없는 상태면 스피너 없이 안내와 버튼만 둔다. 권한 거부 등에는 "다시 시도"(iOS는 "새로고침") 버튼이 뜬다. iOS에서 동작 권한을 아직 묻지 않았으면(`queryMotionPermission`이 `prompt`) 위치 요청을 미루고 권한 단계에 스피너 없이 '허용' 버튼 하나를 둔다(`motionAskNote`) — 동작 권한 창은 탭 안에서만 띄울 수 있어서다(웹 AR에서 흔한 방식). 누르면 동작 권한 창(`requestMotionPermission`)과 위치 권한 창을 차례로 띄우고, 동작 권한 답과 상관없이 위치를 기다린다. 제목은 위치도 처음이면 "위치와 동작 권한을 허용해 주세요", 위치가 이미 허용됐으면 "동작 권한을 허용해 주세요"이고, 위치가 막혀 있으면 묻지 않고 거부 안내를 먼저 띄운다. 묻지 않고 동작 센서를 주는 브라우저(Android 크롬 등)는 이 단계가 없다. 휴대폰 권한 안내(위치 권한 창·iOS 권한 단계)에만 "운전 중에는 화면을 보지 말아 주세요"를 덧붙인다 — 세계에 들어가기 전 한 번이고, 들어간 뒤로는 탈것을 타도 글을 띄우지 않는다. 흐린 위치(±50m 넘음 — `weak`·`coarse`·`approximate`, 받다가 멈춘 `stale`)를 받는 동안도 첫 줄 그대로 기다렸다가 알아서 시작한다 — 몇 초 뒤 사라질 화면이라 위치를 또렷하게 하는 방법은 시작한 뒤 위쪽 알림과 펼침 지도가 보여 준다. 위치를 받으면(첫 줄은 적어도 2초 보여 준 뒤) 같은 간격으로 문구를 넘기고(플레이 씬처럼 화면을 만드는 일이 아니라 내가 동네로 나서는 순서로 말한다 — "창밖 날씨를 보는 중이에요" → "현관문을 나서는 중이에요" → "엘리베이터를 기다리는 중이에요"), 준비가 끝나면 "동네로 나가요!"를 띄운 뒤 글이 흐려지고 배경이 녹아 씬이 드러난다. 길을 불러오지 못하면 "내 주변 길을 불러오지 못했어요"와 "다시 시도"(위치 받기부터 다시)를 띄운다(오류 내용은 콘솔에 남긴다)
- **이어 깔기**(`ground-stream.ts`): 바닥을 한 변 256m 구역으로 나눠 캐릭터가 선 구역 둘레 3×3을 깔아 둔다 — 가장자리에 서도 앞쪽 256m가 깔려 있어 보이는 거리(175m)보다 넉넉하다. 다른 구역으로 넘어가면 앞줄을 한 구역씩 더 깔고, 두 칸 넘게 멀어진 구역은 치운다. 불러오는 사이 빈 곳은 잔디만 있는 받침 바닥(4km, 구역보다 5cm 아래)이 받친다. 충돌 바닥은 끝없이 넓은 평면 하나다(가장자리 벽·범위 끝 없음)
- **걸을 수 있는 곳**(`GroundStream.nearestWalk`): 보이는 대로 걷는다 — 화면에 그린 막힌 곳만 피하고, 그 밖은 잔디·공터·광장·인도 모두 걸을 수 있다(게임 엔진 내비메시처럼 바닥은 걸을 수 있고 장애물만 구멍을 낸다). 지금 막힌 곳은 차도로, 깔린 구역의 마스크에서 r ≥ 128인 칸이다. 건물·물은 그리게 되면 막힌 곳에 더한다([로드맵](../roadmap.md) P2-4). 걸을 수 있는 칸이면 그 자리를, 차도 위면 둘레를 한 겹씩 넓혀(최대 150m) 가장 가까운 칸을 찾고, 같은 방향으로 인도 폭(1m)까지 들어가 본 그 폭의 가운데 자리를 돌려준다(가장자리 칸에 서면 몸이 차도에 걸친다). 그 자리 구역이 아직 안 깔렸거나 150m 안에 없으면 `null`이다
- **워커에서 그리기**(`ground.worker.ts` · `ground-source.ts`): 타일 받기·해석과 구역 마스크 그리기는 워커의 OffscreenCanvas에서 하고, 메인 스레드는 돌려받은 픽셀(전송, 복사 없음)로 텍스처만 만든다 — 구역 하나를 그리는 데 약 40ms가 들어 메인 스레드에서 그리면 경계를 넘을 때마다 멈칫하기 때문이다. 워커는 받은 z14 타일을 로컬 좌표로 바꿔 12장까지 캐시하고, 구역을 그릴 때 그 구역(+가장 넓은 길 절반 여유)에 걸치는 길만 쓴다. 워커나 OffscreenCanvas가 없거나 워커를 띄우지 못하면 같은 코드를 메인 스레드에서 돌린다
- **바닥 한 구역**(`ground.ts`): 길을 그린 마스크를 원작 지형 셰이더에 꽂는다(구역마다 768², 약 0.33m/px). 채널은 원작 `masks.png`와 같아 r = 차도, b = 인도·보행로(흙길 색)이고, 차선 점선은 원작 `terrain-road`처럼 별도 텍스처의 r에 그린다. 차도 폭은 도로명 끝 글자로 정한다(도로명주소 부여 기준) — 대로 40m, 로 20m, 길 8m이고, 대로·로가 방향마다 한 줄씩(일방) 그려졌으면 한 줄은 절반이라 두 줄이 모여 한 길이 된다. 이름은 같은 타일의 `transportation_name` 레이어에서 도로 선분마다 2m 안의 가장 가까운 이름선을 찾아 다수결로 붙인다. 고속도로·도시고속도로(motorway·trunk)는 이름과 상관없이 대로로, '대로'로 끝나도 간선 등급이 아니면(예: 경기대+로) 로로 본다. 이름이 없으면 등급으로 가늠하고(간선·보조간선 → 로, 그 밖 → 길), 이름 없는 주차장 통로·진입로는 5m, 램프는 8m다. 인도는 양옆 1m다. 길 선은 구역 경계를 넘어 이어 그리므로 이웃 구역과 이음매 없이 맞는다
- **차선 점선 박자**(`ground.ts`): 길 데이터는 타일(약 2km)마다 따로 오고 같은 길이 이웃 타일에도 겹쳐(버퍼) 들어 있어, 선 시작점부터 무늬를 세면 타일 경계 둘레 수십 m에서 두 박자가 겹치고 경계에서 끊긴다. 그래서 가운데 점선만은 제 타일 안쪽으로 잘라 한 번씩만 그리고, 잘린 끝(타일 경계)에는 늘 틈 한가운데가 오게 무늬 시작점을 맞춘다. 양 끝이 모두 타일 경계인 조각은 그 사이에 무늬가 딱 맞게 주기(6m)를 조금 늘이거나 줄인다(100m 조각이면 3% 안). 구역 경계에서는 같은 선을 같은 시작점부터 그리므로 박자가 저절로 맞는다
- **이동**: PC는 플레이 씬과 같은 3인칭 조작이다. 휴대폰은 GPS로만 걷는다 — 직접 조작은 늘 꺼 두고(`controller.setEnabled(false)`. 손으로 옮기면 실제 위치에서 멀어져 GPS가 도로 끌어당긴다), 컨트롤러의 `steer` 입력으로 걸음 목표까지 걸어가며, 0.3m 안이면 서고(차도 위 목표는 폭 1m 인도 가운데로 옮기므로 그 안에 서게) 그보다 4m 더 멀면 최고 속도다. 걸음 목표는 ±50m 안 위치(`isWalkableFix`)만 쓰고(그보다 흐린 위치는 목표로 쓰지 않아 캐릭터가 마지막 목표에서 멈춰 선다), 목표가 캐릭터에서 150m 넘게 떨어져 있으면(지하철·차) 걸어가지 않고 컨트롤러의 `snap`으로 곧장 옮긴다. PC는 시작한 자리에서 걷고 GPS를 따라가지 않는다(흐린 위치로 시작했어도 나중에 옮기지 않는다)
- **GPS 거르기**(휴대폰): GPS 위치를 칼만 필터로 거른다. 새 위치마다 거른 자리의 분산에 '초당 2m 움직일 수 있음'(`GPS_MOTION_MPS`, 탈것이면 30m — `RIDE_MOTION_MPS`)만큼 더한 뒤 정확도²를 측정 분산으로 섞는다. 거른 자리에서 정확도의 두 배(최소 3m, GPS 속도로 지난 위치 뒤 흐른 시간만큼 갈 거리의 두 배가 더 크면 그만큼) 넘게 떨어진 위치는 섞지 않고, 서로 그 거리 안에 세 번 잇달아 찍히면(`GPS_JUMP_COUNT`) 그 위치에서 새로 시작한다(첫 위치는 곧장). 상태만 바뀐 알림도 같은 위치를 다시 싣고 오므로 위치의 `timestamp`로 한 번만 세고, 구독 전에 받은 위치(캐릭터를 세운 위치)는 구독한 직후 `gps.snapshot`으로 넣는다
- **걸음 목표**(휴대폰): 거른 자리다 — 잔디·공터·광장·인도면 그 자리 그대로이고, 차도 위면 거리와 상관없이 가장 가까운 인도로 옮긴다(`nearestWalk`, 구역이 안 깔렸으면 거른 자리 그대로). 새 목표가 지난 목표에서 6m(`WALK_HOP_M`) 넘게 떨어지면(예: 차도 위에서 길 건너편 인도로) 거른 자리가 그쪽에 지난 목표보다 6m(`WALK_HOP_MARGIN_M`) 넘게 가까운 위치가 세 번 잇달아 찍혀야 옮긴다 — 차도 위에서 흔들려도 이쪽저쪽 인도를 오가지 않는다. 서 있던 캐릭터는 목표가 3m(`GPS_STEP_M`, 정확도의 절반이 더 크면 그만큼) 넘게 떨어져야 출발하고(서 있는데 몇 m씩 옮기면 몸이 돌고 카메라가 따라 돈다), 출발하면 0.3m 안에 닿을 때까지 목표를 새 자리로 계속 바꾼다. 캐릭터가 차도 위(탈것에서 내린 뒤 등)에 서 있으면 거리와 상관없이 목표까지 간다
- **탈것**(휴대폰): 웹에는 기기 활동 인식이 없어 발걸음(가속도계)과 GPS 속도(`GpsFix.speed`)로 가린다 — 앱의 Android 활동 인식·iOS Core Motion과 교통수단 판별 연구도 가속도계로 걷는지부터 가린다. GPS 속도는 도플러로 재서 실내·빌딩 사이에서 위치가 튀어도 튀지 않는다. 걸음 없이 GPS 속도가 시속 10km(`RIDE_ENTER_MPS`)를 넘는 채로 5초 이어지면 탈것이고, 걸음이 3초(`RIDE_EXIT_MS`) 이어지면(내려서 걸으면) 다시 걷기다 — 정차·신호 대기에는 걸음이 없어 그대로 탈것이고, 달리기는 걸음이 있어 탈것이 아니다. 시속 25km(`RIDE_FAST_MPS`)를 넘으면 걸음과 상관없이 탈것이다(페달 흔들림·차 안에서 걷기). 가속도가 오지 않으면(iOS 권한 거절·센서 차단) GPS 속도만으로 보수적으로 가린다 — 시속 25km를 넘는 채로 5초면 탈것, 시속 7km 아래로 30초 이어지면 다시 걷기다(정차와 내림을 구별할 수 없어 길게 기다린다). GPS 속도를 못 재는 위치(null)로는 탈것이 되지 않는다. 탈것이면 걸음 목표를 멈추고(차도 위여도 인도로 옮기지 않는다), 매 프레임 컨트롤러의 `glide`로 받은 자리를 지난 10초(`RIDE_WINDOW_MS`) 이동으로 잰 속도로 앞질러 어림한 자리(최대 3초 앞)를 선 채로 따라붙는다(시간 상수 0.3초, 판정 전 뒤처진 거리는 그 속도의 세 배·최소 초속 20m까지). 500m 넘게 떨어지면 `snap`으로 곧장 옮긴다. 캐릭터 모션은 3(탈것 — idle 포즈)이고, `/proximity`에는 위치를 5.5초(`RIDE_SEND_MS`)마다 한 번만 새로 보낸다(서버가 초당 10m 넘는 이동은 5초에 한 번 순간이동으로만 받는다). 탈것이라고 알리는 글은 띄우지 않는다(탈것 에셋은 예정 — 모션 3에 그린다)
- **발걸음**(`lib/geo/steps.ts`): `devicemotion`의 중력 포함 가속도 크기를 고른 값(시간 상수 0.03초)에서 바닥선(0.3초)을 뺀 값이 1m/s²를 넘었다가 바닥선 아래로 돌아오면 한 번 솟은 것으로 보고, 앞 봉우리와 0.25~1.25초 간격이면 박자 맞는 걸음으로 센다(더 짧으면 한 걸음 안의 흔들림, 더 길면 박자가 끊긴 첫걸음이라 다음 걸음의 기준으로만 둔다). 지난 3초에 박자 맞는 걸음이 3번 이상이면 걷는 중이다(뛰기 포함). 2초 넘게 값이 안 오면 센서를 못 쓰는 것으로 본다. Android 크롬은 묻지 않고 값을 주고, iOS는 동작 권한을 받은 뒤 만들어야 값이 와서 권한 단계를 지난 뒤 만든다
- **펼침 지도의 '나'**: 씬 루프가 매 프레임 `MapTrack { lng, lat, bearing }`(캐릭터 자리와 화면이 보는 방향 — 카메라 시선의 북쪽 기준 시계방향 각도)을 채우고, 펼침 지도는 이를 '나'와 방향 화살표로 그린다. GPS가 잡은 자리는 따로 작은 점과 정확도 원으로 보인다
- **위쪽 알림**: `walkNote`가 정한 한 줄과 "지도 보기" 버튼(누르면 지도를 펼친다)을 가운데 위에 띄운다. 휴대폰에서 GPS가 걸음을 못 따라갈 때("걸음 신호가 잠시 멈췄어요 · 걸으면 다시 따라가요", ±50m 밖이면 "GPS 신호가 약해(±N) 캐릭터를 잠깐 멈춰 뒀어요"), 위치를 받을 수 없게 됐을 때("위치를 받을 수 없어 캐릭터가 GPS를 따라가지 않아요") 뜬다. 좁은 화면에서는 버튼이 글 아래 줄로 내려가고, 오른쪽 위 지도 버튼과 겹치지 않게 비켜 둔다. 지도가 펼쳐져 있으면 숨긴다
- **지도 버튼**: 우상단(위·오른쪽 20px)에 플레이 씬 HUD 버튼과 같은 모양의 지도 버튼 하나를 둔다(`aria-label`·툴팁 "지도 펼치기 (M)", 위치를 못 잡으면 구석에 "!", 손가락 기기 1.2배·2400×1300px 이상 화면 1.3배). 소리가 없어 클릭음이 없고, 등장 애니메이션 없이 씬이 시작되면 바로 뜬다. 단축키는 M(펼치기/접기)·Esc(접기)이고 Ctrl+M은 없다. 지도가 화면에 있는 동안(접을 때는 다 접혀 배경이 걷힐 때까지 — `onClosed`) PC 캐릭터 조작(키보드·마우스·터치)은 끄고(`controller.setEnabled(false)` — 휴대폰은 늘 꺼져 있다), 휴대폰 GPS 걷기(`steer`)는 계속된다
- **출처 표기**: 길이 깔린 동안 좌하단에 "지도 데이터 © OpenStreetMap · OpenMapTiles · OpenFreeMap"(각각 링크)을 띄우고, 5초 뒤 (i) 버튼으로 접는다(누르면 다시 편다). 로딩·대기 화면에는 띄우지 않는다. OpenStreetMap 표기 지침은 표기를 접어 두어도 되지만 구석의 (i) 같은 곳에서 늘 찾을 수 있어야 한다고 하고, OpenFreeMap도 OpenMapTiles·OpenStreetMap 표기를 요구한다
- **멀티플레이**: 익명 socket.io `/proximity`(`lib/realtime/relay.ts`의 `connectRelay(…, 'proximity')`)로 플레이 씬과 같은 필드를 주고받되, 사람마다 씬 원점이 달라 위치 `p`는 실제 좌표 `[경도, 위도, 높이]`(소수 7·7·2자리, 약 1cm)로 보낸다. 받은 위치는 내 원점 기준 로컬 m로 바꿔 `remote-players.ts`에 넘긴다(로컬 축 방향이 모두 같아 방향 `r`은 그대로 쓴다). 방은 없고, 서버가 사람마다 반경 200m 안에서 가까운 19명을 골라 보여 준다(규칙은 백엔드 컨벤션). 멀어졌다 돌아온 사람은 같은 id로 다시 들어오므로, `remote-players.ts`는 사라지는 중인 캐릭터에게 갱신이 오면 지금 크기에서 다시 키운다. 모션 3(탈것)인 사람은 위치가 몇 초마다 오므로 지난 위치가 온 뒤 흐른 시간(1~8초)에 걸쳐 새 위치까지 선 채로 미끄러지듯 잇는다(500m 넘게 떨어지면 곧장 옮긴다)

## 씬 HUD — 우상단 버튼

씬 HUD는 `features/play/play-scene.tsx`에서 `sa-*` 클래스로 렌더한다. 수치는 뷰포트 폭 1200px 초과 기준이며, 1200px 이하 값은 괄호로 적는다. 내 주변은 같은 모양의 지도 버튼 하나만 둔다([내 주변(베타)](#내-주변베타-nearby) 절).

로딩 화면은 로더(`components/ui/loader.tsx`)로, 스피너 아래에 산책 채비 순서의 문구를 띄운다 — "산책 가방을 챙기는 중이에요" → "신발 끈을 묶는 중이에요" → "목줄을 채우는 중이에요" → 준비 끝 "이제 나가요!"(10초를 넘길 수 있는 기다림이라 진행을 보인다). 문구는 조사를 살린 문장으로 쓴다. 중간 줄은 실제 진행과 상관없이 2.4초마다 같은 간격으로 넘기고, 오래 걸리면 "목줄을 채우는 중이에요"에서 기다린다 — 실제 단계에 묶으면 첫 단계(에셋 받기)만 길고 뒤 줄이 몰아서 지나간다. 마지막 줄은 준비가 끝나야 뜬다: 지금 줄을 적어도 2초 보여 준 뒤 "이제 나가요!"로 바꾸고 1.2초 뒤에 로더를 걷는다(`useLoadingSteps` — 내 주변·에셋 미리보기도 같다). 간격은 가장 긴 줄(16자)을 한국어 자막 읽기 속도(초당 12자, 넷플릭스 성인 기준)로 읽는 1.3초에 줄이 바뀌며 흐려졌다 떠오르는 0.4초와 눈길이 가는 틈을 더한 값이고, 마지막 줄도 자막 최소 표시 시간(5/6초)보다 길게 둔다. 그러다 씬이 준비되면(아래 로더 뒤 GPU 예열과 펼침 지도 그리기까지 끝난 뒤, 일찍 준비돼도 스피너가 한 바퀴를 채운 뒤 — `waitSpinTurn`) 글·스피너가 0.75초(cubic in-out)에 걸쳐 흐려지기 시작할 때 인트로를 함께 시작하고, 로더 배경은 0.5초부터 0.5초에 걸쳐 녹인다(`dissolve`) — 인트로 덮개가 로더와 같은 크림색 `#FFFDF8`이라 이음매 없이 소용돌이가 열리는 장면이 드러난다. 글이 다 빠진 뒤에 인트로를 시작하면 소용돌이가 처음엔 아주 천천히 열려(4초 선형) 빈 화면이 1초쯤 남는다. 불러오지 못하면 스피너 없이 "게임을 불러오지 못했어요"와 "새로고침" 버튼을 띄운다(오류 내용은 콘솔에 남긴다). WebGL2가 없으면 로더를 걷고 같은 로더 모양으로 "이 브라우저에서는 게임을 열 수 없어요"와 최신 브라우저 안내만 띄운다(HUD·펼침 지도도 띄우지 않는다).

### 단축키·조작 잠금

| 키 | 동작 |
|---|---|
| M | 펼침 지도 펼치기/접기. Ctrl·Alt·Cmd와 함께 누르면 무시한다 |
| Esc | 펼침 지도 접기 |
| Ctrl+M | 사운드 버튼과 같은 소리 토글(클릭음 포함, 브라우저 기본 동작은 막는다). Shift·Alt·Cmd와 함께 누르면 무시한다 |
| E | 말 걸기 아이콘을 누른 것과 같다(클릭음 포함) — 원형 메뉴가 열려 있으면 그 사람에게(멀거나 쉬는 중이면 걸지 않고 아이콘이 흔들리며 까닭을 한 줄로 알린다), 없으면 메뉴를 열지 않고 손가락 표시에 E가 붙은 사람(쉬지 않는 가장 가까운 사람)에게 바로 건다. 둘 다 없거나 펼침 지도가 펼쳐져 있으면 받지 않고, 입력칸 안·IME 조합 중·Ctrl·Alt·Cmd와 함께면 무시한다 |

- `window`의 `keydown`으로 받고, 물리 키(`code`) 기준이라 한글 입력 상태에서도 동작한다. 키 반복은 무시하고, M·Esc(`useMapHotkey`)는 입력칸(`input`·`textarea`·`select`·`contenteditable`) 안이거나 IME 조합 중이면 무시한다. 씬이 준비된 뒤(`playing`)부터 받는다
- 오디오 첫 입력: 브라우저는 탭을 뗄 때(`touchend`·터치 `pointerup`)·`click`·`keydown` 처리 안에서만 소리를 켜 주고, 누르는 순간(`touchstart`·`pointerdown`)과 끌기는 치지 않는다(iOS 사파리는 끌기 뒤의 `touchend`도 치지 않는다). 그래서 선택 페이지의 '플레이' 링크(`components/ui/sound-link.tsx`)가 누르는 순간 오디오 컨텍스트를 켜 두고(`lib/audio/unlock.ts` — 1샘플 무음까지 틀어 iOS에서도 연다) 씬이 three 공용 컨텍스트(`THREE.AudioContext.setContext`)로 이어 쓴다. 같은 문서로 넘어가므로(클라이언트 이동) 그 누름이 남아 있으면(`navigator.userActivation.hasBeenActive`) 씬은 첫 입력을 기다리지 않고 오디오를 만든다. 주소로 바로 들어오면 페이지 `click`·캔버스 `pointerup`·`keydown`에서 오디오를 만든다. 켜짐 표시는 컨텍스트가 실제로 `running`이 될 때 바꾼다(`onUnlock`) — 첫 입력이 휴대폰 끌기면 오디오가 막힌 채 만들어져 꺼짐 표시로 남고, 다음 탭·클릭·키에서 풀리며 켜진다. 막힌 동안 사운드 버튼·Ctrl+M은 토글하지 않고 푼다. Ctrl·Shift·Alt·Meta만 누른 `keydown`은 첫 입력으로 치지 않는다 — Ctrl+M의 Ctrl이 먼저 소리를 켜 M이 곧바로 끄는 일이 없다. Ctrl+M이나 사운드 버튼이 첫 입력이면 소리를 켜는 것으로 끝난다(한 번 더 토글하지 않는다)
- 창을 숨기면(최소화·다른 탭, `visibilitychange`) 게임처럼 소리를 멈춘다 — 0.5초 시상수로 줄이고 2.5초 뒤 오디오 컨텍스트를 멈춰(`suspend`) 음악도 그 자리에 선다(그 전에 돌아오면 멈추지 않는다). 다시 보이면 곧바로 켜고(`resume`) 멈춘 자리에서 2초 시상수로 키운다(음소거 중이면 조용한 채로 켠다). 보이는데 오디오가 멈춰 있으면(iOS 사파리가 제스처 없이 켜 주지 않거나 전화 등으로 끊겼을 때) 다음 `pointerup`·`touchend`·`click`·`keydown`에서 켠다
- 펼침 지도가 화면에 있는 동안 캐릭터 조작을 끈다(`controller.setEnabled(false)` — 원본이 모달을 띄울 때처럼, 눌린 키·드래그를 풀어 캐릭터는 관성으로 미끄러져 선다). 펼치기 시작하면 바로 끄고, 접을 때는 다 접혀 배경(dim)까지 걷힌 뒤(`PaperMap`의 `onClosed`) 다시 켠다
- 만남 대화 입력칸에 포커스가 있는 동안에도 캐릭터 조작을 끈다(`onTyping` — 지도 상태와 함께 `syncControl`이 정한다). 글자를 칠 때 WASD로 캐릭터가 걷지 않는다

## 만남 대화 — 말 걸기·대화 창 (`components/hud/talk-layer.tsx`)

플레이 씬에서 가까이 마주친 두 사람이 서로 받아들여 1:1로 글을 주고받는 화면이다(규칙·수치는 [비즈니스 규칙](../product/business-rules.md)의 만남 대화, 서버 판정은 백엔드 컨벤션). 상태는 `lib/realtime/talk.ts`의 `createTalk()`가 들고, 화면은 그 스토어를 `useSyncExternalStore`로 읽어 그린다.

- **서버가 판정한다**: 요청이 이어졌는지, 대화가 열렸는지·끝났는지는 서버 이벤트(`talkStarted`·`talkEnded` 등)대로만 그린다. 화면이 먼저 바꾸는 것은 내가 건 요청의 "기다리는 중…"과 내가 끝낸 대화뿐이다(서버 답이 끝내 오지 않으면 요청 시간이 지난 뒤 기다림을 푼다)
- **머리 위 자리**: 사람마다 하나인 머리 위 표시(손가락 표시 또는 "기다리는 중…", `talk.hintAnchor(id)`)와 원형 메뉴·말을 건 사람의 "!"·내 말풍선·상대 말풍선 네 자리(`menu`·`inviter`·`selfBubble`·`peerBubble`, `talk.anchor()`)는 크기 0인 앵커다. 씬 루프가 매 프레임 `talk.frame()`으로 발 위 1.7m(원형 메뉴는 가운데를 가슴께 0.85m)를 캔버스 화면 좌표로 옮겨 `translate3d`로 놓으므로 React를 다시 그리지 않는다. 카메라 뒤이거나 화면 밖(NDC ±1.2)이면 `visibility: hidden`으로 숨기고(사라지는 중인 머리 위 표시는 마지막 자리에 둔 채 옅어진다), 화면 가장자리에서는 좌우로 내용 너비의 절반 + 8px, 위로 내용 높이 + 8px(원형 메뉴는 위아래로 높이의 절반 + 8px)만큼 안으로 당겨 잘리지 않게 한다
- **원형 메뉴**: 심즈의 파이 메뉴처럼, 화면에 보이는 캐릭터를 짧게 클릭·탭하면 그 사람 가슴께를 가운데로 지름 112px 고리(`tk-wheel`)가 펼쳐지고 고리 위에 44px 둥근 아이콘 버튼이 놓인다. 지금은 12시 자리의 말 걸기(말풍선 아이콘) 하나이고, 누르면 바로 요청을 건다. 나중 아이콘(인사·친구·차단)은 같은 고리의 다른 자리에 붙인다. 아이콘은 머리 위 표시와 같은 판정으로 4m 안(야외에서 평소 목소리로 대화하는 거리)에 들어오면 켜지고 4.2m 밖에서 꺼진다. 잠깐 못 쓰는 아이콘은 숨기지 않고 상태를 보인다 — 4.2m 밖이면 바탕을 채운 채 색만 옅게 하고(반투명으로 흐리면 뒤 풍경이 비쳐 깨져 보인다), 거절된 뒤 5분 동안은 아이콘을 덮은 어두운 덮개가 12시부터 시계 방향으로 걷힌다(게임의 쿨다운 표시 — `@property --tk-cool` + `conic-gradient`. 남은 시간은 덮개를 처음 그릴 때 한 번만 잰다. 다시 그릴 때마다 `animation-delay`를 새로 재면 이미 돌던 애니메이션이 그만큼 앞으로 튄다). 못 쓰는 아이콘을 누르면(E 키도) 아이콘이 흔들리고 "조금 더 가까이 가면 말을 걸 수 있어요"·"잠시 뒤에 다시 말을 걸 수 있어요"를 한 줄로 알린다. 그 사람이 떠나거나 화면 밖으로 나가거나 대화·요청이 생기면, 또 빈 곳을 누르거나 Esc를 누르면 닫힌다
- **누르기**: 씬(`play-scene.tsx`)이 캔버스를 감싼 요소에서 캡처 단계로 `pointerdown`을 먼저 받아 `talk.pick(x, y)`로 누른 자리의 캐릭터를 찾는다 — 머리 위 1.7m부터 발까지, 폭은 키의 0.6배(작게 보여도 최소 48px)인 칸이고, 겹치면 화면에 크게 보이는(카메라에 가까운) 사람, 화면 밖 사람은 고르지 않는다. 캐릭터면 이벤트를 3인칭 조작으로 넘기지 않아 이동·점프가 일어나지 않고, 12px 안 움직이고 0.6초 안에 떼면 `talk.select(id)`로 원형 메뉴를 연다. 빈 곳을 누르면 메뉴를 닫고 조작은 그대로 받는다. PC는 캐릭터 위에서 커서가 손가락 모양(`cursor: pointer`)이 된다
- **손가락 표시**: 로블록스 ProximityPrompt처럼 4m 안에 들어온, 화면에 보이는 사람마다 기다리지 않고 바로 머리 위에 손가락 표시(`tk-hint` — 손끝 아이콘)를 띄워 누를 수 있는 사람임을 알리고, 4.2m 밖으로 나가면 지운다(0.2m는 경계에서 깜빡이지 않게 둔 여유 — 사라진 자리와 다시 뜨는 자리가 거의 같다). 말 걸기 아이콘(말풍선)과 헷갈리지 않게 "눌러 보세요"를 뜻하는 모양이고, 1.6초마다 3px 오르내리며 테두리 파문이 퍼져 눈길을 끈다(마우스를 올리면 멈춘다). 나타날 때는 0.22초에 커지며 또렷해지고, 사라질 때는 뚝 없어지지 않고 그 자리에서 0.18초에 작아지며 옅어진 뒤 빠진다(Material 모션처럼 나가는 쪽을 짧게 — 사라지는 중에 다시 들어오면 그 자리에서 되돌아온다). 손가락으로 누르기 좋게 보이는 크기보다 9px 넓게 받고, 누르면 원형 메뉴를 연다. 그 가운데 쉬지 않는 가장 가까운 사람이 E 키 상대이고 그 표시에만 E가 붙는다(손가락 기기 `pointer: coarse`에서는 E를 숨긴다). 거절된 뒤 5분 동안 쉬는 사람의 표시는 숨기지 않고 흐리게, 움직임 없이 둔다(눌러서 메뉴를 열면 남은 시간이 보인다). 건 요청을 기다리는 동안은 그 상대 머리 위만 "기다리는 중…"이고, 상대가 4.2m 밖으로 가면 요청을 거두고 지운다. 대화 중이거나 받은 요청이나 원형 메뉴가 떠 있으면 표시가 없다
- **요청 카드**: "옆에서 말을 걸었어요"와 좋아요·다음에 버튼, 아래쪽에 남은 시간 막대(15초). 데스크톱은 위 가운데(폭 340px), 639px 이하는 우상단 HUD와 겹치지 않게 아래(엄지가 닿는 자리)에 띄운다. 639px 이하이면서 높이 560px 이하(휴대폰 가로)는 아래를 가득 펼치면 오른쪽 HUD 버튼 줄을 덮으므로 아래 가운데에 폭 min(340px, 100vw − 144px)로 띄운다. 받기를 꺼 두었거나 대화 중·카드가 이미 떠 있으면 카드 없이 `talkReply({ accept: false })`로 거절한다
- **대화 창**: 게임 채팅 관례(마인크래프트 자바·MMO의 왼쪽 아래 채팅)대로 오른쪽 위 HUD의 반대편인 왼쪽 아래에 340px(높이 min(46dvh, 420px))로 둔다. 639px 이하 세로 화면은 아래를 가득(높이 44dvh) 채우고, 높이 560px 이하(휴대폰 가로·낮은 창)도 같은 왼쪽 아래에서 높이만 화면에 맞춘다(최대 min(420px, 100dvh − 24px), 폭 min(340px, 100vw − 96px)) — 화면 크기가 바뀌어도 창이 오른쪽·아래·왼쪽을 오가지 않는다. 제목 "대화 중"(10m 밖이면 "멀어지고 있어요"), × 닫기, 대화 로그(최근 60줄, 최소 48px. 새 줄이 오면 맨 아래를 보던 중(맨 아래 32px 안)이거나 내가 보낸 글일 때만 맨 아래로 내리고, 위로 올려 읽는 중이면 자리를 두고 로그 아래 가운데에 "↓ 새 메시지 N개" 버튼을 띄운다 — 누르면 맨 아래로 내려가고, 직접 맨 아래까지 내려도 사라진다. 창 크기가 바뀌어 로그 높이가 달라져도 맨 아래를 보던 중이면 맨 아래에 붙는다(`ResizeObserver`) — 넘치면 세로로 스크롤하고, 스크롤바는 메신저처럼 화살표 없는 6px 둥근 막대로 마우스를 올리면 진해진다. 크롬·사파리는 `::-webkit-scrollbar`, 파이어폭스는 `scrollbar-width: thin`으로 그린다 — 크롬은 표준 `scrollbar-*` 값이 있으면 `::-webkit-scrollbar`를 버려 윈도우에서 화살표가 남으므로 `@supports selector(::-webkit-scrollbar)` 안에서 auto로 되돌린다), 빠른 문구 4개(메신저 빠른 답장·Material 칩 가이드처럼 한 줄로 두고 넘치면 옆으로 넘긴다 — 줄을 바꾸지 않는다. 더 있는 쪽 끝을 32px 흐리게 해(`data-more`: start·end·both) 잘린 게 아니라 더 있다는 것을 보이고, 마우스 세로 휠도 옆으로 넘긴다), 입력칸(200자, 글씨 16px — iOS가 확대하지 않게)과 보내기
- **말풍선·알림**: 보낸 글은 두 사람 머리 위 말풍선으로 7초 보였다 사라진다(최대 폭 min(240px, 60vw)). 끝난 까닭·이어지지 않은 요청·링크 막힘은 위 가운데 한 줄(2.6초)로 알리고, 요청 카드가 위에 떠 있으면 카드 아래로 비킨다. 639px 이하는 우상단 HUD 버튼 줄을 비켜 좌우 72px 안에 두고, 긴 글은 잘라 내지 않고 두 줄로 넘긴다(카드는 아래에 뜨니 비키지 않는다)
- **한글 입력**: Enter는 IME 조합 중(`isComposing`)이면 보내지 않는다 — 조합을 마무리하는 Enter에 보내면 마지막 글자가 한 번 더 간다. 보낼 글은 조합이 끝난 직후의 값을 아는 입력칸 DOM 값에서 읽는다. Esc는 입력칸을 벗어난다
- **글 검증**: 빈 글·200자 넘음·0.5초 안 재전송은 보내지 않고, 링크면 "링크는 보낼 수 없어요"를 띄운 채 쓰던 글을 남긴다. 서버가 같은 검증을 다시 한다
- **E 키 처리기**: `window` `keydown` 하나를 활성 상태(`active` — 펼침 지도가 접혀 있을 때)마다 한 번 건다. 클릭음 콜백은 ref로 최신 것을 부른다 — 부모가 렌더마다 새로 만든 콜백을 이펙트 의존성에 넣으면, 첫 키(소리를 켜며 씬을 다시 그린다)를 처리하는 도중에 처리기가 바뀌어 그 키를 놓친다
- **스타일**: `tk-*` 클래스를 컴포넌트 안 `<style>`에 둔다. 크림 `#f9efdc`·하드 그림자 `#716c66`·Pretendard 글씨, 카드·창 제목은 Stylish다. 층(`.tk-layer`)은 `pointer-events: none`이고 버튼·카드·창만 입력을 받는다. `prefers-reduced-motion`이면 애니메이션을 끈다(쉬는 중 덮개는 걷지 않고 다 덮어 두었다가 쉬는 게 끝나면 걷는다)

## 펼침 지도 (Paper Map) — MapLibre GL JS

플레이 씬과 내 주변은 M 키나 HUD 지도 버튼으로 게임 지도처럼 펼치는 종이 지도(`components/map/paper-map.tsx`)를 **씬 렌더러와 분리된 독립 MapLibre GL 캔버스**로 띄운다(별도 WebGL 컨텍스트, [ADR 001](../adr/001-webgl-context-sharing.md)의 분리 원칙). 플레이 씬에서는 유저의 실제 GPS 위치를, 내 주변에서는 캐릭터 자리를 '나'로 표시한다. 컴포넌트는 씬이 시작되면(`playing` — 플레이 씬은 씬을 불러오는 동안, 펼치는 건 인트로가 시작된 뒤부터다) 마운트되지만, 지도는 처음 펼칠 때 지도 코드(`maplibre-gl`, 동적 `import`)를 받아 만든다. 만드는 동안 셰이더 링크·타일 업로드로 GPU가 잠깐씩 막히는데, 윈도 크롬은 CSS 합성도 같은 GPU 스레드에서 처리해 로더 뒤에서 미리 만들면 로더 스피너가 끊긴다 — 그래서 씬 로더는 지도를 기다리지 않는다. 만든 지도는 접혀 있는 동안 루트를 `visibility: hidden`으로 숨겨 둔다(레이아웃과 지도는 살아 있다). 지도는 Stylish 폰트가 온 뒤(`document.fonts.load`) 만들고 `localIdeographFontFamily: 'Stylish'`로 라벨의 한글을 그 폰트로 그린다. 지도 코드를 받지 못했거나(오프라인) WebGL을 쓸 수 없어 지도를 만들지 못하면 GPS 쪽지 대신 "지도를 그릴 수 없어요" 쪽지를 띄운다(씬은 영향받지 않는다).

MapLibre 워커는 페이지 번들과 따로 `public/maplibre/`에서 받는다(`setWorkerUrl('/maplibre/maplibre-gl-worker.mjs')`). 워커는 옆의 `maplibre-gl-shared.mjs`를 상대 경로로 불러오는데 번들러(Turbopack·webpack)는 이 파일을 함께 내보내지 않아, `scripts/copy-maplibre-worker.mjs`가 `npm run dev`·`npm run build` 전에(`predev`·`prebuild`) 두 파일을 `node_modules/maplibre-gl/dist`에서 복사한다. 복사본은 저장소에 두지 않는다(`.gitignore`).

| export | 내용 |
|---|---|
| `PaperMap`(default) | 지도 본체. props `open`·`onClose`·`gps`(GPS 추적기)·`track`(내 주변 — `MapTrack` ref, 없으면 GPS 위치가 '나')·`title`(제목 태그·표지 글씨)·`accent`('나'·정확도 원 색, 기본 `#8875ad`, 플레이 씬은 캐릭터 옷 색)·`onClosed`(다 접혀 배경까지 걷힌 순간 — 씬이 캐릭터 조작을 다시 켠다) |

### 생명주기·조작

- 지도는 씬마다 한 번, 처음 펼칠 때 만든다. 처음 중심은 캐릭터 자리(내 주변) 또는 GPS 위치(플레이 씬)이고, 둘 다 없으면 형식상 중심으로 만든다(위치를 받기 전에는 지도를 가려 두어 보이지 않는다). 줌은 16에서 시작한다(플레이 씬에서 흐린 위치면 아래 '가운데·줌'의 물러난 줌)
- 컴포넌트 언마운트·페이지 이동 시 마커를 지우고 `map.remove()`를, 종이 폭을 재는 `ResizeObserver`는 `disconnect()`를 반드시 호출한다
- 조작: 끌기·확대/축소는 되고, 회전·기울이기는 막는다(`dragRotate`·`pitchWithRotate`·`touchPitch` false, 핀치·Shift+방향키 회전도 끈다 — `touchZoomRotate.disableRotation()`·`keyboard.disableRotation()`). 북쪽이 위인 평면(메르카토르)이고 줌은 11~18.5다. 키보드 조작(방향키 이동·`+`/`-` 줌)은 지도에 포커스가 있을 때 MapLibre 기본 동작이다
- 크기: MapLibre가 컨테이너 크기(`clientWidth`·`clientHeight` — 레이아웃 크기라 펼치는 중의 CSS 변환과 무관하다)를 스스로 따라간다(`trackResize` 기본값). 다 접히면 애니메이션을 모두 걷어(`cancel`) 변환이 남지 않게 둔다

### 펼치기·접기

Web Animations API로 한 장면을 만든다. 모든 애니메이션이 같은 길이라 재생 방향을 거꾸로 돌려도 서로 맞는다. 접는 선은 늘 세로(옆으로 펼침)이고, 종이 폭(`offsetWidth` — 레이아웃 크기라 변환과 무관)에 따라 접는 횟수가 다르다.

| 종이 폭 | 접힘 | 펼치기 |
|---|---|---|
| 720px 이상 | 3단(두 번 접힘) | 3300ms — 표지가 잠깐 머문 뒤 왼쪽 날개가 먼저(장면의 28~52%) 펼쳐지고, 드러난 오른쪽 날개 겉면의 범례를 1초쯤 읽을 수 있게 멈췄다가 오른쪽 날개가(64~88%) 펼쳐진다 |
| 440px 이상 | 반(한 번 접힘) | 2000ms — 표지가 잠깐 머문 뒤 오른쪽 반이 오른쪽으로 펼쳐지고(40~82%), 접힌 묶음이 화면 가운데 오도록 종이를 폭의 25%만큼 오른쪽에 두었다가 날개가 펼쳐지는 만큼 함께 제자리로 미끄러진다 |
| 440px 미만 | 접지 않음 | 700ms — 가로로 조금 좁게 나타나 탁 펴지며 자리를 잡는다 |

- 공통: 배경(가장자리가 짙은 갈색 비네트)이 먼저 짙어지고, 종이 무대가 아래에서 기울어진 채 튀어 오르듯(overshoot) 자리를 잡는다(장면의 18%까지, 접지 않음은 72%까지). 종이 위 UI는 거의 다 펴진 뒤(장면의 88%, 접지 않음은 45%부터) 나타나고, 접는 선 자국은 다 펴지면 옅어진다
- `prefers-reduced-motion`이면 종이 폭과 상관없이 접지 않는 장면을 220ms로 짧게 돈다
- 접을 때는 같은 장면을 2배속으로 거꾸로 돌린다. 펼치는 중에 M·Esc를 누르면 그 자리에서 되돌아가고, 접는 중에 M을 누르면 다시 펼친다. 방향을 바꿀 때는 돌던 애니메이션의 재생 속도만 바꾸지 않고 지금 시각에서 장면을 새로 만들어 반대로 돌린다 — 속도만 바꾸면 크롬이 합성기 쪽을 처음 시각으로 다시 시작해 몇 프레임 동안 종이·배경이 사라지거나 접힌 모양이 번쩍인다. 장면 끝에 닿은 채 새로 돌리면 `play()`가 반대쪽 끝으로 되감으므로(auto-rewind) 끝에서 1ms 안쪽부터 돌린다. 배경 클릭은 다 펼쳤을 때만 접는다 — 펼치거나 접는 중의 클릭은 배경이 삼켜, 지도 버튼을 연달아 눌러도 펼치자마자 접히지 않는다. 펼친 채 창 크기가 달라져 면 수가 맞지 않게 되면, 접기 전에 지금 면 수로 장면을 다시 만들어 끝 장면부터 접는다
- 펼치기 시작할 때 '나'에게 맞추고(아래 '가운데·줌' 참고), 다 펼치면 포커스를 지도 대화상자(루트, `tabIndex={-1}`)에 준다 — × 버튼에 주면 키보드로 펼쳤을 때 버튼에 포커스 테두리가 그려진다(Tab을 누르면 버튼으로 간다). 다 접으면 애니메이션을 모두 걷고 루트를 숨긴 뒤, 펼치기 전 포커스가 있던 요소로 포커스를 돌려준다
- 날개: 3단은 왼쪽(종이 0~⅓)·오른쪽(⅔~1) 날개 둘, 반 접기는 오른쪽 반 날개 하나다. 살아 있는 지도 면(`.pm-live`)과 종이 그림자는 `clip-path`로 아직 펼쳐지지 않은 날개 자리를 잘라 두었다가, 날개가 내려앉는 순간 그 구간을 연다. 그 뒤 장면의 1~4% 동안 날개 안쪽 면을 흐리게 지워(크로스페이드) 밑의 진짜 지도로 넘기고, 다 지운 날개는 숨기지 않고 지도 면 바로 뒤(`translateZ(-1px)`)로 내린다(접을 때는 거꾸로 — 날개가 먼저 올라와 짙어진 뒤에 지도 면을 닫는다). 날개는 3D로 합성돼 지도보다 조금 흐리게 그려지므로 한 번에 바꾸면 선·글자가 한 픽셀 튀어 깜빡여 보이고, 지도 면을 여는 것(메인 스레드)과 날개를 내리는 것(합성기)이 한 프레임 어긋나면 그 자리가 비어 보인다. `visibility`로 숨겼다가 접을 때 다시 보이게 하면 크롬이 날개 속 음영을 한두 프레임 틀린 값으로 그린다. 날개 안쪽 면의 종이 결·그을림 층은 접는 선 쪽으로 종이 끝까지 늘여(면 밖은 잘린다) 펼친 종이의 결·그을림과 같은 자리에 온다 — 접는 선에 그을림이 없어 넘어가는 순간 띠가 사라지지 않는다. 다 펴진 면의 잘라내기는 `inset(0%)`가 아닌 `none`이다 — `inset`끼리만 오가면 크롬이 clip-path를 합성기에서 돌리며, 도중 시각에서 새로 만든 장면의 첫 프레임을 가끔 접힌 모양으로 그린다
- 안쪽 면: MapLibre `render` 이벤트 안에서(펼치거나 접는 중에만) 살아 있는 지도 캔버스의 그 구간을 `drawImage`로 옮겨 그린다 — 렌더 직후라 드로잉 버퍼가 살아 있어 `preserveDrawingBuffer`가 필요 없다. 펼치기·접기를 시작할 때 `triggerRepaint()`로 한 번 그리게 해, 다 펴지는 순간 진짜 지도로 이음매 없이 넘어간다
- 겉면: 맨 위에 접힌 날개가 표지(초록 띠·지도 아이콘·제목)이고, 3단의 뒤 날개는 범례(길·공원·물·건물 색 견본, 파선 테두리)다
- 음영: 면이 옆으로 설수록(90°) 어두워진다 — 겉면은 들리며 어두워지고, 안쪽 면은 내려앉으며 밝아진다
- 종이 질감: 접는 선 자국(⅓·⅔ 또는 ½), 종이 결(SVG 노이즈, `mix-blend-mode: multiply`), 가장자리 그을림(안쪽 그림자)

### GPS 표시

- 상태 쪽지(`gpsNote`): 가운데 위에 테이프 붙인 쪽지(−1° 기울임)로 아이콘·제목(Stylish)·안내·설정 순서(Pretendard)를 띄운다. 정확하면(`good`·`fair`) 아래쪽 작은 칩으로 내려간다. 아이콘은 찾음 = 초록 체크, 찾는 중 = 로더와 같은 스피너, 부정확 = 물음표 핀(까딱임), 쓸 수 없음 = 금 간 핀이다. 거부 등에는 쪽지에 "다시 시도"/"새로고침" 버튼이 붙는다. 세로 화면에서는 제목 태그 아래로 내려온다
- 도장: 쓸 수 없을 때("위치 꺼짐"·"https 필요"·"위치 미지원") 종이 가운데에 −12° 기울인 빨간 도장이 튀어 박히고(0.45초), 지도는 바랜 색(`grayscale(0.55) sepia(0.25)`)이 된다
- 음파: 찾는 중(`prompt`·`searching`·`unavailable`)이고 위치가 없으면 가운데에서 세 겹 원이 퍼진다(2.4초 주기, 0.8초 간격)
- 정확도 원: 반경(m)을 지금 줌에 맞춰 px로 바꿔 그리고, 줌이 달라질 때마다 다시 잰다(지름 30px 이하·6000px 이상이면 숨긴다). 흐리면(`coarse`·`approximate`) 굵은 파선 원 + 원 아래 "이 근처 어딘가 · ±N" 라벨, `fair`·`weak`는 숨쉬듯 커졌다 작아지고(2.4초), 멈춤(`stale`)은 점선으로 흐리게 그린다
- '나': 크림 원 + 가운데 `accent` 색 점 + 아래 "나" 라벨. 플레이 씬(GPS가 '나')에서는 흐린 위치면 파선 테두리에 물음표로, 멈춤·쓸 수 없음이면 흐리게 그린다. 내 주변은 캐릭터 자리 + 화면이 보는 방향 화살표이고, GPS가 잡은 자리는 따로 작은 색 점(툴팁 "GPS가 잡은 자리")과 정확도 원으로 보인다
- 찾았다: 펼쳐 둔 동안 찾는 중이거나 멈춰 있다가(`prompt`·`searching`·`unavailable`·`stale`) `good`이 되면 '나' 위에 "찾았다!" 말풍선이 한 번 떠올랐다 사라진다(1.6초)
- 위치 모름: 플레이 씬에서 위치가 없으면 지도 캔버스·컨트롤을 가리고 모눈(48px) 빈 종이에 상태 쪽지만 띄운다 — 엉뚱한 동네를 보여 주지 않는다
- `prefers-reduced-motion`이면 음파·숨쉬기·까딱임·말풍선·도장 애니메이션을 끈다(음파는 옅은 고리로 멈춰 둔다)

### 가운데·줌

- 펼칠 때 '나'에게 맞춘다(`jumpTo`). 줌은 지금 줌을 두되 15보다 작으면 15로 맞춘다
- 플레이 씬에서 흐린 위치(`coarse`·`approximate`)면 정확도 원 전체가 지도 짧은 변의 80%에 들어오는 줌으로 물러난다(줌 11~16)
- 플레이 씬에서 위치 없이 있다가 첫 위치가 오면(펼쳐 둔 채여도) 그리로 `jumpTo`한다
- 펼쳐 둔 동안 지도는 '나'를 따라 움직이지 않는다(마커만 움직인다). 끌어서 둘러본 뒤에는 "내 자리로" 버튼으로 돌아온다

### 마커

- '나'·정확도 원·GPS 점은 MapLibre DOM 마커(`Marker`)라 지도를 다시 그리지 않고 CSS로 움직인다. 마커 요소의 `position`은 MapLibre가 `absolute`로 두므로 덮어쓰지 않는다
- 내 주변은 펼쳐 둔 동안(펼치고 접는 중 포함) rAF로 매 프레임 `MapTrack`을 읽어 '나'를 옮긴다. GPS 표시는 추적기를 구독해 옮긴다(좌표는 React 상태에 두지 않는다)

## GPS 상태

브라우저 위치는 `lib/geo/gps.ts`(추적기·상태)와 `lib/geo/gps-messages.ts`(상태별 안내 문구·기기 판별)가 맡는다. 씬과 펼침 지도가 `watchPosition` 하나를 나눠 쓴다.

### 추적기 (`createGpsTracker`)

- `watchPosition`을 `enableHighAccuracy: true`, `maximumAge: 5000`, `timeout: 30000`(첫 위치에만 걸린다 — 크롬은 권한 창 시간도 세어 넉넉히 둔다)으로 건다. `start()`는 여러 번 불러도 한 번만 시작하고, `retry()`는 watch를 다시 건다(대기 화면·쪽지의 "다시 시도")
- 시작: 플레이 씬은 페이지를 열 때 `startIfGranted()`를 부른다 — 사이트 권한이 이미 허용돼 있으면(Permissions API `granted`) 권한 창 없이 바로 추적하고, 아니면 지도를 처음 펼칠 때(`PaperMap`이 펼칠 때마다 `start()`를 부른다) 권한을 묻는다. 내 주변은 `waitForStartFix`가 곧바로 `start()`한다(iOS에서 동작 권한을 물어야 하면 권한 단계의 '허용' 뒤)
- 권한: Permissions API(`navigator.permissions.query({ name: 'geolocation' })`)로 상태를 읽고 `change`를 구독한다. 크롬·파이어폭스는 거부→허용이면 자동으로 다시 찾고, 허용→거부면 watch를 끝낸다. 사파리는 이 이벤트를 보내지 않아 위치·오류로만 안다
- http(보안 연결 아님)면 부르기 전에 `insecure`로 둔다 — 불러도 권한 거부로만 와서 이유를 알 수 없다. 위치 기능이 없으면 `unsupported`다
- `watchStale` 옵션을 켜면 화면이 보이는 동안 20초 넘게 위치가 안 올 때도 `stale`로 본다. 내 주변은 휴대폰에서 켠다(걷는 동안 위치가 계속 와야 한다). PC와 플레이 씬은 끈다 — PC는 위치가 거의 바뀌지 않아 멈춤과 구별되지 않는다
- 버리는 위치: 앞 위치보다 시각이 이른 위치(순서가 어긋난 위치)와, 도착했을 때 30초보다 오래된 위치

| 상태 | 뜻 |
|---|---|
| `idle` | 아직 요청하지 않았다 |
| `unsupported` | 브라우저에 위치 기능이 없다 |
| `insecure` | https(또는 localhost)가 아니다 |
| `prompt` | 권한 창에 아직 답하지 않았다 |
| `searching` | 첫 위치를 찾는 중 |
| `unavailable` | 위치를 얻지 못했다는 오류(code 2)가 왔다 — watch는 계속 찾는다 |
| `denied` | 권한 거부(code 1) — 사이트 차단과 기기·OS 위치 꺼짐이 구별되지 않는다. watch가 끝난다 |
| `good` | ±20m 안 |
| `fair` | ±50m 안 |
| `weak` | ±150m 안 |
| `coarse` | ±1km 안 |
| `approximate` | 1km 넘음 |
| `stale` | 받다가 멈췄다 — 위치를 받은 뒤 오류(TIMEOUT·위치 없음)가 오거나, `watchStale`이면 화면이 보이는데 20초 넘게 위치가 안 온다. 마지막 위치는 남는다 |

- `slow`: 첫 위치 전에 8초가 지나거나(쓸 수 없는 상태 제외) TIMEOUT·위치 없음 오류가 오면 켜져, 찾는 중 안내가 "신호가 조금 늦네요"가 된다. 위치를 받거나 다시 시도하면 꺼진다
- 스냅샷은 `{ status, fix, slow }`이고 `fix`는 `{ lng, lat, accuracy, speed, timestamp }`다. `speed`는 GPS 칩이 도플러로 잰 수평 속도(m/s)라 위치가 튀어도 튀지 않고, 못 재면(와이파이·기지국 위치, 옛 iOS의 −1) `null`이다. 끊기거나 권한이 사라져도 마지막 `fix`를 남긴다
- 좌표는 React 상태로 다루지 않는다 — 구독자(`subscribe`)가 갱신마다 스냅샷을 받아 쓰고(씬의 걸음·지도 마커), 화면 문구·버튼은 `useGpsSnapshot`이 상태·정확도(반올림)·`slow`가 달라질 때만 다시 그린다

| 헬퍼 | 규칙 |
|---|---|
| `isWalkableFix` | ±50m 안 — 캐릭터를 걷게 하거나 옮겨도 되는 위치 |
| `isGpsBlocked` | `denied`·`insecure`·`unsupported` — 기다려도 소용없는 상태 |
| `queryGpsPermission` | 위치 권한을 묻지 않고 알아본다(Permissions API가 없으면 `null`) — 내 주변 iOS 권한 단계가 위치도 함께 물을지 정한다 |
| `waitForStartFix` | 시작 위치 기다리기 — ±50m 안이면 즉시, 그보다 흐리면 첫 위치부터 6초 다듬은 뒤 가장 나은 위치로. 위치를 하나도 못 받으면 끝나지 않는다 |
| `formatAccuracy` | `±Nm` / `±N.Nkm`(10km부터 `±Nkm`). 100m 안은 5m, 1km 안은 50m, 그 밖은 100m 단위로 반올림한다 |
| `accuracyStatus` | 정확도(m) → `good`~`approximate` |

- 브라우저 동작 근거(W3C 명세, Chromium·WebKit·Gecko 구현): watch의 timeout은 첫 위치에만 걸린다(그 뒤 멈춤은 오류가 오지 않아 직접 잰다). TIMEOUT·POSITION_UNAVAILABLE 뒤에도 watch는 계속 돌고 PERMISSION_DENIED만 watch를 끝낸다. http에서도 `navigator.geolocation`은 있고, 부르면 PERMISSION_DENIED가 온다. 기기·OS 위치 꺼짐도 대개 PERMISSION_DENIED다. 크롬은 권한 창을 기다리는 시간도 timeout에 센다. 화면이 숨겨지면 위치가 오지 않는다(돌아오면 다시 온다). 정확도 반경은 명세상 95%, 안드로이드 크롬은 68% 반경이다. iOS에서 '정확한 위치'를 끄면 1~20km, 안드로이드 대략 위치는 약 2km 오차로 온다

### 안내 문구 (`gps-messages.ts`)

해요체 문구를 지도 쪽지·내 주변 대기 화면·위쪽 알림이 함께 쓴다. `detectGpsEnv()`가 UA로 기기를 가린다 — iOS(iPadOS 포함 — 터치가 되는 Macintosh)·Android·Windows·Mac, 삼성 인터넷(`SamsungBrowser`), 앱 속 브라우저(카카오톡 `KAKAOTALK`·네이버 앱·인스타그램·페이스북·라인 표시).

| 함수 | 쓰는 곳 |
|---|---|
| `gpsNote(snapshot, env, { walking })` | 지도 쪽지·도장·버튼. `walking`(내 주변)이면 걸음 이야기를 한다 |
| `startWaitNote(snapshot, env)` | 내 주변 대기 화면 — 위치를 기다리는 동안(`idle`·찾는 중·흐린 위치·`good`·`fair`)은 `null`(로딩 첫 줄만 둔다), 해야 할 일이 있을 때(`prompt`·`denied`·`insecure`·`unsupported`·`unavailable`, `slow`한 `searching`)만 `gpsNote`와 같은 안내 |
| `walkNote(snapshot, { mobile })` | 내 주변 위쪽 알림(문구는 [내 주변(베타)](#내-주변베타-nearby) 절) |

| 상태 | `gpsNote` 제목 | 톤 | 도장 |
|---|---|---|---|
| `insecure` | 보안 연결에서만 위치를 쓸 수 있어요 | off | https 필요 |
| `unsupported` | 이 브라우저는 위치를 못 써요 | off | 위치 미지원 |
| `denied` | 위치 권한이 꺼져 있어요 | off | 위치 꺼짐 |
| `prompt` | 위치 권한을 허용해 주세요 | wait | |
| `searching` | 위치를 찾고 있어요… (`slow`면 "신호가 조금 늦네요") | wait | |
| `unavailable` | 신호가 조금 늦네요 | wait | |
| `good` | 위치를 찾았어요 · ±N | ok | |
| `fair` | 신호가 살짝 흔들려요 · ±N | ok | |
| `weak` | GPS 신호가 약해요 · ±N | warn | |
| `coarse` | 위치가 아직 흐릿해요 · ±N | warn | |
| `approximate` | 대략적인 위치만 받고 있어요 · ±N | warn | |
| `stale` | 걸음 신호가 잠시 멈췄어요 | warn | |

`idle`이면 쪽지가 없다.

- 설정이 필요한 안내(거부·대략적 위치)는 `steps`(설정 순서)로 준다 — 구글·애플 도움말처럼 한 단계에 한 가지 행동이고, 두 단계 이상이면 번호 목록이다. 메뉴 경로는 `[설정 › 개인정보 보호 및 보안 › 위치 서비스]`처럼 대괄호로 묶고, `GpsSteps`(`components/location/gps-steps.tsx`)가 경로를 진하게 › 로 이어 보인다. 경로 조각("개인 정보 및 보안")과 따옴표로 묶은 화면 이름(‘위치 서비스’)은 줄 중간에서 쪼개지지 않는다. 대기 화면은 로더의 `detail`, 지도 쪽지는 안내 아래에 붙는다
- 거부 안내는 사이트 권한과 기기 위치를 함께 적는다 — iOS: ① 설정 › 개인정보 보호 및 보안 › 위치 서비스를 켠다 ② 같은 화면의 Safari 웹사이트를 '앱을 사용하는 동안'으로 바꾼다 ③ 아래 '새로고침' / 안드로이드: ① 주소창 왼쪽 아이콘 › 권한에서 위치 허용 ② 휴대폰 '위치' / 삼성 인터넷: ① 메뉴 › 설정 › 사이트 및 다운로드 › 사이트 권한 › 위치에서 허용 ② 휴대폰 '위치' / Windows: ① 주소창 왼쪽 아이콘에서 위치 허용 ② Windows 설정 › 개인 정보 및 보안 › 위치의 '위치 서비스' / macOS: ① 주소창 왼쪽 아이콘에서 위치 허용 ② 시스템 설정 › 개인정보 보호 및 보안 › 위치 서비스에서 브라우저 켜기 / 앱 속 브라우저: 메뉴의 '다른 브라우저로 열기'
- 대략적 위치 안내: iOS는 'Safari 웹사이트'의 '정확한 위치', 안드로이드는 브라우저 앱 권한의 '정확한 위치 사용'을 켜라고 하고, PC는 GPS가 없어 크게 어긋날 수 있으니 휴대폰으로 열라고 한다. 앱 속 브라우저는 '다른 브라우저로 열기'
- 찾는 중·늦음 안내는 휴대폰(하늘이 보이는 곳·창가)과 PC(와이파이로 위치를 잡는다)를 나눠 적는다
- 거부 시 버튼: iOS(앱 속 브라우저 제외)는 "새로고침"(웹킷은 거부한 뒤 페이지를 다시 불러와야 권한이 반영된다), 그 밖은 "다시 시도"(탭 안에서 watch를 다시 걸어 안드로이드 크롬이 꺼진 기기 위치를 켜는 창을 띄울 수 있다)

### 지도 버튼의 "!" (`GpsBadge`)

위치를 못 잡았으면 지도 버튼 오른쪽 위 구석에 14px 빨강 "!"를 단다 — 위치가 아직 없거나(권한 창 대기·찾는 중·위치 없음) 쓸 수 없을 때(`denied`·`insecure`·`unsupported`)다. 위치를 잡았으면 정확도·멈춤과 상관없이 달지 않고(자세한 상태는 펼침 지도 쪽지가 알린다), 찾기 전(`idle`)에도 달지 않는다.

위치는 보안 연결(https 또는 localhost)에서만 된다 — 휴대폰에서 PC의 `http://<IP>:3000`으로 열면 "https 필요" 상태가 된다.

| `/play` | `app/play` | 플레이 씬 (`page.tsx`가 `features/play/play-scene.tsx`를 내보내고 viewport-fit=cover로 노치 화면까지 채운다) | 없음 (씬 소켓도 익명) |
| `/nearby` | `app/nearby` | 내 주변(베타) — 실제 길을 플레이 씬 화풍으로 깐 1단계, 반경 200m 사람이 실제 자리에 보인다 | 없음 (소켓도 익명) |
| `/asset-viewer` | `app/asset-viewer` | 에셋 미리보기(개발용, `page.tsx`가 `features/asset-viewer/asset-viewer.tsx`를 내보낸다) — ref-assets 캐릭터·소품을 지도 없이 띄워 크기·본·애니메이션·인스턴스·LOD 규격을 확인한다(자체 에셋 교체 시 규격 대조). 에셋을 다 받을 때까지 로더를 띄운다 — 문구는 플레이 씬처럼 내가 공원으로 소풍 가는 순서로 같은 간격마다 바뀌고("돗자리를 챙기는 중이에요" → "도시락을 싸는 중이에요" → "공원에 가는 중이에요"), 준비가 끝나면 "공원에 도착했어요!"를 띄운 뒤 글이 흐려지고 배경이 녹아 씬이 드러난다 | 없음 |
| `/api/health` | `app/api/health/route.ts` | Next 서버 자체 응답(`{ "status": "ok" }`) | 없음 |

`lib/routes.ts`의 `SCENE_ROUTES`(`/play`·`/nearby`·`/asset-viewer`)는 선택 페이지만 쓴다. 버튼의 이름·배지·기울기·아이콘은 `app/page.tsx`의 `PLACES`(경로별, `SCENE_ROUTES`와 타입으로 묶인다)에 있다. 선택 페이지는 서버 컴포넌트이고, 스타일은 페이지 안 `<style>`(`home-*` 클래스)에 있다. `next.config.ts`의 `redirects`는 `/village`·`/neighborhood`·`/preview`를 각각 `/play`·`/nearby`·`/asset-viewer`로 영구 이동(308)한다.

탭 제목은 루트 레이아웃의 `metadata.title`이 정한다 — `default`는 "Dumb Dumb"(선택 페이지), `template`은 "%s · Dumb Dumb"이다. 각 페이지는 선택 페이지 버튼 이름만 `title`로 적어 "플레이 · Dumb Dumb", "내 주변 · Dumb Dumb", "에셋 미리보기 · Dumb Dumb"이 된다(페이지 이름이 앞, 제품 이름이 뒤. 배지는 제목에 넣지 않는다). 제품 이름은 이 템플릿 한 곳에만 쓴다. `metadata`는 서버 컴포넌트에서만 내보낼 수 있어, 화면이 클라이언트 컴포넌트인 페이지는 `page.tsx`가 제목을 정하고 `features/<화면>/`의 화면 컴포넌트를 내보낸다.

로그인(`/login`)·본인인증(`/verify`)·맵(`/map`)·상점(`/store`) 화면과 이 화면들이 부를 BFF 라우트는 예정이다([로드맵](../roadmap.md)).

루트 레이아웃(`app/layout.tsx`)은 모든 페이지를 `PageTransition`으로 감싸, 링크 이동 때 로더를 화면 전체에 띄우고 로더 배경이 화면을 다 덮은 뒤(0.3초 — `LOADER_COVER_MS`)에 옮긴다 — 먼저 옮기면 반투명한 배경 너머로 도착한 페이지(미리 받아 둔 씬의 로더 등)가 비쳐, 스피너가 나왔다 가려지고 다시 뜨는 것처럼 보인다. 이동은 캡처 단계에서 클릭의 기본 동작을 막아 늦춘다(`Link`는 막힌 클릭이면 옮기지 않고 `onClick`은 그대로 불려, 플레이 버튼의 오디오 켜기는 누르는 순간 된다). 씬으로 갈 때의 안내는 도착한 씬 로더의 첫 문구와 같다 — `/play` "산책 가방을 챙기는 중이에요", `/nearby` "내 위치를 찾는 중이에요", `/asset-viewer` "돗자리를 챙기는 중이에요"(각 씬 로더의 첫 단계)이고, `/`는 "처음 화면으로 가는 중이에요", 그 밖(코드로 이동 등)은 "준비하는 중이에요"다. 나타날 때는 배경이 0.3초에 깔리고 스피너(92% 크기에서, 0.1초 뒤)·글(6px 아래에서, 0.16초 뒤)이 시차를 두고 떠오른다(Material 3 강조 감속 곡선). 6px은 글 줄만 옮긴다 — 로더 바닥까지 늘어난 글 영역을 통째로 내리면 바닥을 넘쳐, 떠오르는 동안 로더(`overflow-y: auto`) 안에 세로 스크롤바가 생겼다 사라지며 가운데 스피너가 옆으로 튄다. 떠 있는 동안에는 뒤에 붙은 씬 로더의 문구를 따라가다가(fade through — 씬 로더가 전환 로더 뒤에서 다음 단계로 넘어가도), 씬 로더가 이어받을 때 스피너 박자·문구가 같은 화면이라 그대로 걷는다 — 걷는 순간 다른 문구가 툭 드러나거나 두 문구가 겹쳐 보이지 않는다. 씬 로더에만 안내·버튼이 있으면(위치 권한 요청 등) 0.25초에 흐려 걷는다. 도착한 곳에 로더가 없거나 씬 로더가 벌써 걷히는 중이면(미리 받아 둔 빠른 로딩) 글이 먼저 빠지고 배경이 녹는다. 뒤로·앞으로 가기에는 전환 로더를 띄우지 않고, 링크를 누른 직후라 떠 있던 전환 로더도 바로 걷는다 — 도착한 곳은 라우터 캐시로 바로 뜨거나 제 로더를 띄운다.

로더끼리 넘겨받을 때(전환 로더 → 씬 로더, 씬 안의 상태별 로더)는 한 로더처럼 보인다. 스피너는 늘 화면 한가운데에 있고 글은 그 아래로만 늘어나며(스피너를 끈 상태도 자리는 비워 둔다), 글이 아래 절반에 다 들지 않는 낮은 화면(휴대폰 가로)에서만 스피너가 위로 비키고 그래도 넘치면 스크롤된다 — 위아래 끝에는 16px을 남긴다(`::before` min-height·`.ld-body::after`라 넉넉할 때는 가운데가 그대로다), 새로 붙는 스피너는 먼저 떠 있던 스피너(전환 로더의 것은 늘 붙어 있다)와 같은 박자로 돈다 — `LoaderSpinner`가 회전 애니메이션(`ld-spin`)의 `startTime`을 맞춘다. 회전끼리만 맞춘다 — 떠 있던 스피너가 나타나는 중이면 크기·투명도 전환이 회전보다 앞에 놓여(`getAnimations()` 순서), 첫 애니메이션에 맞추면 누른 때에 따라 박자가 어긋나 넘겨받는 순간 스피너가 한 프레임에 수십 도 튄다. 첫 줄은 문구가 바뀌면 앞 줄이 0.12초에 빠진 뒤 새 줄이 4px 아래에서 0.3초에 떠오른다(fade through — 글자만 갈아 끼우면 깜빡인 것처럼 보이고, 두 줄이 겹치면 이중으로 보인다). 앞 줄과 새 줄은 한 칸(grid)에 겹쳐, 짧은 줄로 바뀌어도 빠지는 줄이 꺾이지 않는다. 처음 뜬 줄은 움직이지 않는다 — 넘겨받을 때 같은 줄이 다시 떠오르면 깜빡여 보인다.

스피너는 고정된 호 하나(둥근 끝)가 1초에 한 바퀴 돈다(`SPIN_MS`). 회전(`transform`)만 움직이고 그 회전을 SVG가 아닌 감싼 HTML 요소(`.ld-spinner`)에 걸어 합성기에서 돌게 하므로, 로딩 중 무거운 작업이 메인 스레드를 막아도 끊기지 않는다 — 호 길이를 바꾸는 `stroke-dashoffset` 애니메이션이나 SVG 요소의 회전은 메인 스레드에서 다시 그려야 해 막힐 때마다 멈춘다. 로더는 아무리 빨리 끝나도 한 바퀴는 돌고 사라진다 — 전환 로더는 뜬 뒤 `SPIN_MS`가 지나야 걷고, 씬 로더(플레이·내 주변·에셋 미리보기)는 로더가 뜬 시각부터 `waitSpinTurn`으로 한 바퀴를 채운 뒤 걷는다. 씬 로더가 걷힐 때 글·스피너는 0.75초(cubic in-out)에 흐려지고, 배경도 0.5초부터 0.5초에 걸쳐 녹아 씬이 드러난다(`dissolve` — `LOADER_EXIT_MS` 1초 뒤에 걷는다. 녹는 동안 씬 위 HUD도 장면과 함께 드러나게 로더를 그 위에 둔다). 플레이 씬은 글이 흐려지기 시작할 때 인트로를 함께 시작해, 녹는 배경 뒤로 같은 크림색 덮개에서 소용돌이가 열리는 장면이 드러난다. 움직임을 줄이는 설정(`prefers-reduced-motion`)이면 떠오름·크기 변화 없이 페이드만 한다.

### 미들웨어 (`middleware.ts`)

- `matcher`가 빈 배열이라 미들웨어는 어떤 경로에도 실행되지 않는다. 인증 게이팅이 없어 모든 페이지가 공개다
- API 서버의 인가는 NestJS 전역 가드(`AccessTokenGuard`)와 PostgreSQL RLS가 담당한다

### `app/api/`

`app/api/`에는 Next 서버 자체 응답인 `app/api/health`만 있다. 화면이 붙을 때 `app/api/` Route Handler는 브라우저와 NestJS API 사이의 얇은 **BFF 프록시**로 두고(API 주소 비노출 + CORS 불필요, `Authorization` 헤더를 그대로 전달), **비즈니스 로직은 NestJS `apps/api`에만 둔다.** PG 결제 웹훅은 BFF를 거치지 않고 API 서버(`POST /billing/webhook`)로 직접 들어간다.

플레이 씬 소켓(`/room`)과 내 주변 소켓(`/proximity`)은 브라우저가 `NEXT_PUBLIC_WS_URL`로 직접 붙는다(`lib/realtime/relay.ts`). 이 주소가 localhost인데 페이지가 localhost가 아닌 곳에서 열렸으면(주소 없이 빌드한 배포본) 방문자 PC로 붙지 않도록 접속하지 않는다.

- 위치 좌표를 React state에 저장 금지 → 다른 사람 위치는 socket.io 채널에서, 내 GPS 위치는 추적기 구독(`subscribe`)에서 직접 소비한다. 화면 문구에 필요한 GPS 상태는 `useGpsSnapshot`으로 받는다
- 전역 상태 라이브러리(Redux, Zustand 등) 도입은 팀 합의 후 진행

## 컴포넌트 구조

### 디렉토리

```
components/
├── ui/           ← 공통 UI (button·card·toast), loader(로더 — 모든 로딩 화면)
├── layout/       ← page-transition(링크 이동 때 전체 화면 로더)
├── map/          ← paper-map·paper-map-style (플레이 씬·내 주변 펼침 지도와 그 스타일·무늬)
├── location/     ← gps-steps (위치 설정 경로 안내 — 펼침 지도 쪽지·내 주변 대기 화면)
├── hud/          ← talk-layer(만남 대화 — 플레이 씬), chat-input·direction-pad·joystick(렌더하는 곳 없음)
└── avatar/       ← avatar-card (아바타 미리보기 카드, 사용처 없음)
```

- `app/`에는 라우트 파일(`page.tsx`·`layout.tsx`·`route.ts`)만 둔다. 화면별 코드는 `features/<화면>/`(`play`·`nearby`·`asset-viewer`)에, 여러 화면이 같이 쓰는 UI는 `components/`에, 로직은 `lib/`(3D 엔진은 `lib/three/`)에 둔다. 화면끼리는 서로 가져다 쓰지 않는다 — 둘 이상이 쓰면 `components/`나 `lib/`로 옮긴다
- 파일·폴더 이름은 kebab-case(`paper-map.tsx`, `third-person.ts`)이고, 컴포넌트·타입 이름은 PascalCase(`PaperMap`)다. 같은 폴더 안은 `./파일`, 다른 폴더는 `@/…` 별칭으로 가져온다([ADR 009](../adr/009-web-structure-and-naming.md))

### 캔버스·DOM 이벤트 규칙

- 씬 HUD(플레이 씬 우상단 사운드·옷 색·지도·말 걸기 받기 버튼과 만남 대화 화면, 내 주변 지도 버튼·위쪽 알림)와 펼침 지도 오버레이는 캔버스 컨테이너의 형제 요소로 렌더해, HUD·지도 입력이 캔버스의 이동 입력에 닿지 않게 한다. 펼침 지도 루트(`z-index: 40`)는 보이는 동안 HUD와 만남 대화 화면 위를 덮는다
- 캔버스 위에 겹치되 입력을 받지 않는 표시 요소는 `pointer-events: none`이다(플레이 씬 HUD 버튼 안 아이콘, 지도 버튼의 "!" 등). 펼침 지도는 무대(`.pm-stage`)·날개·종이 위 UI 층을 `none`으로 두고, 다 펼쳤을 때(`data-phase='open'`)만 지도 면(`.pm-live`)과 버튼·쪽지(`.pm-btn`·`.pm-note`)가 입력을 받는다. 제목 태그·북쪽 화살표·도장·음파와 '나'·정확도 원 마커는 늘 `none`이다. 배경(`.pm-backdrop`)은 보이는 동안 클릭을 받되 다 펼쳤을 때만 지도를 접는다(펼치거나 접는 중의 클릭은 삼켜 아래 HUD 버튼에도 가지 않는다). 접혀 있을 때는 루트가 `visibility: hidden`이라 아무 입력도 받지 않는다
- 키보드 입력은 `window` 리스너로 받는다 — 3인칭 컨트롤러의 이동·점프(WASD·방향키·Space, 두 씬), 펼침 지도 M·Esc(`useMapHotkey`, 두 씬), 플레이 씬 Ctrl+M(소리)·E(말 걸기). 플레이 씬 오디오는 선택 페이지 '플레이'를 누를 때 켜 둔 컨텍스트를 이어 쓰거나 첫 페이지 `click`·캔버스 `pointerup`·`keydown`(Ctrl·Shift·Alt·Meta만 누른 것은 빼고)에서 만들고, 실제로 돌기 시작하면 음소거를 푼다(전체 볼륨 0.25, 숲·해변 환경음은 캐릭터 x 35~65m로 교차, 발소리는 수평 속도에 비례). 보이는데 멈춰 있는 오디오는 `window` 캡처 단계의 `pointerup`·`touchend`·`click`·`keydown`에서 다시 켠다
- 3D 캔버스에 `click`/`touchstart` 리스너 직접 바인딩 금지 (백엔드 컨벤션 프론트엔드 하네스)
- 캔버스의 `pointer*`·`mousedown`/`mouseup`(오른쪽 버튼 점프)·`contextmenu` 리스너는 3인칭 컨트롤러(`lib/three/third-person.ts`)만 등록하며, 이동·점프 조작 전용이다(예외: 플레이 씬의 첫 캔버스 `pointerup`은 오디오를 켠다). 오브젝트 선택·팝업 호출에는 쓰지 않는다
