# ADR 004: 원화 직행 결제 — 가상 화폐 없는 구조

**상태:** Accepted

## 결정

인앱 결제에서 보석·코인 등 중간 가상 화폐를 완전히 배제하고, **원화(KRW) 직행 확정 결제 구조**를 채택한다.

## 배경

많은 모바일 게임이 "보석 충전 → 보석으로 아이템 구매" 구조를 사용한다. 이 구조는 두 가지 법적·사업적 리스크를 내포한다.

1. **확률형 아이템 규제**: 보석으로 랜덤 아이템을 뽑는 구조는 게임법상 확률형 아이템으로 분류되어 확률 공시 의무, 사행성 심의 등 규제를 받음
2. **환금성 논란**: 보석(가상화폐)에 환금성이 생기면 사행성 판정 리스크

## 근거

| 항목 | 가상 화폐 충전 | 원화 직행 결제 |
|---|---|---|
| 사행성 규제 리스크 | 있음 (확률형 심의 대상 가능) | 없음 (100% 확정 구매) |
| 애플/구글 심사 | 불확실 (확률 표기 의무) | 통과 가능 (SaaS 정가 구매) |
| 유저 혼란 | 가격 체감 흐림 | 명확한 정가 |
| 개발 복잡도 | 충전·소모·환불 로직 별도 필요 | PG 웹훅 단순화 |

## 상품 구조

금액은 서버의 상품 카탈로그(`apps/api/src/billing/billing.service.ts` `PRODUCTS`)가 정한다. 클라이언트가 보낸 금액은 쓰지 않는다.

```
상품 1: 3D 아바타 외형권 (character, 2,200원, 100% 확정 발급)
  → 팔레트 조합 + 난수 시드로 외형 생성, appearance_hash UNIQUE로 전 세계 단 1종 보장
    (겹치면 다시 뽑는다. 외형 생성기는 생성형 AI로 교체할 예정)
  → 고유 시리얼 번호(OW-00000001 형식) 부여

상품 2: 가시거리 기능 라이선스 (정가)
  → 반경 100m 해제권(license_100m, 4,900원) / 반경 300m 해제권(license_300m, 9,900원)
  → 발급 시 보유 가시거리를 더 큰 값으로 상향
  → 아바타 외형과 완전히 독립된 별도 상품

번들: 아바타 10종 묶음 (bundle_10, 19,800원)
  → 주문 하나로 아바타 10개 발급
```

## 스토어 심사 대응 포지셔닝

"본 서비스는 유저가 3D 아바타 외형과 가시거리 기능 권한을 각각 정가에 100% 확정 구매하는 직관적인 SaaS/유틸리티 플랫폼이며, 외형 디자인 조합만 서버가 주문마다 유니크하게 생성해 주는 주문 제작형 구조임."

→ 확률형 아이템 표시 의무 및 사행성 규제 대상에서 제외됨.

## 결제 안전 규칙

- 웹훅은 raw body HMAC-SHA256 서명(`PG_WEBHOOK_SECRET`)을 검증한 뒤에만 처리한다
- 승인 반영은 주문 행을 `SELECT … FOR UPDATE`로 잠그고, 웹훅 금액이 주문 금액과 다르면 거절한다
- 같은 주문의 웹훅이 다시 와도 주문 행을 `FOR UPDATE`로 잠근 뒤 이미 `PAID`면 반영하지 않는다. 같은 승인번호가 다른 주문에 쓰이면 승인번호 UNIQUE 부분 인덱스(`orders_pg_approval_uniq`)가 막는다
- 발급 워커는 `FOR UPDATE SKIP LOCKED`로 결제 완료 주문을 집고, `(order_id, order_seq)` UNIQUE(`characters_order_item_uniq`)가 중복 발급을 막는다
- 외형이 겹쳐 다시 뽑을 때마다 `fulfill_attempts`가 쌓이고, 8회에 닿은 주문은 워커가 더 집지 않으므로 운영자가 확인한다
