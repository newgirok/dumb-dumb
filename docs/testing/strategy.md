## Phase별 완료 기준

각 Phase는 아래 검증 기준을 통과해야 완료로 처리한다.

| Phase | 완료 기준 | 검증 방법 | 상태 |
|---|---|---|---|
| Phase 1 | 이메일+비밀번호·OAuth 로그인 후 `/map` 진입 | 모바일·PC 수동 확인 + `npm run type-check` 오류 없음 | 진행 중 |
| Phase 2 | 플레이 씬 로딩·인트로 정상, 플레이 씬 익명 방 동기화·만남 대화, 맵 socket.io 섹터 위치 동기화 지연 500ms 이하, 속도 초과 패킷 서버 드롭, 내 주변 1단계(길 배치·이어 깔기·가까운 사람 동기화) | 브라우저 수동 확인 + 2탭 소켓 e2e 측정 | 진행 중 |
| Phase 3 | 결제 승인 후 아바타 발급 5초 이내, 동일 외형 중복 발급 차단, 지급 최종 실패 시 3초 이내 PG사 자동 취소 | 서명한 승인 웹훅 E2E → PG 결제창 연동 후 토스페이먼츠 테스트 환경 E2E | 진행 중 |
| Phase 4 | `ST_DWithin` 반경 쿼리 10ms 이하, pg_cron 광고 스케줄러 익일 실행, 광고주 테넌시 격리, 라이선스 지급 후 씬 뷰 디스턴스 확장, 섹터 채팅 말풍선 표시 | pgbench 벤치마크 + pg_cron 로그 + RLS 접근 테스트 + 2탭 수동 확인 | 예정 |
| Phase 5 | 동접 200명 p99 1초 이하, 에러율 0.1% 이하 | k6 부하 테스트 | 예정 |

## 통합 테스트 시나리오

### 시나리오 1 — 로그인 플로우 (Phase 1, 로그인·맵 화면을 만든 뒤)

1. 로그인 화면 접속 (`/login`)
2. 이메일+비밀번호 로그인 또는 카카오/구글 OAuth 버튼 클릭
3. 인증 완료 후 `/map` 자동 이동 확인 (OAuth 실패 시 `/login?error=`)
4. **합격 기준**: 인증 세션 수립 후 맵 정상 렌더링

### 시나리오 2 — 플레이 씬 (Phase 2)

1. 로그인 없이 선택 페이지(`/`)를 연다 — 제목 "Dumb Dumb" 아래 목적지 버튼 3개(플레이, 내 주변 + "베타" 배지, 에셋 미리보기 + "개발용" 배지)가 세로로 쌓여 있고 버튼에 아이콘과 이름만 있는지 확인한다. 제목·버튼 글씨가 기본 글꼴로 먼저 보였다가 바뀌지 않는다(폰트가 오면 제목은 바로 Luckiest Guy, 버튼 이름은 Stylish로 보인다). 캐시를 끄고 느린 휴대폰 망(지연 150ms·1.6Mbps)으로 열어도 버튼 이름·배지가 1초 안에 제 글꼴로 뜬다(쓰는 글자만 담은 4KB·2KB 폰트). 탭 제목은 선택 페이지 "Dumb Dumb", 플레이 "플레이 · Dumb Dumb", 내 주변 "내 주변 · Dumb Dumb", 에셋 미리보기 "에셋 미리보기 · Dumb Dumb"이다(링크로 이동해도 바로 바뀐다). 휴대폰 세로·가로·태블릿·데스크톱 크기에서 스크롤 없이 한 화면에 담기고, 기울인 버튼끼리 겹치지 않는다(568×320·844×390처럼 낮은 화면 포함). 처음 열 때와 씬에서 뒤로 가기로 돌아올 때 하늘은 그대로이고 제목, 버튼 3개가 차례로 살짝 떠오른다(움직임을 줄이는 설정이면 페이드만)
2. 플레이 버튼으로 `/play`에 들어간다 — 누르면 전환 로더가 배경부터 깔리고 스피너·안내가 시차를 두고 떠오른다. 전환 로더에서 씬 로더로 넘어가는 동안 스피너가 처음부터 다시 돌거나 둘로 겹쳐 보이지 않고, 안내("산책 가방 챙기는 중이에요")도 그대로이며 글이 잠깐 사라지거나 두 문구가 겹쳐 보이지 않는다. 로딩이 진행되면 문구가 "신발 끈 묶는 중이에요" → "목줄 채우는 중이에요" → "이제 나가요!"로 바뀌고(한 문구는 적어도 0.7초), 바뀔 때마다 앞 줄이 빠진 뒤 새 줄이 떠오른다(두 줄이 겹치거나 빠지는 줄이 꺾이지 않는다). 로더 첫 줄은 Stylish이고, 느린 망에서 처음 들어와도 기본 글꼴로 먼저 그려졌다 바뀌지 않는다. 에셋을 해석하느라 화면이 바쁜 동안에도, 로더가 걷히기 직전(셰이더 컴파일·그림자 굽기·첫 그리기)에도 스피너가 멈칫하지 않고 1초에 한 바퀴씩 돌며, 로딩이 금방 끝나도(캐시) 한 바퀴는 돈 뒤 사라진다. 내장 GPU 노트북의 크롬에서 트레이스로 잰 화면 프레임 간격(GPU 스레드의 `SkiaOutputSurfaceImplOnGpu::SwapBuffers` 사이)이 플레이 버튼을 누른 뒤 로더가 떠 있는 동안·흐려지는 동안·인트로와 그 뒤 8초까지 0.05초를 넘지 않는다(재방문 기준. 크롬 GPU 셰이더 캐시가 빈 첫 방문에는 펼침 지도의 셰이더 컴파일로 로더가 한 번 0.2초 안쪽으로 멈출 수 있다). 창이 다른 창에 가려지면 크롬이 그리기를 건너뛰므로 앞에 두거나 `--disable-features=CalculateNativeWinOcclusion`으로 띄운다. CDP 스크린캐스트는 프레임마다 GPU 일을 더 얹어 실제보다 크게 잰다. WebGL 호출을 세면 로더가 걷힌 뒤(인트로 8초·WASD로 15초 걷기)에는 씬·펼침 지도 모두 셰이더 링크·버퍼·텍스처·렌더 타깃을 새로 만드는 호출이 한 건도 없고 매 프레임 애니메이션 갱신(`bufferSubData`·`texSubImage2D`)만 있다 — 첫 방문과 Mapbox 응답을 늦춘 경우도 같다(지도가 늦으면 로더가 8초까지 기다린다). 로딩 중에 뒤로 가기를 누르면 로더가 다시 뜨지 않고 곧장 선택 페이지로 돌아간다. 다시 들어가 로딩 화면이 사라진 뒤 인트로 전환(4초)·카메라 돌리(6초) 동시 시작, 1.5초 뒤부터 조작 가능 확인
3. WASD·방향키·마우스 가상 조이스틱으로 이동, 스페이스로 점프(터치 기기는 드래그 이동·탭 점프)
4. 우상단에 사운드·옷 색·지도·말 걸기 받기 버튼 네 개가 위에서부터 있고 각 버튼에 이름(툴팁)이 뜨는지 확인한다. 선택 페이지에서 '플레이'를 누르고 들어오면 아무것도 누르지 않아도 인트로 뒤에 소리가 나고 사운드 버튼이 켜짐이다. 주소로 바로 들어오면 첫 탭·클릭·키에서 켜진다 — 휴대폰에서 끌어 걷기만 했을 때는 사운드 버튼이 꺼짐으로 남고(브라우저가 소리를 막은 상태, 아이폰 사파리), 그때 사운드 버튼을 누르면 꺼지지 않고 소리가 켜진다. Ctrl만 누른 것은 첫 입력으로 치지 않아 첫 입력이 Ctrl+M이면 소리가 켜진 채로 남는다. 소리가 나는 중에 창을 최소화하거나 다른 탭으로 가면 소리가 잦아들다 멈추고, 돌아오면 멈춘 자리에서 저절로 다시 커진다(음소거 중이면 조용한 채다). iOS 사파리에서 앱을 오갔다 돌아와 소리가 나지 않으면 화면을 한 번 누를 때 다시 난다
5. 단축키 — M으로 펼침 지도가 펼쳐지고(다 펼쳐져도 × 버튼에 포커스 테두리가 그려지지 않는다) M·Esc·×·배경 클릭으로 접힌다. Ctrl+M은 사운드 버튼과 같이 소리를 켜고 끄며 지도는 그대로 둔다. 한글 입력 상태에서도 같고, 키를 누르고 있어도 한 번만 반응한다. 지도가 화면에 있는 동안에는 키보드·조이스틱으로 캐릭터가 움직이지 않고, 접을 때는 다 접혀 배경이 걷힌 뒤에야 다시 움직인다(접히는 동안 W를 눌러도 서 있다). 지도 버튼을 연달아 빠르게 눌러도 펼치자마자 접히지 않고 끝까지 펼쳐진다
6. 창 폭 1280px·600px·390px에서 지도를 펼친다(3단·반 접기는 접힌 종이의 표지가 잠깐 머문 뒤 펼쳐진다) — 각각 3단(왼쪽 날개가 먼저 펼쳐지고, 드러난 오른쪽 날개 겉면의 범례(길·공원·물·건물)가 1초쯤 보인 뒤 오른쪽 날개가 펼쳐진다)·반 접기(오른쪽 반이 펼쳐지며 종이가 가운데로 함께 미끄러진다)·접지 않고 바로 펼친 모양으로 나타나고, 다 펴지는 순간 날개의 지도와 진짜 지도가 이음매 없이 이어진다. 접을 때는 거꾸로 더 빠르게 접히고, 펼치는 중에 M을 다시 누르면 그 자리에서 되돌아간다. 다 펼친 직후 접거나 펼치는 중·접는 중에 방향을 바꿔도 화면이 깜빡이지 않는다(지도·배경이 한 프레임 사라지거나, 접힌 모양이나 짙은 음영이 번쩍이지 않는다). 1280px에서 펼친 채 창을 600px로 줄인 뒤 접으면 반 접기 모양으로 접히고, 다시 펼친 지도가 종이 크기에 맞게 그려진다
7. GPS 상태별로 지도를 펼친다(재현 방법은 아래 "GPS 상태 재현" 표) — 위치 권한을 허용한 적 없으면 지도를 처음 펼칠 때 권한 창이 뜨고, 이미 허용한 사이트면 씬이 뜰 때부터 위치를 찾는다. 위치를 모르는 동안은 지도를 가리고 모눈 빈 종이에 상태 쪽지만 띄우며, 권한 창 대기·찾는 중·늦음·위치 없음이면 음파가 퍼진다. 거부·https 아님이면 도장("위치 꺼짐"·"https 필요")이 찍히고(지도가 보이면 흑백으로 바랜다), 거부 쪽지에는 기기별 설정 순서(번호 목록, 메뉴 경로는 › 로 잇고, 경로 조각과 ‘위치 서비스’ 같은 화면 이름 중간에서 줄이 바뀌지 않는다)와 "다시 시도"(iOS 사파리는 "새로고침")가 있다
8. 위치가 오면 지도가 '나'(옷 색 점)로 간다 — ±50m 안이면 아래 작은 칩으로, 그보다 흐리면 위쪽 쪽지로 알린다. 정확도 원은 ±20m를 넘고 ±150m 안이면 숨 쉬고, ±150m를 넘으면 점선 원 + "이 근처 어딘가 · ±N" 라벨과 물음표 '나'가 되며 펼칠 때 원 전체가 보이게 물러난다. 받다가 멈추면 점점선 원과 흐린 '나'가 된다. 찾는 중이다가 ±20m 안으로 잡히면 '나' 위에 "찾았다!"가 한 번 뜬다. 지도 버튼 구석에는 위치를 못 잡았을 때(권한 창 대기·찾는 중·거부·https 아님)만 빨강 "!"가 붙고, 위치를 잡으면 정확도와 상관없이 사라진다
9. **합격 기준**: 실시간 서버·API 서버 없이 씬·조작·펼침 지도 정상 동작, 지도 키(`NEXT_PUBLIC_MAPBOX_TOKEN`)가 없으면 지도 대신 "지도를 그릴 수 없어요" 쪽지만 뜨고 씬은 그대로 돈다

### 시나리오 2-1 — 플레이 씬 익명 멀티플레이 (Phase 2)

1. 실시간 서버(`apps/realtime`, DB 없이 뜬다)를 띄우고 `/play`를 두 곳에서 연다(브라우저 두 개, 또는 브라우저 하나 + `/room`에 붙는 socket.io 클라이언트)
2. 한쪽이 움직이고 점프하고 색을 바꾼다 → 다른 쪽에서 그 캐릭터가 0.35초에 걸쳐 나타나 같은 위치·방향·모션(달리기·공중·심심함)·색으로 따라오는지 확인
3. 한쪽 탭을 숨긴다(창 최소화·다른 탭) → 다른 쪽에서 사라지지 않고 그대로 보이며, 숨긴 쪽이 다시 보이면 그동안 움직인 다른 사람들이 바로 제자리에 보이는지 확인
4. 한 방에 20명이 차면 21번째는 다른 방에 들어가는지, 초당 10m를 넘는 이동이 막히는지 확인
5. **합격 기준**: 상대 갱신이 약 0.1초 지연 안에서 매끄럽게 이어지고, 정원을 채워도 프레임이 떨어지지 않으며, 실시간 서버를 끄면 혼자인 채로 씬이 정상 동작

### 시나리오 2-2 — 내 주변(베타) (Phase 2)

1. `/nearby`를 열면 위치를 받을 때까지 대기 화면(로더)에 머문다 — GPS 상태별로(재현 방법은 아래 "GPS 상태 재현" 표) 권한 창 대기 "위치 권한을 허용해 주세요", 찾는 중 "내 위치 찾는 중이에요"(스피너, 작은 줄 없음 — 전환 로더의 안내가 그대로 이어진다), 8초 넘게 못 받거나 위치 없음이면 "신호가 조금 늦네요", 거부면 스피너 없이 기기별 설정 순서(번호 목록) + "다시 시도"(iOS 사파리는 "새로고침"), https 아님이면 스피너 없이 "보안 연결에서만 위치를 쓸 수 있어요"가 뜨고, 얼마를 기다려도 스스로 넘어가지 않는다
2. 위치 권한을 주고 정확도별로 시작해 본다(Playwright는 `context.setGeolocation`의 `accuracy`) — ±50m 안(예: 10m)이면 곧바로 길을 깔고 시작하고, 그보다 흐리면(예: 100m·500m·3km) 버튼 없이 첫 줄("내 위치 찾는 중이에요") 그대로 6초 기다렸다가 그 사이 가장 나은 위치로 시작한다. 위치를 받은 뒤에는 문구가 "창밖 날씨 보는 중이에요" → "현관문 나서는 중이에요" → "엘리베이터 기다리는 중이에요" → "동네로 나가요!"로 바뀌고(빨리 끝나면 사이 줄을 건너뛰고 마지막 줄로 간다), 준비되면 글이 흐려진 뒤 배경이 녹아 동네와 지도 버튼이 함께 드러난다
3. PC에서 흐린 위치로 시작하면 위쪽 알림 없이 그 자리에서 걷는다. 이어서 ±50m 안 위치를 줘도 캐릭터가 옮겨지지 않는다(휴대폰은 그 위치를 걸음 목표로 삼아 걸어간다)
4. 도착한 자리의 길을 펼침 지도와 비교한다 — 카메라를 위로 올려 보면 길의 방향·교차로·막다른 골목이 펼침 지도와 같은 배치여야 한다(서울시청: 광장 타원·세종대로, 망원동: 기운 골목 격자)
5. PC에서 북쪽으로 4초 걸으면 약 15m 간다. 우상단 지도 버튼이나 M으로 지도를 펼치면 '나'가 캐릭터 자리에 화면이 보는 방향 화살표와 함께 있고, GPS가 잡은 자리는 작은 점과 정확도 원으로 따로 보인다. 방향을 틀고 다시 펼치면 화살표도 그쪽을 가리킨다. 지도가 펼쳐진 동안에는 키보드·마우스로 움직이지 않고, M·Esc로 접힌다
6. 휴대폰(User-Agent 아이폰)에서 ±50m 안 위치를 30m 옮기면 캐릭터가 걸어가 1.5m 앞에서 서고, 600m 옮기면 곧장 옮겨지며 그 둘레에 구역 9개가 깔린다. 정확도를 ±50m 밖(예: 100m)으로 두고 옮기면 따라 걷지 않고 위쪽에 "GPS 신호가 약해(±100m) 캐릭터를 잠깐 멈춰 뒀어요"가 뜬다. 지도를 펼쳐 둔 채 위치를 옮기면 캐릭터는 계속 걷고 '나'가 따라 움직이며, 지도는 다시 그리지 않는다(마커만 CSS로 움직인다)
7. PC에서 구역 경계(256m)를 넘을 때까지 걸으면 앞줄 3구역이 깔린다 — 구역은 워커가 그리므로 크롬 성능 기록에서 구역을 까는 동안 메인 스레드에 긴 작업(12ms 이상)이 없어야 한다. OffscreenCanvas를 지운 브라우저에서도 바닥이 깔린다(메인 스레드가 그린다)
8. 서울시청 옆 타일 경계(경도 126.97998°)를 지나는 왕복 도로에 서서 차선 텍스처를 읽는다 — 점선이 경계 양쪽으로 약 6m 박자로 이어지고, 칠한 구간 3.4~3.6m·틈 2.5~2.8m이며 경계에 틈 한가운데가 온다(두 박자가 겹치면 칠한 구간이 길어지고 틈이 짧아진다)
9. `/proximity`에 socket.io 봇을 붙여 캐릭터 북쪽 6m의 실제 좌표를 보내면 그 자리에 캐릭터가 나타나고, 끊으면 사라진다
10. **합격 기준**: 위치를 받을 때까지 대기 화면에서 기다리고(±50m 바로·그보다 흐리면 6초 뒤 그 근처에서 시작), PC는 흐린 위치로 시작해도 나중에 옮겨지지 않으며, 길 배치가 펼침 지도와 겹치고, 걸은 거리가 실제 거리와 같으며, 끝없이 걸어도 바닥이 이어진다

### 시나리오 2-3 — 반응형 구도 (Phase 2)

1. `/play`를 16:9 이상(예: 1920×1080)·정사각(1000×1000)·휴대폰 세로(390×844) 창으로 연다 — 16:9 이상은 원본 구도(세로 화각 45°·반경 5.836m·앙각 9.866°) 그대로이고, 좁을수록 화각이 넓어지고 카메라가 물러나 높이 올라가며 시선을 살짝 든다. 휴대폰 세로에서는 하늘·앞길·발밑이 대략 3분의 1씩 보인다
2. 창 크기를 끌어 조절하거나 기기를 돌리는 동안 구도가 한 프레임에 튀지 않고 부드럽게 따라간다
3. 각 비율에서 마우스 가상 조이스틱을 누른다 — 고정점이 캐릭터 발끝을 따라가(16:9에서는 화면 위 72.5%) 발끝 근처를 누르면 제자리에 서 있고, 둘레로 끌면 그쪽으로 걷는다. 최대 세기 거리는 짧은 변 × 0.23(90~200px)이라 작은 창에서도 창 안에서 최고 속도가 난다
4. `/nearby`에서도 같은 구도가 나오고, `/asset-viewer`는 세로로 긴 창에서 같은 기준으로 화각을 넓힌다(화면은 창 크기를 따라 채우고, 통계 패널은 좁은 화면에서 폭 안에서 줄바꿈된다)
5. **합격 기준**: 어느 비율에서나 캐릭터·앞길·하늘이 함께 보이고, 비율이 달라져도 구도가 튀지 않으며, 조이스틱 고정점이 발끝에 있다

### 시나리오 2-4 — 플레이 씬 만남 대화 (Phase 2)

1. 실시간 서버를 띄우고 `/play`를 두 곳에서 연다(브라우저 두 개, 또는 브라우저 하나 + `/room`에 붙어 말을 걸고 답하는 socket.io 봇). 뒤에 가린 탭·창은 프레임이 멈춰 머리 위 표시가 갱신되지 않으므로, 확인하는 쪽을 앞에 둔다
2. 다른 캐릭터가 4m 안에 들어오면 기다리지 않고 바로 머리 위에 손가락 표시가 살짝 오르내리며 뜬다(손가락 기기는 E 없이). 4m 안에 둘이 있으면 둘 다 뜨고 E는 더 가까운 사람 표시에만 붙는다. 그보다 멀거나 화면 밖이면 뜨지 않는다. 4.2m 밖으로 멀어지면 표시가 뚝 끊기지 않고 그 자리에서 작아지며 옅어지고(0.18초), 다시 4m 안에 들어오면 곧바로 다시 뜬다. 상대 캐릭터나 표시(보이는 칸 바깥 9px까지)를 짧게 클릭·탭하면 그 사람 둘레에 원형 메뉴가 펼쳐지고(캐릭터를 누른 것으로는 이동·점프하지 않는다, PC는 캐릭터 위에서 커서가 손가락 모양), 4m 밖이면 12시의 말 걸기 아이콘이 옅은 색으로 꺼져 있다가 다가가면 켜진다. 꺼진 아이콘을 누르거나 E를 누르면 걸리지 않고 아이콘이 흔들리며 "조금 더 가까이 가면 말을 걸 수 있어요"가 뜬다. 빈 곳을 누르거나 Esc를 누르면 메뉴가 닫힌다. 4.2m 밖으로 가면 표시가 사라지고 아이콘이 꺼지며, "기다리는 중…"일 때 멀어지면 요청도 거둬져 상대 카드가 닫힌다
3. E(새로고침 직후 첫 입력이어도)나 원형 메뉴의 켜진 말 걸기 아이콘을 누르면 상대 머리 위가 "기다리는 중…"으로 바뀌고, 상대 화면 위쪽(639px 이하는 아래)에 "옆에서 말을 걸었어요" 카드가 15초 막대와 함께 뜨며, 말을 건 사람 머리 위에 빨강 "!"가 뜬다
4. 좋아요 → 두 화면에 대화 창이 열린다(데스크톱·가로 화면은 왼쪽 아래, 639px 이하 세로 화면은 아래를 가득). 320×568·568×320·844×390·1280×800에서 빠른 문구가 한 줄로 놓이고 넘치는 쪽 끝이 흐려지며, 손가락·트랙패드·마우스 휠로 옆으로 넘겨 4개 모두 누를 수 있고, 입력칸·보내기가 창 안에 들며, 대화 창·요청 카드·위쪽 한 줄이 우상단 HUD 버튼과 겹치지 않는다. 입력칸에 쓰는 동안 W를 눌러도 캐릭터가 서 있고 E는 글자로 들어간다. 한글을 조합하다 Enter를 눌러도 마지막 글자가 두 번 가지 않는다. 보낸 글은 양쪽 대화 창과 두 사람 머리 위 말풍선(7초)에 보이고, 화면 가장자리에 선 사람의 말풍선은 안쪽으로 당겨져 잘리지 않는다. 빠른 문구도 바로 보내진다. 대화가 길어져 위로 올려 읽는 중에 상대 글이 오면 읽던 자리가 그대로이고 로그 아래에 "새 메시지 N개" 버튼이 떠 개수가 늘며, 누르면 맨 아래로 간다. 위를 읽다가 내가 보내면 바로 맨 아래로 간다. "www.example.com"처럼 링크가 든 글은 "링크는 보낼 수 없어요"가 뜨고 쓰던 글이 남는다
5. 끝 — ×를 누른 쪽은 "대화를 마쳤어요", 상대는 "상대가 대화를 마쳤어요". 한쪽이 10m 넘게 멀어지면 제목이 "멀어지고 있어요"로 바뀌고 10초 뒤 "멀어져서 대화가 끝났어요". 상대 탭을 닫으면 "상대가 떠났어요", 3분 동안 글이 없으면 "한동안 말이 없어 대화를 마쳤어요"
6. 다음에 → 건 쪽에 "지금은 바쁜가 봐요"가 뜨고 5분 동안 그 사람 위의 손가락 표시가 흐리고 움직이지 않는다(E도 붙지 않는다, 서버도 다시 건 요청을 곧바로 거절한다). 그 사람을 눌러 메뉴를 열면 말 걸기 아이콘을 덮은 어두운 덮개가 12시부터 시계 방향으로 걷히고, 누르거나 E를 누르면 흔들리며 "잠시 뒤에 다시 말을 걸 수 있어요"가 뜬다. 알림이 떴다 사라지거나 메뉴를 닫았다 열어도 덮개는 실제 남은 시간대로 걷힌다. 15초 동안 답하지 않거나 대화 중인 사람에게 걸어도 같은 한 줄이다
7. 우상단 말 걸기 받기 버튼을 끄면(말풍선에 사선) 오는 요청이 카드 없이 거절되고, 새로고침해도 꺼진 채다
8. **합격 기준**: 두 사람이 서로 받아들일 때만 대화가 열리고, 글이 두 사람에게만 바로 보이며, 끝나는 네 경우가 모두 제때 끝나고, 대화 글이 서버 어디에도 남지 않는다

### GPS 상태 재현 (시나리오 2·2-2)

| 상태 | 재현 방법 |
|---|---|
| 정확도별 위치(±20m·±50m·±150m·±1km·1km 넘음) | Playwright `context.grantPermissions(['geolocation'])` 뒤 `context.setGeolocation({ latitude, longitude, accuracy })` — `accuracy`(m)로 단계를 고른다. 브라우저에서는 개발자 도구 Sensors의 위치 덮어쓰기 |
| 권한 창 대기 | 사이트 위치 권한을 기본값(묻기)으로 둔 브라우저로 연다 |
| 찾는 중·늦음 | 답하지 않는 `navigator.geolocation` 대역(mock) — 8초가 지나면 늦음 |
| 위치 없음 | 대역이 POSITION_UNAVAILABLE(code 2)로 답한다 |
| 거부 | 사이트 위치 권한을 차단하거나, 대역이 PERMISSION_DENIED(code 1)로 답한다 |
| https 아님 | localhost가 아닌 `http://<LAN IP>:3000`으로 연다(휴대폰에서 PC 개발 서버를 열 때와 같다) |
| 받다가 멈춤 | 대역이 위치를 준 뒤 오류(code 2·3)로 답한다. 내 주변을 휴대폰(모바일 UA)으로 열었다면 대역이 위치를 한 번 준 뒤 20초 넘게 보내지 않는다 |

3. `orders.status = 'PAID'` 전환 확인

5. 동일 승인번호 웹훅 재전송 → DB 제약으로 중복 발급 없음 확인

4. 상점 화면을 만든 뒤에는 상점 가시거리 표시가 현재 반경과 일치하는지 확인
