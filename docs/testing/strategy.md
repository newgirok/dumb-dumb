## 단위 테스트 대상

저장소에는 아직 테스트 러너가 설정되어 있지 않다. 아래는 테스트 러너를 붙일 때 우선 작성할 대상이다.

### 클라이언트 로직 — `shared/`·`lib/`·`app/village/`·`app/neighborhood/`

| 파일 | 테스트 케이스 |

| `app/village/thirdPerson.ts` | 전진 가속·정지 미끄러짐(최고 약 3.75m/s, 정지 약 0.7m) / 벽을 따라 미끄러짐·높은 턱 차단 / 스페이스를 누르고 있어도 점프 1회 / `setEnabled(false)` 동안 키보드·마우스 입력 무시(눌려 있던 키·드래그는 풀림)·`steer`(휴대폰 GPS) 입력은 계속 / 16:9 이상에서 카메라 앙각 9.866° 유지(인트로 줌 포함) / `framingFor` — 16:9 이상은 세로 화각 45°·반경 ×1, 9:19.5에서 화각 66°·반경 ×1.3·앙각 +8°·시선 들기 5°, 그 사이는 smoothstep / 비율이 달라지면 화각·극각·시선각·반경이 프레임당 0.05로 따라감(한 프레임에 튀지 않음) / 마우스 조이스틱 고정점 16:9에서 화면 위 72.5%·구도에 맞춰 발끝을 따라감, 최대 세기 거리 짧은 변 × 0.23(90~200px) / 벽 충돌 시 카메라 반경 축소(최소 캡슐 반경 × 1.25) |

| `lib/realtime/scene.ts` | 바뀐 필드만 전송(위치는 월드별 소수 자리 — 마을 씬(`island`) 2·2·2, 내 주변 7·7·2 — 방향은 둘째 자리 비교) / 5분 무변화면 끊고 변화 시 재접속 / 탭 숨김 시 끊기·보이면 재접속 / 서버가 끊으면 30초 뒤 재시도 / 소켓 주소가 localhost인데 페이지가 localhost가 아니면 접속 안 함 |
| `lib/geo/gps.ts` | 정확도 단계 경계(±20·50·150·1000m) / 순서가 거꾸로 왔거나 도착 때 30초보다 오래된 위치 버림 / http면 watch를 부르기 전에 `insecure` / 거부(code 1)면 watch를 끝내고 `denied`, 위치 없음(code 2)·TIMEOUT 뒤에는 계속 찾음(위치를 받은 뒤면 `stale`) / 8초 안에 첫 위치가 없으면 `slow` / 권한이 거부에서 허용이 되면 다시 찾음 / `waitForStartFix` — ±50m 안은 바로, ±150m 안은 6초 동안 가장 나은 위치, 그보다 흐리면 `takeBest()`를 부를 때만 끝남 / `useGpsSnapshot`은 상태·반올림한 정확도·slow가 달라질 때만 다시 그림 |
| `lib/geo/gpsMessages.ts` | 기기 판별(터치 되는 Mac은 iPadOS, 삼성 인터넷, 카카오톡 등 앱 속 브라우저) / 거부 버튼은 iOS(앱 속 브라우저 제외) `reload`, 그 밖 `retry` / `startWaitNote` 상태별 문구 / `walkNote` — 쓸 수 없는 상태는 PC·휴대폰 모두, 흐린 시작은 ±150m를 경계로 두 문구, 멈춤·흐림은 휴대폰만 |

대시보드 월드·음성·로그인 화면의 클라이언트 로직(전송 전 속도 사전 검증, 15m 도로 스냅, 50m마다 450m 밖 피어 정리, 액세스 토큰 갱신 합치기, 40m 안 상위 8명 음성 구독, 30~40m 음량 감쇠)은 그 화면을 만들 때 테스트 대상에 넣는다.

## 통합 테스트 시나리오

### 시나리오 1 — 로그인 플로우 (Phase 1, 로그인·대시보드 화면을 만든 뒤)

1. 로그인 화면 접속 (`/login`)
2. 이메일+비밀번호 로그인 또는 카카오/구글 OAuth 버튼 클릭
3. 인증 완료 후 `/dashboard` 자동 이동 확인 (OAuth 실패 시 `/login?error=`)
4. **합격 기준**: 인증 세션 수립 후 대시보드 월드 정상 렌더링

### 시나리오 2 — 마을 씬 (Phase 2)

1. 로그인 없이 선택 페이지(`/`)를 연다 — 제목 "어슬렁" 아래 목적지 버튼 3개(마을, 내 주변 + "베타" 배지, 에셋 미리보기 + "개발용" 배지)가 세로로 쌓여 있고 버튼에 아이콘과 이름만 있는지 확인한다. 제목·버튼 글씨가 기본 글꼴로 먼저 보였다가 바뀌지 않는다(폰트가 오면 바로 Stylish로 보인다). 탭 제목은 선택 페이지 "어슬렁", 마을 "마을 · 어슬렁", 내 주변 "내 주변 · 어슬렁", 에셋 미리보기 "에셋 미리보기 · 어슬렁"이다(링크로 이동해도 바로 바뀐다). 휴대폰 세로·가로·태블릿·데스크톱 크기에서 스크롤 없이 한 화면에 담긴다
2. 마을 버튼으로 `/village`에 들어간다 — 전환 로더에서 씬 로더로 넘어가는 동안 스피너가 처음부터 다시 돌거나 둘로 겹쳐 보이지 않고, 안내("마을을 불러오고 있어요. 잠시만 기다려 주세요.")도 그대로다. 로딩 중에 뒤로 가기를 누르면 로더가 다시 뜨지 않고 곧장 선택 페이지로 돌아간다. 다시 들어가 로딩 화면이 사라진 뒤 인트로 전환(4초)·카메라 돌리(6초) 동시 시작, 1.5초 뒤부터 조작 가능 확인
3. WASD·방향키·마우스 가상 조이스틱으로 이동, 스페이스로 점프(터치 기기는 드래그 이동·탭 점프)
4. 우상단에 사운드·옷 색·지도 버튼 세 개가 위에서부터 있고 각 버튼에 이름(툴팁)이 뜨는지 확인한다. 첫 입력 때 소리가 켜지고, Ctrl만 누른 것은 첫 입력으로 치지 않아 첫 입력이 Ctrl+M이면 소리가 켜진 채로 남는다
5. 단축키 — M으로 펼침 지도가 펼쳐지고(다 펼쳐져도 × 버튼에 포커스 테두리가 그려지지 않는다) M·Esc·×·배경 클릭으로 접힌다. Ctrl+M은 사운드 버튼과 같이 소리를 켜고 끄며 지도는 그대로 둔다. 한글 입력 상태에서도 같고, 키를 누르고 있어도 한 번만 반응한다. 지도가 펼쳐진 동안에는 키보드·조이스틱으로 캐릭터가 움직이지 않고, 접으면 다시 움직인다
6. 창 폭 1280px·600px·390px에서 지도를 펼친다(3단·반 접기는 접힌 종이의 표지가 잠깐 머문 뒤 펼쳐진다) — 각각 3단(왼쪽 날개가 먼저, 오른쪽 날개가 겹쳐 펼쳐진다)·반 접기(오른쪽 반이 펼쳐지며 종이가 가운데로 함께 미끄러진다)·접지 않고 바로 펼친 모양으로 나타나고, 다 펴지는 순간 날개의 지도와 진짜 지도가 이음매 없이 이어진다. 접을 때는 거꾸로 더 빠르게 접히고, 펼치는 중에 다시 누르면 그 자리에서 되돌아간다. 1280px에서 펼친 채 창을 600px로 줄인 뒤 접으면 반 접기 모양으로 접히고, 다시 펼친 지도가 종이 크기에 맞게 그려진다
7. GPS 상태별로 지도를 펼친다(재현 방법은 아래 "GPS 상태 재현" 표) — 위치 권한을 허용한 적 없으면 지도를 처음 펼칠 때 권한 창이 뜨고, 이미 허용한 사이트면 씬이 뜰 때부터 위치를 찾는다. 위치를 모르는 동안은 지도를 가리고 모눈 빈 종이에 상태 쪽지만 띄우며, 권한 창 대기·찾는 중·늦음·위치 없음이면 음파가 퍼진다. 거부·https 아님이면 도장("위치 꺼짐"·"https 필요")이 찍히고(지도가 보이면 흑백으로 바랜다), 거부 쪽지에는 기기별 설정 순서(번호 목록, 메뉴 경로는 › 로 잇고, 경로 조각과 ‘위치 서비스’ 같은 화면 이름 중간에서 줄이 바뀌지 않는다)와 "다시 시도"(iOS 사파리는 "새로고침")가 있다
8. 위치가 오면 지도가 '나'(옷 색 점)로 간다 — ±50m 안이면 아래 작은 칩으로, 그보다 흐리면 위쪽 쪽지로 알린다. 정확도 원은 ±20m를 넘고 ±150m 안이면 숨 쉬고, ±150m를 넘으면 점선 원 + "이 근처 어딘가 · ±N" 라벨과 물음표 '나'가 되며 펼칠 때 원 전체가 보이게 물러난다. 받다가 멈추면 점점선 원과 흐린 '나'가 된다. 찾는 중이다가 ±20m 안으로 잡히면 '나' 위에 "찾았다!"가 한 번 뜬다. 지도 버튼 구석에는 위치를 못 잡았을 때(권한 창 대기·찾는 중·거부·https 아님)만 빨강 "!"가 붙고, 위치를 잡으면 정확도와 상관없이 사라진다
9. **합격 기준**: API·소켓 연결 없이 씬·조작·펼침 지도 정상 동작, 지도 키(`NEXT_PUBLIC_MAPBOX_TOKEN`)가 없으면 지도 대신 "지도를 그릴 수 없어요" 쪽지만 뜨고 씬은 그대로 돈다

### 시나리오 2-1 — 마을 씬 익명 멀티플레이 (Phase 2)

1. API 서버를 띄우고 `/village`를 두 곳에서 연다(브라우저 두 개, 또는 브라우저 하나 + `/scene`에 붙는 socket.io 클라이언트)
2. 한쪽이 움직이고 점프하고 색을 바꾼다 → 다른 쪽에서 그 아이가 0.35초에 걸쳐 나타나 같은 위치·방향·모션(달리기·공중·심심함)·색으로 따라오는지 확인
3. 한쪽 탭을 숨긴다 → 다른 쪽에서 0.25초에 걸쳐 사라지고, 다시 보이면 돌아오는지 확인
4. 한 방에 20명이 차면 21번째는 다른 방에 들어가는지, 초당 10m를 넘는 이동이 막히는지 확인
5. **합격 기준**: 상대 갱신이 약 0.1초 지연 안에서 매끄럽게 이어지고, 정원을 채워도 프레임이 떨어지지 않으며, API를 끄면 혼자인 채로 씬이 정상 동작

### 시나리오 2-2 — 내 주변(베타) (Phase 2)

1. `/neighborhood`를 열면 위치를 받을 때까지 대기 화면(로더)에 머문다 — GPS 상태별로(재현 방법은 아래 "GPS 상태 재현" 표) 권한 창 대기 "위치 권한을 허용해 주세요", 찾는 중 "위치를 찾고 있어요…"(스피너), 8초 넘게 못 받거나 위치 없음이면 "신호가 조금 늦네요", 거부면 스피너 없이 기기별 설정 순서(번호 목록) + "다시 시도"(iOS 사파리는 "새로고침"), https 아님이면 스피너 없이 "보안 연결에서만 위치를 쓸 수 있어요"가 뜨고, 얼마를 기다려도 스스로 넘어가지 않는다
2. 위치 권한을 주고 정확도별로 시작해 본다(Playwright는 `context.setGeolocation`의 `accuracy`) — ±50m 안(예: 10m)이면 곧바로 길을 깔고 시작하고, ±150m 안(예: 100m)이면 "위치를 또렷하게 맞추는 중이에요"로 6초 기다렸다가 그 사이 가장 나은 위치로 시작한다. 그보다 흐리면(예: 500m) 계속 기다리며 "이 근처에서 시작하기 (±500m)" 버튼이 뜨고, 누를 때만 그 위치로 시작한다
3. 흐린 위치로 시작하면 위쪽에 알림 한 줄("위치가 ±100m 흔들려 근처에서 시작했어요 · 또렷해지면 제자리로 옮겨 드려요" 또는 "대략적인 위치(±500m)에서 시작했어요 · 정확해지면 옮겨 드려요")과 "지도 보기" 버튼이 뜬다(좁은 화면에서는 버튼이 글 아래 줄로 내려가고, 지도가 펼쳐져 있으면 숨는다). 이어서 ±50m 안 위치를 주면 캐릭터가 그 자리로 한 번 옮겨지고 알림이 사라진다(PC·휴대폰 모두)
4. 도착한 자리의 길을 펼침 지도와 비교한다 — 카메라를 위로 올려 보면 길의 방향·교차로·막다른 골목이 펼침 지도와 같은 배치여야 한다(서울시청: 광장 타원·세종대로, 망원동: 기운 골목 격자)
5. PC에서 북쪽으로 4초 걸으면 약 15m 간다. 우상단 지도 버튼이나 M으로 지도를 펼치면 '나'가 캐릭터 자리에 화면이 보는 방향 화살표와 함께 있고, GPS가 잡은 자리는 작은 점과 정확도 원으로 따로 보인다. 방향을 틀고 다시 펼치면 화살표도 그쪽을 가리킨다. 지도가 펼쳐진 동안에는 키보드·마우스로 움직이지 않고, M·Esc로 접힌다
6. 휴대폰(User-Agent 아이폰)에서 ±50m 안 위치를 30m 옮기면 캐릭터가 걸어가 1.5m 앞에서 서고, 600m 옮기면 곧장 옮겨지며 그 둘레에 구역 9개가 깔린다. 정확도를 ±50m 밖(예: 100m)으로 두고 옮기면 따라 걷지 않고 위쪽에 "GPS 신호가 약해(±100m) 캐릭터를 잠깐 멈춰 뒀어요"가 뜬다. 지도를 펼쳐 둔 채 위치를 옮기면 캐릭터는 계속 걷고 '나'가 따라 움직이며, 지도는 다시 그리지 않는다(마커만 CSS로 움직인다)
7. PC에서 구역 경계(256m)를 넘을 때까지 걸으면 앞줄 3구역이 깔린다 — 구역은 워커가 그리므로 크롬 성능 기록에서 구역을 까는 동안 메인 스레드에 긴 작업(12ms 이상)이 없어야 한다. OffscreenCanvas를 지운 브라우저에서도 바닥이 깔린다(메인 스레드가 그린다)
8. 서울시청 옆 타일 경계(경도 126.97998°)를 지나는 왕복 도로에 서서 차선 텍스처를 읽는다 — 점선이 경계 양쪽으로 약 6m 박자로 이어지고, 칠한 구간 3.4~3.6m·틈 2.5~2.8m이며 경계에 틈 한가운데가 온다(두 박자가 겹치면 칠한 구간이 길어지고 틈이 짧아진다)
9. `/neighborhood`에 socket.io 봇을 붙여 캐릭터 북쪽 6m의 실제 좌표를 보내면 그 자리에 아이가 나타나고, 끊으면 사라진다
10. **합격 기준**: 위치를 받을 때까지 대기 화면에서 기다리고(±50m 바로·±150m 6초 뒤·그보다 흐리면 고를 때만 시작), 흐린 위치로 시작하면 첫 ±50m 위치에서 제자리로 옮겨지며, 길 배치가 펼침 지도와 겹치고, 걸은 거리가 실제 거리와 같으며, 끝없이 걸어도 바닥이 이어진다

### 시나리오 2-3 — 반응형 구도 (Phase 2)

1. `/village`를 16:9 이상(예: 1920×1080)·정사각(1000×1000)·휴대폰 세로(390×844) 창으로 연다 — 16:9 이상은 원본 구도(세로 화각 45°·반경 5.836m·앙각 9.866°) 그대로이고, 좁을수록 화각이 넓어지고 카메라가 물러나 높이 올라가며 시선을 살짝 든다. 휴대폰 세로에서는 하늘·앞길·발밑이 대략 3분의 1씩 보인다
2. 창 크기를 끌어 조절하거나 기기를 돌리는 동안 구도가 한 프레임에 튀지 않고 부드럽게 따라간다
3. 각 비율에서 마우스 가상 조이스틱을 누른다 — 고정점이 캐릭터 발끝을 따라가(16:9에서는 화면 위 72.5%) 발끝 근처를 누르면 제자리에 서 있고, 둘레로 끌면 그쪽으로 걷는다. 최대 세기 거리는 짧은 변 × 0.23(90~200px)이라 작은 창에서도 창 안에서 최고 속도가 난다
4. `/neighborhood`에서도 같은 구도가 나오고, `/preview`는 세로로 긴 창에서 같은 기준으로 화각을 넓힌다(화면은 창 크기를 따라 채우고, 통계 패널은 좁은 화면에서 폭 안에서 줄바꿈된다)
5. **합격 기준**: 어느 비율에서나 캐릭터·앞길·하늘이 함께 보이고, 비율이 달라져도 구도가 튀지 않으며, 조이스틱 고정점이 발끝에 있다

### GPS 상태 재현 (시나리오 2·2-2)

| 상태 | 재현 방법 |
|---|---|
| 정확도별 위치(±20m·±50m·±150m·±1km·1km 넘음) | Playwright `context.grantPermissions(['geolocation'])` 뒤 `context.setGeolocation({ latitude, longitude, accuracy })` — `accuracy`(m)로 단계를 고른다. 브라우저에서는 개발자 도구 Sensors의 위치 덮어쓰기 |
| 권한 창 대기 | 사이트 위치 권한을 기본값(묻기)으로 둔 브라우저로 연다 |
| 찾는 중·늦음 | 답하지 않는 `navigator.geolocation` 대역(mock) — 8초가 지나면 늦음 |
| 위치 없음 | 대역이 POSITION_UNAVAILABLE(code 2)로 답한다 |
| 거부 | 사이트 위치 권한을 차단하거나, 대역이 PERMISSION_DENIED(code 1)로 답한다 |
| https 아님 | localhost가 아닌 `http://<LAN IP>:3000`으로 연다(휴대폰에서 PC 개발 서버를 열 때와 같다) |
| 받다가 멈춤 | 대역이 위치를 준 뒤 오류(code 2·3)로 답한다. 내 주변을 휴대폰(모바일 UA)으로 열었다면 대역이 위치를 한 번 준 뒤 20초 넘게 보내지 않는다 |

### 시나리오 3 — 대시보드 월드 이동 + 실시간 동기화 (Phase 2, 대시보드 월드 화면을 만든 뒤)

1. 브라우저 탭 2개에서 각각 로그인 후 `/dashboard` 진입 (유저 A, 유저 B)
2. 유저 A WASD 10m 이동
3. 유저 B 화면에서 유저 A 위치 갱신 확인
4. **합격 기준**: 갱신 지연 500ms 이하, 속도 초과 패킷 서버 드롭

### 시나리오 4 — 음성 거리 기반 구독 (Phase 3, 대시보드 월드 음성 클라이언트를 만든 뒤)

1. 유저 A, B가 같은 섹터에서 35m 거리로 시작하고 마이크 옵트인
2. 유저 A가 접근 → 30m 이내에서 서로의 음성이 풀볼륨으로 들리는지 확인
3. 유저 A가 후퇴 → 40m 이탈 시 오디오 구독 해제(묵음) 확인

### 시나리오 5 — 결제 파이프라인 E2E (Phase 4)

1. 아바타(2,200원) 주문 → `orders.status = 'PENDING'` 주문서 발행 (API 서버 `POST /billing/orders`, 상점 화면을 만든 뒤에는 상점에서)
2. 서명한 승인 웹훅(`POST /billing/webhook`, `x-pg-signature`) 전송 (PG 결제창 연동 후에는 토스페이먼츠 테스트 카드 결제 승인)
3. `orders.status = 'PAID'` 전환 확인
4. 워커가 `characters` 신규 레코드 발급 확인 (5초 이내)
5. 동일 승인번호 웹훅 재전송 → DB 제약으로 중복 발급 없음 확인

### 시나리오 6 — 가시거리 라이선스 (Phase 4)

1. 가입 직후 API 서버 `GET /me/license` 25m 확인
2. 가시거리 300m 라이선스 지급 후 300m로 갱신 확인
3. 이어서 100m 라이선스를 지급해도 300m 유지 확인 (`GREATEST`)
4. 상점 화면을 만든 뒤에는 상점 가시거리 표시가 현재 반경과 일치하는지 확인

### 시나리오 7 — 씬 뷰 디스턴스 + 스폰서 실루엣 (Phase 5, 예정)

1. 무료 유저 기본 씬 뷰 디스턴스 확인
2. 35m 지점 스폰서 랜드마크 실루엣 노출 확인
3. 라이선스 지급 후 씬 뷰 디스턴스 100m 즉시 확장 (0.1초 이내) 확인
