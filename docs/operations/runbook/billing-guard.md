# 과금 방어 대응

API 과금 폭탄 발생 시 원인 진단 및 즉시 차단 절차.

## Mapbox 과금 폭탄

Mapbox 요청은 마을 씬·내 주변의 펼침 지도(Streets v8·지형 DEM, 줌 11~18.5 끌기·확대/축소 가능)에서 나온다. 다시 만들 대시보드 월드 지도(Standard 3D 건물, 줌 14~20 조작 가능)도 같은 `NEXT_PUBLIC_MAPBOX_TOKEN`을 쓴다.

### 원인 진단 체크리스트

1. **토큰 도용 의심**: Mapbox 대시보드 → "Analytics" → 비정상적인 요청 패턴(IP, 도메인) 확인
2. **지도 둘러보기**: 펼침 지도는 펼친 동안 끌기·확대/축소(줌 11~18.5)를 받으므로, 넓게 훑을수록 다른 지역 타일을 요청한다. 캐릭터 이동·GPS 갱신은 마커만 옮기고 지도를 다시 그리지 않는다(펼칠 때와 마을 씬에서 첫 위치가 올 때만 '나'에게 맞추며 그 자리 타일을 받는다)
3. **지도 인스턴스 누적**: 라우트 전환 시 떠난 씬의 지도가 `map.remove()` 없이 잔존 (펼침 지도가 언마운트 시 `map.remove()`를 호출하는지 확인)
4. **Map load 급증**: 마을 씬·내 주변 진입마다 Map load가 1회라(지도를 펼치지 않아도 씬이 시작되면 한 번 만든다), 방문 수 급증이 곧 과금 증가다

### 즉시 조치

```bash
# 1. Mapbox 대시보드에서 Billing Hard Cap 즉시 설정
# Settings → Billing → Budget alerts → Hard Cap 활성화

# 2. 의심 토큰 즉시 Revoke
# Tokens → 해당 토큰 → Revoke

# 3. 새 토큰 발급 + 도메인 락 적용
# Tokens → Create token → Allowed URLs: https://서비스도메인.com
```

## socket.io 실시간 연결 과부하 (실시간 서버 부하)

소켓 게이트웨이는 모두 실시간 서버(`apps/realtime`)에 있고 API 서버와 프로세스가 나뉘어 있어, 여기서의 과부하는
REST·결제 웹훅·발급 워커로 번지지 않는다([ADR 008](../../adr/008-realtime-server-split.md)).
대시보드 월드의 위치·채팅 브로드캐스트는 섹터 게이트웨이(`apps/realtime/src/sector/sector.gateway.ts`)가
처리한다(화면을 다시 만들기 전에는 붙는 클라이언트가 없다). 마을 씬의 익명 멀티플레이는 같은 서버의 방 게이트웨이(`apps/realtime/src/room/room.gateway.ts`)가
방(20명)마다 35ms로 묶어 중계하며, 로그인 없는 공개 트래픽이라 전체 정원(1,000명)과 초당 60건 제한으로
상한을 둔다. 내 주변(베타)은 근접 게이트웨이(`apps/realtime/src/proximity/proximity.gateway.ts`)가 같은 상한으로
사람마다 가까운 19명에게 35ms로 중계한다(방 대신 사람마다 보내므로 한 곳에 몰리면 전송 수가 사람 수에 비례해 는다). 섹터 게이트웨이는 위경도 섹터(500m 격자) 단위로 좌표를 묶어
200ms마다(5Hz) 한 묶음으로 방송하므로, 부하는 동시 접속 수와 활성 섹터 수에 좌우된다. 접속 상태는
인스턴스 메모리에 있다. 트래픽이 특정 섹터로 쏠리거나 유령 채널이 쌓이면 CPU·메모리가 급증한다.

### 원인 진단

서버 메트릭과 로그로 판단한다(외부 대시보드가 아니라 게이트웨이 상태 기준).

1. **동시 접속 급증**: 게이트웨이 위치 상태 수(`playerCount` — 최근 30초 안에 `move`를 보낸 접속 수)와 인스턴스 CPU/메모리 확인
2. **핫스팟 섹터**: 방송 중인 섹터별 인원 분포에서 한 섹터에 인원이 몰렸는지 확인
3. **유령 채널 잔존**: 방(room)에 남은 소켓이 있는지 확인한다. `STALE_MS`(30초) 정리는 위치 상태만 지우고
   룸 참여는 유지하므로, 방 인원은 소켓 연결 해제나 섹터 변경 때만 줄어든다

### 즉시 조치

1. **섹터 채널 해제 로직 점검**: 클라이언트가 섹터를 이탈하면 해당 섹터 방에서 빠져야 한다.
   서버는 `requiredSectors` 재계산 시 이전 섹터를 `leave`하고, 소켓이 끊기면 위치 상태를 지운다. `flush`의
   30초 정리는 위치 상태만 지우고 룸 참여는 그대로 둔다. 이 경로들이 정상 동작하는지 확인한다.
2. **실시간 서버 스케일**: 게이트웨이는 위치 상태(`players`)를 인스턴스 메모리에 두고, "2명 이상인 섹터만 방송"도
   인스턴스마다 따로 판단하는 단일 인스턴스 전제다. 같은 섹터의 두 유저가 서로 다른 인스턴스에 붙으면 서로
   보이지 않으므로, 수평 확장하려면 socket.io 어댑터(공유 백플레인)와 위치 상태 공유를 함께 구현해야 한다.
   그 전까지는 실시간 서버 단일 인스턴스를 수직 확장한다. API 서버는 상태가 없으므로 REST 부하는 인스턴스를 늘려 푼다.
3. **일시 완화**: 극단적 폭주 시 방송 주기(`TICK_MS`, 200ms)를 늘리거나(부하 대비 프레임 감소)
   신규 접속을 일시 제한한다.

## LiveKit Cloud 사용량 초과

음성은 대시보드 월드에서만 쓰이고, 화면을 다시 만들기 전에는 룸에 붙는 클라이언트가 없다. 룸 토큰은
API 서버 `POST /voice/token`(액세스 토큰 필수)만 발급한다.

### 원인 진단

1. LiveKit 콘솔 → "Usage" → 일별 분(分) 소모량 그래프 확인
2. 특정 시간대 급증 패턴 확인 (이벤트·핫스팟 구간 의심)

### 즉시 조치

- 대시보드 월드 클라이언트는 거리순 Top-8 구독 Capping을 따른다(40m 안의 가까운 8명만 구독).
  이 상한이 지켜지는지 확인한다.
- 혼잡 구간에서는 구독 반경(40m)과 구독 상한(8명)을 임시로 줄여 구독 총량을 완화한다.
  전체 볼륨 반경(30m)은 들리는 크기만 정하고 구독량에는 영향이 없다.
- 룸 토큰 TTL은 1시간이지만 접속 중인 세션 길이에는 상한이 없다. 세션 길이를 제한해야 하면
  룸에 연결한 뒤 상한 타이머를 건다.

```typescript
// 세션 최대 길이 강제 적용 (60분 초과 시 disconnect)
const SESSION_MAX_MS = 60 * 60 * 1000;
setTimeout(() => {
  room.disconnect();
}, SESSION_MAX_MS);
```

## 좌표 위변조/텔레포트 방어 발동

### 증상

- 섹터 게이트웨이(`/sector`)에서 특정 유저의 위경도 좌표가 비정상적으로 빠르게 이동
- 조작된 `move` 패킷이 특정 유저로부터 반복 유입

### 방어 동작

속도 검증은 서버에서 수행한다. 섹터 게이트웨이는 `move` 수신 시 직전 위경도 좌표와 비교해
도보로 불가능한 속도(30km/h 초과)면 그 좌표를 **무시**한다(`isPlausibleMove`). 따라서
텔레포트 좌표는 브로드캐스트되지도, 다른 유저에게 렌더되지도 않는다. 대시보드 월드 클라이언트도 전송 전에
같은 기준으로 거른다.

### 즉시 조치

1. 게이트웨이는 폐기한 `move`를 로그로 남기지 않는다. 조작이 의심되면 소켓 수·섹터 분포와
   클라이언트 측 이상 징후로 판단한다.
2. 악성 유저의 세션을 막으려면 `token_version`을 올린다. 리프레시 토큰이 폐기되어 새 액세스 토큰을
   받을 수 없고, 남은 액세스 토큰이 만료(최대 15분)되면 재접속이 막힌다. 게이트웨이는 접속 시에만
   토큰을 검증하므로 이미 열린 소켓은 끊기지 않는다. API 인스턴스를 재기동해도 클라이언트가 처음 받은 액세스
   토큰으로 자동 재접속하므로, 차단은 그 토큰이 만료(최대 15분)된 뒤에 확정된다. 즉시 강제 퇴장시키는 수단은 없다.

```sql
-- 해당 유저의 리프레시 토큰 전부 폐기 (남은 액세스 토큰이 만료되면 재로그인 필요)
UPDATE users SET token_version = token_version + 1, updated_at = now()
WHERE id = '<user_id>';
```
