## Mapbox 과금 폭탄

Mapbox는 5시 GIS 미니맵 전용이므로 타일 요청은 미니맵의 GPS 위치 갱신에서만 발생한다.

### 원인 진단 체크리스트

1. **토큰 도용 의심**: Mapbox 대시보드 → "Analytics" → 비정상적인 요청 패턴(IP, 도메인) 확인
2. **GPS 갱신 주기 과다**: 미니맵이 GPS 위치를 지나치게 자주 갱신해 타일 요청 폭증
3. **줌 레벨 미고정**: 미니맵 줌이 풀려 넓은 지역 타일을 대량 요청
4. **미니맵 다중 마운트**: 라우트 전환 시 이전 미니맵이 `map.remove()` 없이 잔존

### 즉시 조치

```bash
# 1. Mapbox 대시보드에서 Billing Hard Cap 즉시 설정
# Settings → Billing → Budget alerts → Hard Cap 활성화

# 2. 의심 토큰 즉시 Revoke
# Tokens → 해당 토큰 → Revoke

# 3. 새 토큰 발급 + 도메인 락 적용
# Tokens → Create token → Allowed URLs: https://서비스도메인.com
```

## socket.io 실시간 연결 과부하 + API 서버 부하

위치·채팅 브로드캐스트는 월드 게이트웨이(`apps/api/src/world/world.gateway.ts`)가 처리한다.
서버는 섹터(500m 격자) 단위로 좌표를 묶어 200ms마다(5Hz) 한 묶음으로 방송하므로, 부하는
동시 접속 수와 활성 섹터 수에 좌우된다. 트래픽이 특정 섹터로 쏠리거나 유령 채널이 쌓이면
CPU·메모리가 급증한다.

### 원인 진단

서버 메트릭과 로그로 판단한다(외부 대시보드가 아니라 게이트웨이 상태 기준).

1. **동시 소켓 수 급증**: 게이트웨이 접속 소켓 수(`playerCount`)와 인스턴스 CPU/메모리 확인
2. **핫스팟 섹터**: 방송 중인 섹터별 인원 분포에서 한 섹터에 인원이 몰렸는지 확인
3. **유령 채널 잔존**: 이탈했는데도 방(room)에 남은 소켓이 있는지, `STALE_MS`(30초) 정리가
   도는지 확인

### 즉시 조치

1. **섹터 채널 해제 로직 점검**: 클라이언트가 섹터를 이탈하면 해당 섹터 방에서 빠져야 한다.
   서버는 `requiredSectors` 재계산 시 이전 섹터를 `leave`하고, 30초 이상 갱신이 없는 소켓을
   `flush`에서 정리한다. 이 두 경로가 정상 동작하는지 확인한다.
2. **Prune 시 구독 해제**: 클라이언트 반경 450m 바깥 오브젝트를 dispose하는 Prune 로직에서
   더 이상 안 보이는 상대의 구독·렌더 리소스가 함께 해제되는지 확인한다(불필요한 상태 보유
   방지).
3. **API 서버 스케일**: 단일 인스턴스가 동시 연결을 감당하지 못하면 수평 확장한다. 게이트웨이
   인스턴스를 늘릴 때는 socket.io 어댑터(공유 백플레인)로 섹터 방송이 인스턴스 간에 전달되도록
   한다.
4. **일시 완화**: 극단적 폭주 시 방송 주기를 늘리거나(부하 대비 프레임 감소) 신규 접속을
   일시 제한한다.

## LiveKit Cloud 사용량 초과

### 원인 진단

1. LiveKit 콘솔 → "Usage" → 일별 분(分) 소모량 그래프 확인
2. 특정 시간대 급증 패턴 확인 (이벤트·핫스팟 구간 의심)

### 즉시 조치

```typescript
// 세션 최대 길이 강제 적용 (60분 초과 시 disconnect)
const SESSION_MAX_MS = 60 * 60 * 1000;
setTimeout(() => {
  room.disconnect();
}, SESSION_MAX_MS);
```

- 거리순 Top-8 구독 Capping이 정상 동작하는지 확인한다(한 유저가 과도한 오디오 트랙을
  구독하지 않도록).
- 혼잡 구간에서는 조인 반경(기본 30m)을 임시로 축소해 룸 규모와 구독 총량을 완화한다.

## 좌표 위변조/텔레포트 방어 발동

### 증상

- 특정 유저의 씬 좌표가 비정상적으로 빠르게 이동
- 조작된 `move` 패킷이 특정 유저로부터 반복 유입

### 방어 동작

속도 검증은 서버에서 수행한다. 월드 게이트웨이는 `move` 수신 시 직전 씬 좌표와 비교해
도보로 불가능한 속도(30km/h 초과)면 그 좌표를 **무시**한다(`isPlausibleMove`). 따라서
텔레포트 좌표는 브로드캐스트되지도, 다른 유저에게 렌더되지도 않는다.

### 즉시 조치

1. 서버 로그에서 반복적으로 폐기된 `move`가 특정 유저에게서 나오는지 확인한다.
2. 악성 세션을 강제로 끊어야 하면 해당 유저의 `token_version`을 올려 발급된 토큰을 무효화한다.
   재접속 시 재인증이 강제되며 기존 소켓 토큰도 검증에 실패해 끊긴다.

```sql
-- 해당 유저의 모든 토큰 즉시 폐기 (재로그인 강제)
UPDATE users SET token_version = token_version + 1, updated_at = now()
WHERE id = '<user_id>';
```
