## Phase 1 — UI/UX 기반 구축

> 로그인 화면과 인증 BFF 라우트, 맵 인게임 HUD, 게임 셸을 갖춘다.

- **P1-1.** 인증 플로우 `[FE]`
  - 로그인 화면(`/login`) — 이메일+비밀번호 로그인·회원가입 + 소셜 OAuth(카카오·구글), Spot 스타일 58/42 스플릿 레이아웃
  - 인증 BFF 라우트 — `/api/auth/*`(가입·로그인·토큰 갱신·로그아웃·OAuth 시작·콜백)가 NestJS `auth` 엔드포인트로 넘기고, 리프레시 토큰은 httpOnly 쿠키로 둔다. 라우트 보호는 [구조 방향](#구조-방향-계획)을 따른다
  - 검증
    - 이메일+비밀번호 로그인 후 `/map` 이동
    - OAuth 콜백 성공 시 `/map`, 실패 시 `/login?error=`로 리다이렉트

- **P1-2.** 인게임 HUD 배선 `[FE]` (맵과 함께)
  - 맵에 이동(`onMove`)·채팅(`onChat`) 핸들러를 잇는 HUD 인터페이스. 이동 입력은 PC는 키보드, 모바일은 GPS(`pointer: coarse`로 자동 판별)로 받는다
  - `components/hud/`의 `DirectionPad`·`Joystick`·`ChatInput` 컴포넌트 파일은 있으나 렌더하지 않는다
  - 검증
    - PC 키보드·모바일 GPS 이동 모드 자동 판별 확인

- **P1-3.** 게임 셸 `[FE]`
  - PC 사이드바("내 위치로" GPS 재조회 버튼)·모바일 하단 내비게이션. 맵·상점 화면과 함께 만든다
  - 로딩·에러·빈 상태 처리 패턴 확립

## Phase 2 — 3D 캐릭터 이동 + 실시간 위치 동기화

> 맵(`/map`)에서 Mapbox 실지형 지도 위의 캐릭터를 위경도로 이동시키고, 여러 유저가 섹터 소켓으로 서로의 위치를 실시간으로 본다. 내 주변에는 건물·가로등·물을 더해 플레이 씬에도 적용하고, 참조용 에셋은 반려인이 반려동물과 걷는 자체 에셋으로 바꾼다.

- **P2-1.** 맵 캐릭터 + 카메라 `[3D]`
  - ref-assets kid 스킨드 메시를 Mapbox 커스텀 레이어로 그리고(캐릭터 로더 `lib/three/character.ts`, 내 캐릭터만 로드 실패 시 절차적 메시 폴백), pitch 45°·bearing 45° 고정 쿼터뷰에 줌 14~20만 허용한다 ([ADR 006](./adr/006-quarter-view-camera-lock.md))
  - 검증
    - 맵 캐릭터 렌더링과 고정 쿼터뷰(pitch·bearing 고정, 줌 14~20) 확인

- **P2-2.** 맵 이동 `[FE]`
  - PC는 WASD·방향키 이동(남북 3m/s, 동서 약 2.4m/s), 모바일은 실제 GPS 이동. 새 위치는 15m 이내 도로에 스냅하고, 50m 이동마다 반경 450m 밖 피어 오브젝트를 정리한다
  - 검증
    - 맵 — 캐릭터 이동 확인, 450m 외곽 오브젝트 정리 후 메모리 누수 없음

- **P2-3.** 맵 섹터 소켓 `[FE]`
  - 브라우저가 `NEXT_PUBLIC_WS_URL`로 실시간 서버 `/sector` 게이트웨이에 socket.io로 직접 붙는다. 전송 전 서버와 같은 기준(30km/h, cheap-ruler 거리)으로 사전 검증하고 0.3m 미만 이동은 보내지 않는다
  - 검증
    - 여러 브라우저 창에서 상대 위치 지연 500ms 이하 동기화

- **P2-4.** 내 주변 — 건물·소품·물, 플레이 씬 적용 `[3D]`
  - 2단계 — 건물(벡터 타일 `building`의 높이로 로우폴리 매스), 가로등·나무를 길·공원을 따라 배치, 물(한강 등). 건물이 생기면 구역별 충돌이 필요하다
  - 3단계 — 플레이 씬에 적용
  - 결정 필요 — 플레이 씬에 어떻게 넣을지(첫 화면을 내 주변으로 둘지, 플레이 씬에서 넘어가게 할지)

- **P2-5.** 자체 에셋 교체 — 반려동물과 걷는 시골길 `[3D][FE]`
  - 범위 — 플레이 씬·내 주변·에셋 미리보기가 쓰는 ref-assets(지오메트리·텍스처·오디오·폰트)와 원본에서 옮겨 온 씬 코드(램프 셰이더·3인칭 조작·그림자·바다·새·오디오·후처리·로더와 HUD)를 자체 에셋·자체 코드로 바꾼다
  - 화풍 — 회화풍 로우폴리 시골. 채도 높은 파란 하늘(`#4da6e9`~`#5eaee9`)과 흰 뭉게구름(`#cfdae4`), 흙길(`#dfc194`)·황록 풀(`#97ab59`)·짙은 수풀 그늘(`#446b56`), 푸른 대기의 원경(`#c2d5e8`). 소재는 목장·헛간·사일로·풍차·나무 울타리·들꽃·호수·개울·숲길·설산이다
  - 캐릭터 — 반려인이 반려동물을 목줄로 데리고 걷는다
    - 반려인: 첫 기본 모습은 모자 없는 검은 단발, 흰 티, 파란 반바지의 아이다. 삼각형 3천~5천·본 20~30개로 만들고, 파츠(헤어·상의·하의·신발·액세서리)는 스켈레톤 하나를 함께 쓰며 색은 슬롯 번호로 입혀 `appearance_data`를 그대로 그린다. 앞으로 아이부터 어른까지 여러 모습의 에셋 중에서 고를 수 있게 한다
    - 반려동물: 반려인 곁에서 목줄 길이 안으로 따라 걷는다(서기·걷기·뛰기·앉기). 목줄은 반려인 손과 반려동물 목 사이를 몇 마디 줄로 이어 느슨하면 처지고 당기면 팽팽하다. 종마다 크기·목줄 길이·따라오는 거리를 표로 두고(고양이부터 코끼리·기린까지), 앞으로 여러 종의 에셋 중에서 고를 수 있게 한다
    - 만남 인사 동작: 스칠 때 알아채기(귀·꼬리), 인사를 받아들이면 냄새 맡기·빙글 돌기, 거절되면 아쉬워하기, 멀어질 때 뒤돌아보며 인사하기를 종마다 둔다. 상대 종과 상관없이 맞물리게 만들어 종끼리 짝마다 따로 만들지 않는다(PRD Part 7 만남 인사)
    - 멀티플레이: 색 시드 `s` 대신 외형 코드와 반려동물 종을 보낸다. 반려동물 위치는 보내지 않고, 각 브라우저가 원격 반려인의 경로를 같은 규칙으로 따라가게 한다
    - 반려인·반려동물·판매 외형 파츠는 사람이 새로 그린 캐릭터 시트로 만든다. 외주 계약에는 웹 배포·수정·2차적저작물작성권을 넣는다
  - 에셋 조달
    - 코드 생성: 지형·흙길, 풀꽃(불투명 풀잎 4만~8만·꽃 3천~8천), 하늘(그라디언트 돔 + 구름층 + 뭉게구름 카드), 물(하늘 반사 + 흐름 맵)
    - CC0: 나무·꽃·바위(Quaternius Stylized Nature MegaKit), 농장 건물·동물(Quaternius Farm Buildings·Farm Animal·Ultimate Animated Animal), 울타리·다리·텐트(Kenney Nature Kit), 애니메이션(Quaternius UAL)
    - 외주·직접 제작: 반려인·반려동물, CC0에 없는 동물(백조·닭·다람쥐·염소)과 해바라기·네덜란드식 풍차
    - 오디오는 발소리·클릭(Kenney CC0)·환경음(Freesound CC0)·음악(외주 작곡)으로, 폰트 Stylish는 Google Fonts 배포본(SIL OFL 1.1)으로 채운다
    - 쓰지 않는 것: 원본 파일 추출 방지 조항이 있는 유료 마켓 에셋, 한국을 허용 지역에서 뺀 생성 모델(Hunyuan3D), 무료 티어 AI 3D 산출물(CC BY·비상업), 비상업 전용 음원
  - 파이프라인 — Blender → glTF(`.glb`, Meshopt 압축 + KTX2 텍스처) → `public/assets/`. three r169 GLTFLoader가 읽는 `EXT_meshopt_compression`만 쓴다. 파일마다 출처·라이선스·제작자·도구·날짜를 에셋 대장(`public/assets/LICENSES.json`)에 적고, 대장에 없는 파일이나 ref-assets 참조가 있으면 빌드가 실패한다. `/asset-viewer`는 새 에셋 규격 뷰어로 쓴다
  - 렌더링 — 램프 셰이더는 N·L과 그림자를 합친 값으로 음영을 고르고 청보라 그림자·하늘/지면 반사광·림 라이트·거리/높이 안개를 더한다. 나무는 구 노멀을 입힌 잎 카드로, 후처리는 SMAA + LUT만 쓴다. 계절·시간대는 uniform 키프레임으로 뒤에 붙인다
  - 예산(모바일 상한) — draw call 100 이하(그림자 패스 별도), 프레임당 삼각형 30만~50만, 첫 다운로드 8~12MB, GPU 텍스처 150MB 이하
  - 순서 — ref-assets를 배포 빌드와 저장소에서 빼고 로컬 참고용으로만 둔다 → 아트 가이드(캐릭터 시트·팔레트·배경 콘셉트·에셋 목록) → 로더·셰이더·조작·HUD → 반려인·반려동물 → 배경·충돌 메시·내 주변 지면 → 오디오·폰트 → git 이력과 지난 배포에서 ref-assets 정리
  - 결정 필요 — 반려동물 마릿수(한 마리·두 마리)와 첫 출시 종, 반려동물을 아바타 발급 상품에 넣을지
  - 검증
    - 새 캐릭터 시트가 ref-assets kid와 실루엣(모자·헤어)·머리와 몸 비율·얼굴·신발이 모두 다르다
    - 같은 `appearance_data`면 어느 브라우저에서나 같은 모습이고, 원격 반려인의 반려동물이 같은 자리를 따라간다
    - 반려인이 서면 목줄이 처지고 멀어지면 팽팽해지며, 반려동물이 울타리·벽을 뚫지 않는다
    - 두 반려동물이 스치면 서로 알아채고, 인사하면 종이 달라도 인사 동작이 어긋나지 않는다
    - 회색 박스 씬이 중급 폰에서 30fps 이상이고, 완성 씬이 예산 안에 든다
    - 배포 빌드와 저장소(이력 포함)에 ref-assets 파일이 없다

**완료 기준**
- [ ] 맵 — 여러 브라우저 창에서 각자 캐릭터를 이동할 때 상대 위치가 지연 500ms 이하로 동기화

## Phase 3 — 인앱 결제 + 아바타 발급 + 가시거리 라이선스

> 원화 결제로 유니크 아바타를 발급하고 가시거리 라이선스를 영구 확장한다.

- **P3-1.** PG 결제창 연동 + 자동 취소 `[FE][BE]`
  - 상점 결제창(토스페이먼츠 / 카카오페이) — 상점 화면과 함께 붙이고, 결제 승인은 `POST /billing/webhook`으로 반영한다 ([ADR 003](./adr/003-direct-krw-payment.md))
  - 지급 최종 실패 시 PG사 자동 취소 + CS 로그 적재
  - 검증
    - 지급 최종 실패 시 3초 이내 자동 취소
    - 웹훅 중복 수신 시 단 1회만 발급 확인

- **P3-2.** 발급 대기 연출 + 외형 적용 `[FE][3D]`
  - 발급 대기 중 "주문 제작 중" 로딩 연출 — 상점 화면과 함께
  - 발급 외형은 P2-5의 캐릭터 파츠 체계로 씬의 반려인에게 입힌다

- **P3-3.** 상점 화면 `[FE]`
  - 상점 화면(`/store`) — 상품 카드(아바타 2,200원·가시거리 100m 4,900원·300m 9,900원·아바타 10종 19,800원)·주문, 내 아바타·가시거리·주문 내역 표시
  - 상점 화면이 부르는 BFF 라우트(`/api/me/*`·`/api/billing/*`) — API 서버 `GET /me/characters`·`GET /me/license`·`GET /billing/products`·`GET·POST /billing/orders`로 넘긴다

**완료 기준**
- [ ] 상점 화면 + 결제창 PG 연동(토스페이먼츠·카카오페이)
- [ ] 지급 최종 실패 시 3초 이내 자동 취소
- [ ] 발급 대기 중 "주문 제작 중" 연출

## Phase 4 — B2B 스폰서십 광고 + 씬 뷰 디스턴스 연동 + 채팅 UI

> 광고주가 셀프 서비스로 스폰서 랜드마크(위경도 Point)에 브랜드 텍스처를 매핑하고 노출 통계를 확인한다. 랜드마크 좌표는 펼침 지도의 좌표 마커로도 표시된다. 라이선스 가시거리를 씬 렌더링에 적용하고, 맵에 채팅 UI를 붙인다.

- **P4-1.** PostGIS 공간 쿼리 `[DB]`
  - 반경 조회 함수 `nearby_sponsor_buildings`(마이그레이션 `0005`)가 GiST 인덱스(`idx_sponsor_buildings_geom`)를 타도록 성능 튜닝 ([ADR 004](./adr/004-postgis-gist-index.md))
  - 검증
    - 10개 스폰서 랜드마크 감지 쿼리가 10ms 이하

- **P4-2.** 광고주 포탈 `[FE][BE]`
  - 광고주(`role: advertiser`) 포탈 — 지도에서 랜드마크 좌표 선택 + 이미지 업로드 + 원화 결제
  - `sponsor_buildings` 테넌시 격리 RLS 정책 (광고주 간 데이터 격리)
  - 검증
    - 광고주 포탈 정상 접근 및 랜드마크 좌표 등록 성공
    - 타 광고주 데이터 접근 차단(RLS) 확인

- **P4-3.** 브랜드 텍스처 매핑 + 유효 노출 `[3D][BE]`

## 구조 방향 (계획)

> 현재 구조는 "루트 Next.js 앱 + `apps/api`(REST)·`apps/realtime`(socket.io) NestJS" 코로케이션이며(워크스페이스 도구 없이 패키지마다 따로 설치한다), 공개 진입점은 선택 페이지(`/`)다(모든 페이지 공개, `middleware.ts`는 비어 있다). 아래는 향후 진행 방향으로, 현재 구조로 단정하지 않는다.

- **SaaS 우선 완성** — 인증·실시간·결제·발급 등 서비스 백엔드(SaaS)를 먼저 완성하는 것을 우선순위로 둔다.
- **인증 게이팅 연결** — 로그인·맵·상점 화면을 열 때 `middleware.ts` matcher에 세션 쿠키 기준 라우트 보호를 붙여 `/map`·`/store`·`/admin`을 보호한다. 쿠키가 없으면 `/login`으로 보내고, 진짜 인가는 NestJS 가드와 RLS가 맡는다.
- **마케팅 웹사이트 별도 앱** — 서비스 소개/전환용 마케팅 웹사이트는 SaaS 완성 이후 별도 앱으로 제작한다.
- **모노레포 전환** — pnpm workspaces + Turborepo 기반 모노레포로 정리하는 것을 지향한다.
  ```
  apps/
  ├── app/       ← 게임 클라이언트 (Next.js)
  ├── web/       ← 마케팅 웹사이트 (추후 제작)
  ├── api/       ← NestJS API 서버 (REST)
  └── realtime/  ← NestJS 실시간 서버 (socket.io)
  packages/      ← 공용 타입·UI·설정 등 공유 패키지
  ```
