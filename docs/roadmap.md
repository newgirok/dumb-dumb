## Phase 2 — 3D 월드 이동 + 실시간 위치 동기화

> 선택 페이지(`/`)에서 마을 씬(`/village`)·내 주변(베타)(`/neighborhood`)·에셋 미리보기(`/preview`)로 들어간다. 마을 씬은 로그인 없이 열리는 3D 씬으로, 캐릭터를 3인칭으로 조작하고 M 키나 지도 버튼으로 펼치는 종이 지도(펼침 지도)에 실제 GPS 위치를 표시한다. 같은 방(최대 20명) 다른 방문자의 아이는 익명 소켓(`/scene`)으로 받아 그리고, 서버에 닿지 못하면 혼자인 채로 돈다. 내 주변(베타)은 같은 렌더링으로 내 위치 주변 실제 길을 깔고, 반경 200m 사람의 아이를 실제 자리에 보여 준다. 대시보드 월드(`/dashboard`, 예정)는 Mapbox 실지형 지도 위에서 캐릭터를 위경도로 이동시키며, 여러 유저가 서로의 위치를 실시간으로 본다. 섹터 판정·속도 검증·브로드캐스트 묶음은 서버가 담당한다.

- **P2-1.** 마을 씬 + WebGL 렌더링 `[3D]`
  - 선택 페이지(`/`, `app/page.tsx`) — 게임 타이틀 화면. 여름 오후 풍경 일러스트(하늘·떠가는 구름·겹겹 언덕·발밑으로 굽어 오는 모래길·청록 나무·길을 걷는 아이) 위에 Stylish 제목 "Dumb Dumb"과 목적지 버튼 3개(마을, 내 주변 + "베타" 배지, 에셋 미리보기 + "개발용" 배지)를 세로로 쌓는다. 버튼은 아이콘과 이름뿐이고 `lib/routes.ts`의 `SCENE_ROUTES`(`/village`·`/neighborhood`·`/preview`)로 잇는다. 높이 520px 이하(휴대폰 가로)는 언덕·제목·버튼을 줄여 스크롤 없이 한 화면에 담는다
  - `app/village/`(`/village`) — 씬이 직접 만드는 Three.js WebGL 캔버스 1개(CSR) + EffectComposer(RenderPass·최종 패스(사면체 LUT·인트로)·SMAA·Output), 동적 그림자(시선 앞 ±12m) + 로딩 때 구운 정적 그림자(CSM), 적응형 DPR
  - `/ref-assets/` 참조 에셋 — Draco `.bin` 지오메트리(`lib/three/binLoader.ts`), PNG·KTX2 텍스처, 오디오
    - 지형·바다(하늘 반사)·하늘 돔, 집·창고·파라솔·간판·모래성·도로 차단물·UFO·오락기(gossip), 나무·덤불·야자수·바위(원본 패치 LOD 인스턴스), 가로등·기계, 잔디(55m 밖 숨김), 생물 3종, 갈매기 25마리(무리 비행)
  - 로딩 화면 → 인트로 전환(4초)과 카메라 돌리(6초)가 동시에 시작되고, 1.5초 뒤부터 조작 가능
  - 우상단 HUD 버튼 세 개 — 위부터 사운드·옷 색·지도. 원본 버튼 모양(32×32 크림, 10° 기울임, 하드 그림자, 호버 1.1배, 누르면 눌리며 클릭음)에 이름·툴팁("소리 켜기·끄기 (Ctrl+M)"·"옷 색 바꾸기"·"지도 펼치기 (M)")을 달고, 위치를 못 잡으면 지도 버튼 구석에 "!"를 단다. 손가락 기기(`pointer: coarse`)는 버튼 묶음 전체를 1.2배, 2400×1300 이상 화면은 1.3배로 키운다
  - 단축키 — M 펼침 지도 펼치기·접기, Esc 접기, Ctrl+M 소리 켜기·끄기(사운드 버튼과 같다). 물리 키(`code`) 기준이라 한글 입력 상태에서도 되고, 입력칸·IME 조합 중·키 반복은 무시한다. 씬이 준비된 뒤부터 받는다
  - UFO·오락기·생물 3종의 근접 상호작용은 비활성이다(판정 로직은 `scene.tsx`에 주석)
  - 원본 오디오(첫 입력 때 소리 켜짐, 환경음 교차·발소리). Ctrl·Shift·Alt·Meta만 누른 키는 첫 입력으로 치지 않고, 첫 입력이 Ctrl+M이면 소리를 켜는 것으로 끝난다. 창을 숨기면(최소화·다른 탭) 게임처럼 소리를 줄인 뒤 멈추고, 돌아오면 멈춘 자리에서 저절로 다시 튼다(iOS에서 저절로 켜지지 않으면 다음 터치에서 켠다)
  - 펼침 지도(`components/world/PaperMap.tsx`)는 씬과 별도의 Mapbox GL 캔버스로 띄운다 ([ADR 001](./adr/001-webgl-context-sharing.md)). 씬이 준비되면 지도를 한 번 만들어 접힌 동안 숨겨 두고, 펼치면 접힌 종이가 옆으로 펼쳐진다 — 종이 폭 720px 이상은 3단(두 번 접힘), 440px 이상은 반 접기, 그보다 좁으면 접지 않고 바로 펼친 모양으로 나타난다. 날개 안쪽 면에는 살아 있는 지도의 그 부분을 그려 넣어 다 펴지는 순간 진짜 지도와 이음매 없이 이어진다. 다 펼친 뒤에는 배경 클릭·×로, 언제든 M·Esc로 접고, 지도가 화면에 있는 동안(접을 때는 배경이 다 걷힐 때까지) 캐릭터 조작을 끈다
  - 에셋 미리보기(`/preview`, `app/preview/`) — 개발용. 지도 없이 ref-assets 캐릭터·소품을 띄워 크기·본·애니메이션·인스턴스·LOD 규격을 본다. 화면을 창 크기에 맞춰 채우고, 세로로 긴 화면은 씬과 같은 기준(`framingFor`)으로 화각을 넓힌다
  - 검증
    - 마을 씬 정상 렌더링, 씬 캔버스와 펼침 지도 캔버스의 WebGL 컨텍스트 분리 확인
    - 사운드·지도 버튼과 Ctrl+M·M이 같은 동작을 하고, 지도가 화면에 있는 동안(접을 때는 배경이 다 걷힐 때까지) 캐릭터가 움직이지 않는다
    - 선택 페이지가 휴대폰 세로·가로·데스크톱에서 스크롤 없이 한 화면에 담긴다

- **P2-2.** 캐릭터 + 카메라 `[3D]`
  - 마을 씬 — kid 스킨드 메시(idle/run/air/bored 애니메이션), 3인칭 추적 카메라(`app/village/thirdPerson.ts`, 화면 비율 16:9 이상에서 세로 화각 45°·시선 목표점 중심 반경 5.836m·앙각 9.866°) ([ADR 007](./adr/007-quarter-view-camera-lock.md))
    - 반응형 구도(마을 씬·내 주변 공통, `framingFor(aspect)`) — 16:9에서 9:19.5로 좁아질수록(smoothstep) 세로 화각 45°→66°, 반경 ×1→×1.3, 앙각 +0→+8°, 시선 들기 0→5°로 넓혀 가장 긴 세로 화면에서 하늘·앞길·발밑이 대략 3분의 1씩 보인다. 창 크기·회전으로 비율이 달라지면 줌 스무딩으로 부드럽게 따라간다
    - 마우스 가상 조이스틱의 고정점은 구도에 맞춰 발끝을 따라가고(16:9에서는 화면 위 72.5%), 최대 세기 거리는 짧은 변 × 0.23(90~200px)이다
  - 대시보드 월드(예정) — ref-assets kid 스킨드 메시를 Mapbox 커스텀 레이어로 그리고(캐릭터 로더 `lib/three/character.ts`, 내 캐릭터만 로드 실패 시 절차적 메시 폴백), pitch 45°·bearing 45° 고정 쿼터뷰에 줌 14~20만 허용한다
  - 펼침 지도(마을 씬·내 주변) — 독립 Mapbox GL 캔버스, 북쪽이 위인 평면(`projection: 'mercator'`)에서 끌기·확대/축소만 되고 회전·기울이기는 막는다(줌 11~18.5). 펼칠 때 '나'에게 맞춘다. 스타일(`components/world/paperMapStyle.ts`, Mapbox Streets v8 + 지형 음영)은 씬 화풍의 종이 지도이고 모든 라벨을 Stylish 폰트로 그린다
  - 검증
    - 캐릭터 렌더링 확인, 화면 비율(세로·정사각·16:9 이상)별 카메라 구도 확인, 펼침 지도의 '나' 맞춤·회전·기울이기 차단 확인

- **P2-3.** 이동 + GPS `[FE]`
  - 마을 씬 — WASD·방향키·마우스/터치 가상 조이스틱 이동, 스페이스·오른쪽 클릭 점프, 원본 관성 물리·캡슐 충돌 보행(최고 약 3.75m/s)
  - 마을 씬의 GPS는 펼침 지도의 '나' 표시에만 쓴다(`lib/geo/gps.ts`, `watchPosition` 하나를 씬과 지도가 나눠 쓴다). 사이트 권한이 이미 허용돼 있으면 씬이 뜰 때 바로 찾고, 아니면 지도를 처음 펼칠 때 권한을 묻는다. '나'는 캐릭터 옷 색으로 그리고, 위치를 모르면 지도를 가리고 모눈 빈 종이에 상태 쪽지만 띄운다
  - GPS 상태(권한 창 대기·찾는 중·위치 없음·거부·https 아님·미지원, 정확도 ±20m·±50m·±150m·±1km·1km 넘음, 받다가 멈춤)는 쪽지·도장·음파·정확도 원으로 알리고, 위치를 못 잡으면 지도 버튼 구석에 "!"를 단다. 안내 문구(`lib/geo/gpsMessages.ts`)는 기기(iOS·Android·Windows·Mac, 삼성 인터넷, 앱 속 브라우저)별 설정 경로를 한 단계씩 번호 목록으로 적고(메뉴 경로는 › 로 이어 줄 중간에서 끊기지 않는다), 거부 때는 "다시 시도"(iOS 사파리는 "새로고침")를 둔다
  - 대시보드 월드(예정) — PC는 WASD·방향키 이동(남북 3m/s, 동서 약 2.4m/s), 모바일은 실제 GPS 이동. 새 위치는 15m 이내 도로에 스냅하고, 50m 이동마다 반경 450m 밖 피어 오브젝트를 정리한다
  - 검증
    - 마을 씬 캐릭터 이동 및 펼침 지도 GPS 표시(상태별 쪽지·도장·음파·정확도 원) 동작 확인
    - 대시보드 월드 — 캐릭터 이동 확인, 450m 외곽 오브젝트 정리 후 메모리 누수 없음

- **P2-4.** socket.io 섹터 브로드캐스트 + 속도 검증 `[BE]`

    - 대시보드 월드 — 여러 브라우저 창에서 상대 위치 지연 500ms 이하 동기화

- **P2-6.** 내 주변 — 실제 길을 마을 씬 화풍으로 `[3D][BE]` (1단계 완료 · 2·3단계 예정)
  - 1단계(베타, `/neighborhood`, 완료)
    - 내 위치 주변 OpenStreetMap 벡터 타일(OpenFreeMap z14)의 길을 원작 지형 셰이더 마스크로 그리고 1m = 1m로 걷는다
    - 시작은 대기형이다 — 씬이 GPS 추적기를 만들자마자 위치를 요청하고(`waitForStartFix`), ±50m 안 위치가 오면 바로 시작하고, 그보다 흐리면(와이파이·IP 추정 포함) 첫 위치를 받고 6초 동안 더 나아지길 기다렸다가 그 사이 가장 나은 위치로 이 근처에서 시작한다. 위치를 하나도 못 받는 동안(권한 창·찾는 중·권한 거부·https 아님·미지원)은 스스로 넘어가지 않고 대기 화면에서 계속 기다린다(시간 제한 없음)
    - 대기 화면 — 로더에 상태별 제목·안내(`startWaitNote`)를 띄우며(받을 수 없는 상태면 스피너 없이), 거부 때는 "다시 시도"(iOS 사파리는 "새로고침") 버튼을 둔다. 흐린 위치를 받는 동안은 "위치를 또렷하게 맞추는 중이에요 · ±N"과 "또렷해지면 바로, 아니면 잠시 뒤 이 근처에서 시작해요"를 띄우고 알아서 시작한다
    - 도로 폭은 도로명(대로 40m·로 20m·길 8m, 방향별로 나뉜 대로·로는 절반)으로 정하고, 왕복 차도 가운데 점선은 타일 경계에 박자를 맞춘다
    - 걷는 만큼 256m 구역을 캐릭터 둘레 3×3으로 이어 깐다(끝 없음). 타일 받기·해석과 구역 그리기는 워커(OffscreenCanvas)가 하고, 메인 스레드는 텍스처만 만든다
    - PC는 마을 씬과 같은 조작, 휴대폰은 GPS를 따라 걷되 ±50m 안 위치만 걸음 목표로 쓰고(그보다 흐리면 멈춰 둔다) 한 번에 150m 넘게 튀면 걸어가지 않고 곧장 옮긴다. PC는 흐린 위치로 시작했어도 나중에 옮기지 않는다
    - 위쪽 알림 한 줄(`walkNote`)과 "지도 보기" 버튼 — 휴대폰에서 GPS가 걸음을 따라가지 못할 때(멈춤·흐림), 위치를 받을 수 없게 됐을 때 띄운다. 좁은 화면에서는 버튼이 글 아래 줄로 내려가고, 지도가 펼쳐져 있으면 숨긴다
    - 펼침 지도 — 우상단 지도 버튼(마을 씬 HUD 버튼과 같은 모양, 위치를 못 잡으면 구석에 "!", 손가락 기기 1.2배·큰 화면 1.3배)이나 M으로 펼치고, 다 펼친 뒤에는 배경 클릭·×로, 언제든 M·Esc로 접는다. '나'는 캐릭터 자리와 화면이 보는 방향 화살표(씬이 매 프레임 `MapTrack`을 채운다)이고, GPS가 잡은 자리는 작은 점과 정확도 원으로 따로 보인다. 지도가 화면에 있는 동안(접을 때는 배경이 다 걷힐 때까지) 키보드·마우스 조작은 끄고 휴대폰 GPS 걷기는 계속되며, '나'는 지도를 다시 그리지 않고 마커만 CSS로 움직인다
    - 셰이더·조작·그림자·후처리·애니메이션·원격 아이는 마을 씬 모듈(`app/village/*`)을 함께 쓴다
    - 실제 위치 멀티플레이 — NestJS `neighborhood` 게이트웨이(`/neighborhood`)가 방 없이 사람마다 반경 200m 안 가까운 19명을 골라 35ms로 중계한다. 위치는 실제 좌표(경위도)로 주고받는다
  - 2단계(예정) — 건물(벡터 타일 `building`의 높이로 로우폴리 매스), 가로등·나무를 길·공원을 따라 배치, 물(한강 등). 건물이 생기면 구역별 충돌이 필요하다
  - 3단계(예정) — 마을 씬에 적용
  - 결정됨 — 실제 동네 모드의 멀티플레이는 가까운 사람에게 실제 위치가 보이는 것이 목표다. 결정 필요 — 마을 씬에 어떻게 넣을지(첫 화면을 내 주변으로 둘지, 마을 씬에서 넘어가게 할지)
  - 검증(1단계)
    - 위에서 내려다본 길 모양이 펼침 지도와 같은 방향·배치로 겹친다(서울시청 광장·세종대로, 망원동 골목 격자)
    - ±50m 안 위치면 바로, 그보다 흐리면 6초 뒤 그 근처에서 시작한다. PC는 흐린 위치로 시작해도 나중에 옮겨지지 않는다
    - 휴대폰 모드에서 GPS 위치를 옮기면 캐릭터가 그 자리까지 걸어가 1.5m 앞에서 서고, 600m 옮기면 곧장 옮겨져 둘레 구역 9개가 깔린다. ±50m 밖 위치로는 걷지 않는다
    - 타일 경계를 지나는 왕복 도로의 점선이 약 6m 박자로 이어지고 경계에 틈 한가운데가 온다(서울시청 옆 경도 126.97998°)
    - 걸을 때 구역 이어 깔기는 메인 스레드에 긴 작업(12ms 이상)을 만들지 않는다(타일 해석·구역 그리기는 워커)
    - 같은 동네 봇이 실제 자리에 나타나고, 멀어지거나 끊으면 사라진다

- **P2-7.** 자체 에셋 교체 — 동물 친구와 걷는 시골길 `[3D][FE]` (예정)

  - 예산(모바일 상한) — draw call 100 이하(그림자 패스 별도), 프레임당 삼각형 30만~50만, 첫 다운로드 8~12MB, GPU 텍스처 150MB 이하
  - 순서 — ref-assets를 배포 빌드와 저장소에서 빼고 로컬 참고용으로만 둔다 → 아트 가이드(캐릭터 시트·팔레트·월드 콘셉트·에셋 목록) → 로더·셰이더·조작·HUD → 아이·동물 친구 → 월드·충돌 메시·내 주변 지면 → 오디오·폰트 → git 이력과 지난 배포에서 ref-assets 정리
  - 결정 필요 — 동물 친구 마릿수(한 마리·두 마리)와 첫 출시 종, 동물 친구를 아바타 발급 상품에 넣을지
  - 검증
    - 새 캐릭터 시트가 ref-assets kid와 실루엣(모자·헤어)·머리와 몸 비율·얼굴·신발이 모두 다르다
    - 같은 `appearance_data`면 어느 브라우저에서나 같은 모습이고, 원격 아이의 동물 친구가 같은 자리를 따라간다
    - 아이가 서면 목줄이 처지고 멀어지면 팽팽해지며, 동물 친구가 울타리·벽을 뚫지 않는다
    - 회색 박스 월드가 중급 폰에서 30fps 이상이고, 완성 월드가 예산 안에 든다
    - 배포 빌드와 저장소(이력 포함)에 ref-assets 파일이 없다

**완료 기준**
- [x] 마을 씬 로딩·인트로 정상 동작
- [ ] 대시보드 월드 — 여러 브라우저 창에서 각자 캐릭터를 이동할 때 상대 위치가 지연 500ms 이하로 동기화
- [x] 속도 초과 패킷 서버 드롭 확인
- [x] 마을 씬 익명 멀티플레이 — 같은 방 두 브라우저가 서로의 아이를 약 0.1초 지연 안에서 본다
- [x] 내 주변 1단계 — 길 배치가 펼침 지도와 겹치고, 끝없이 이어 깔리며, 반경 200m 사람이 실제 자리에 보인다

## 구조 방향 (계획)

> 현재 구조는 "루트 Next.js 앱 + `apps/api` NestJS" 코로케이션이며, 공개 진입점은 선택 페이지(`/`)다(모든 페이지 공개, `middleware.ts`는 비어 있다). 아래는 향후 진행 방향으로, 현재 구조로 단정하지 않는다.

- **SaaS 우선 완성** — 인증·실시간·음성·결제·발급 등 서비스 백엔드(SaaS)를 먼저 완성하는 것을 우선순위로 둔다.
- **인증 게이팅 연결** — 로그인·대시보드 월드·상점 화면을 열 때 `middleware.ts` matcher에 세션 쿠키 기준 라우트 보호를 붙여 `/dashboard`·`/store`·`/admin`을 보호한다. 쿠키가 없으면 `/login`으로 보내고, 진짜 인가는 NestJS 가드와 RLS가 맡는다.
- **마케팅 웹사이트 별도 앱** — 서비스 소개/전환용 마케팅 웹사이트는 SaaS 완성 이후 별도 앱으로 제작한다.
- **모노레포 전환** — pnpm workspaces + Turborepo 기반 모노레포로 정리하는 것을 지향한다.
  ```
  apps/
  ├── app/    ← 게임 클라이언트 (Next.js)
  ├── web/    ← 마케팅 웹사이트 (추후 제작)
  └── api/    ← NestJS API 서버
  packages/   ← 공용 타입·UI·설정 등 공유 패키지
  ```
